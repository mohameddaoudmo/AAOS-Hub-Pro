المقدمة الاستراتيجية والتحليلية

عندما تتقدم لمقابلة تقنية متقدمة في إحدى شركات التقنية الألمانية الكبرى — سواءً في BMW بميونخ حيث يُطورون أنظمة المعلومات والترفيه (Infotainment Systems) باستخدام Android Automotive، أو في Bosch حيث يُبرمجون وحدات التحكم المدمجة (Embedded Control Units)، أو في Delivery Hero ببرلين حيث يُعالجون بثوث GPS وصوتية في الوقت الفعلي — فإن معرفتك بـ NDK (Native Development Kit) و JNI (Java Native Interface) ليست "ميزة إضافية"، بل هي شرط أساسي للوظائف الهندسية المتقدمة.

في هذه المقابلات، لا يكفي أن تعرف كيف تُعلن دالة native في Java وتستدعي مكتبة .so. ما يُطلب منك هو فهم عميق لآلية عبور الحدود بين عالم Java المُدار (Managed World) وعالم C/C++ الأصلي (Native World)، وإدراك تام لتكلفة كل انتقال (JNI Boundary Crossing Overhead)، وقدرة على تشخيص الانهيارات الأصلية (Native Crashes) واكتشاف تسريبات الذاكرة (Memory Leaks) التي تتسلل عبر هذا الحاجز.

🎯 لماذا تُركز الشركات الألمانية على NDK/JNI؟

السوق الألماني يضم ثلاثة قطاعات رئيسية تتطلب خبرة NDK:

  • السيارات المتصلة (Connected Cars): BMW وMercedes وVW تستخدم Android Automotive. أنظمة الملاحة والصوت تتطلب معالجة إشارات رقمية (DSP) بزمن استجابة أقل من 5 مللي ثانية — أمر مستحيل في Java.
  • الأجهزة المدمجة (Embedded Devices): Bosch وSiemens يُطورون أجهزة IoT تعتمد على معالجات ARM ذات ذاكرة محدودة. C/C++ يوفر تحكماً دقيقاً في الذاكرة لا يُوفّره Java.
  • تطبيقات الأداء العالي (High-Performance Apps): Delivery Hero وZalando تتعامل مع بثوث بيانات ضخمة (Video Streaming, Real-time GPS) تتطلب Zero-Copy Memory ومعالجة متوازية (Parallel Processing) عبر OpenMP أو pthreads.

تكلفة عبور حاجز JNI — لماذا كل استدعاء يكلفك غالياً؟

عندما تستدعي دالة C++ من Java — أو العكس — فإنك لا تُجري "مجرد قفزة" في الذاكرة. بل تُجري عملية ترجمة بروتوكولية معقدة بين بيئتين مختلفتين تماماً:

تخيل نقطة تفتيش حدودية بين دولتين تتحدثان لغتين مختلفتين ولهما قوانين مرورية مختلفة. السيارة (البيانات) لا تمر ببساطة — يجب أن تتوقف، يُفحص جواز السفر (Type Checking)، يُترجم الاسم (Name Mangling)، يُفحص الحمولة (Argument Marshaling)، وربما يُستبدل السائق (Thread State Transition). كل هذه العمليات تستغرق وقتًا. في JNI، هذا "الوقت" يترجم إلى دورات معالج (CPU Cycles) يمكن أن تصل إلى 40-100 دورة لكل استدعاء — رقم يبدو صغيراً لكنه يتراكم بشكل كارثي في الحلقات.

العمليات التي تحدث عند كل عبور لحاجز JNI:

  1. انتقال حالة الخيط (Thread State Transition): يجب على خيط Java (Managed Thread) أن ينتقل من "حالة مُفسرة" (Interpreted) إلى "حالة أصلية" (Native). هذا يتطلب تحديثاً لبنية بيانات داخلية في ART تُسمى Thread::state_.
  2. فحص الوسائط (Argument Marshaling): يجب تحويل أنواع Java (مثل String و int[]) إلى مكافئاتها في C++ (مثل const char* و jintArray). المصفوفات تتطلب نسخاً كاملاً (Full Copy) ما لم تستخدم GetPrimitiveArrayCritical أو Direct ByteBuffer.
  3. البحث في جدول الدوال (Method Lookup): عند استدعاء دالة Java من C++، يجب البحث عن jmethodID في جدول الدوال الداخلي — عملية تستغرق O(N) في أول مرة، لذا يجب تخزينها (Cache) دائماً.
  4. إدارة المراجع (Reference Management): كل كائن Java يُمرّر إلى C++ يحتاج إلى "مرجع محلي" (Local Reference) يُسجّل في جدول المراجع المحلية (Local Reference Table). هذا الجدول له حد أقصى (512 مرجع افتراضياً) — تجاوزه يُسبب ReferenceTable overflow.
JNI Call Overhead ≈ 40-100 CPU cycles + Marshaling Cost + Thread Transition Cost
⚠️ القاعدة الذهبية: اجمع البيانات في Java، وعالجها دفعة واحدة في C++

إذا كنت تُعالج 1000 عنصر، لا تستدعي الدالة الأصلية 1000 مرة — بل مرّر المصفوفة كاملة مرة واحدة وعالجها في C++ باستخدام حلقة for. الفرق في الأداء يمكن أن يصل إلى 50-100 مرة بسبب تجنب 999 عملية عبور لحاجز JNI.

الهندسة الداخلية لـ JNI وآلية التواصل

قبل أن تكتب سطراً واحداً من C++، يجب أن تفهم البنية الداخلية لـ JNI. فهذه البنية ليست مجرد "واجهة" — بل هي عقدة ترجمة حية (Live Translation Layer) بين JVM وعالم C++.

JNIEnv و JavaVM — المترجم والمصنع

في JNI، هناك كيانان أساسيان:

  • JavaVM: يمثل الجسيم الافتراضي بأكمله (The Virtual Machine Instance). يوجد JavaVM واحد فقط لكل عملية (Process). يُستخدم لـ "ربط" (Attach) و"فك ربط" (Detach) الخيوط الأصلية (Native Threads) ببيئة Java.
  • JNIEnv: يمثل بيئة تنفيذ خيط واحد (Thread Execution Environment). يوجد JNIEnv واحد لكل خيط. يحتوي على جدول الدوال (Function Table) الذي يتيح لك استدعاء كل دوال JNI (مثل NewStringUTF، CallVoidMethod، GetObjectClass).

تخيل مؤسسة ترجمة دولية كبيرة. JavaVM هو المدير العام للمؤسسة — يوجد واحد فقط. JNIEnv هو المترجم المخصص لكل عميل — كل عميل (خيط) يحصل على مترجم خاص به. لا يمكن لعميل أن يستخدم مترجم عميل آخر. إذا أتى عميل جديد (خيط أصلي جديد)، يجب أن يطلب مترجماً خاصاً من المدير العام (JavaVM::AttachCurrentThread).

كيفية الحصول على JNIEnv في خيوط مختلفة

jni_thread_management.cpp C++ 
#include <jni.h>
#include <pthread.h>
#include <android/log.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "JNI-Threads", __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, "JNI-Threads", __VA_ARGS__)

/**
 * JavaVM يجب أن يُخزّن كمتغير عمومي (Global) لأنه يُستخدم
 * لربط الخيوط الأصلية (Native Threads) ببيئة Java.
 * 
 * لماذا نخزنه؟
 * - JNI_OnLoad يستقبل JavaVM مرة واحدة عند تحميل المكتبة.
 * - الخيوط الأصلية (مثل pthreads) لا تمتلك JNIEnv.
 * - يجب استدعاء AttachCurrentThread للحصول على JNIEnv.
 */
static JavaVM* g_javaVm = nullptr;

/**
 * يُستدعى مرة واحدة عند تحميل المكتبة (.so).
 * هنا نحفظ JavaVM للاستخدام المستقبلي.
 */
JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void* reserved) {
    g_javaVm = vm;
    LOGI("JNI_OnLoad: JavaVM captured successfully");
    return JNI_VERSION_1_6;
}

/**
 * الحصول على JNIEnv للخيط الحالي.
 * 
 * إذا كان الخيط الحالي خيط Java (مثل خيط يستدعي دالة native)،
 * فإن JNIEnv يُمرّر تلقائياً كوسيط أول.
 * 
 * إذا كان الخيط أصلياً (Native Thread مثل pthread)،
 * يجب "ربطه" (Attach) أولاً.
 */
JNIEnv* getJNIEnv() {
    JNIEnv* env = nullptr;

    // الحالة 1: الخيط الحالي مُرفق بالفعل (Java Thread)
    // GetEnv يُرجع JNI_OK إذا كان الخيط مُرفقاً
    jint result = g_javaVm->GetEnv(reinterpret_cast(&env), JNI_VERSION_1_6);

    if (result == JNI_OK) {
        return env;
    }

    // الحالة 2: الخيط الحالي غير مُرفق (Native Thread)
    // يجب ربطه — ولا ننسى فك الربط لاحقاً!
    if (result == JNI_EDETACHED) {
        JavaVMAttachArgs args;
        args.version = JNI_VERSION_1_6;
        args.name = "NativeWorkerThread"; // اسم يظهر في المُنقح
        args.group = nullptr;

        result = g_javaVm->AttachCurrentThread(&env, &args);
        if (result != JNI_OK) {
            LOGE("Failed to attach current thread!");
            return nullptr;
        }
        LOGI("Thread attached successfully");
    }

    return env;
}

/**
 * فك ربط الخيط الأصلي.
 * 
 * ⚠️ تحذير: لا تُفك الربط إذا كان الخيط هو خيط Java الأصلي!
 * فك ربط خيط Java يُسبب Crash لأن JVM تتوقع أن يبقى مُرفقاً.
 */
void detachThread() {
    if (g_javaVm != nullptr) {
        g_javaVm->DetachCurrentThread();
        LOGI("Thread detached successfully");
    }
}

/**
 * مثال: خيط أصلي (pthread) يستدعي دالة Java.
 */
void* nativeWorkerThread(void* arg) {
    JNIEnv* env = getJNIEnv();
    if (env == nullptr) {
        return nullptr;
    }

    // ... عمل JNI هنا ...
    // مثلاً: استدعاء دالة Java لإرسال النتائج

    // فك الربط عند الانتهاء
    detachThread();
    return nullptr;
}
🚨 خطأ شائع: فك ربط خيط Java

إذا استدعيت DetachCurrentThread() على خيط Java (وليس خيط أصلي)، فإن JVM ستُنهي الخيط فوراً — مما يُسبب SIGABRT أو IllegalThreadStateException. القاعدة: فك الربط فقط للخيوط التي أنشأتها أنت في C++ (مثل pthreads). الخيوط التي تأتي من Java (مثل تلك التي تستدعي دوالك الـ native) تبقى مُرفقة.

أنواع مراجع الذاكرة في JNI — Local, Global, Weak Global

عندما تُنشئ أو تستقبل كائن Java في C++ (مثل jobject أو jstring)، فإن JNI لا يُعطيك مؤشراً مباشراً إلى الكائن. بل يُعطيك مرجعاً (Reference) — وهو معرف يُستخدم للوصول إلى الكائن عبر JVM. هناك ثلاثة أنواع من المراجع:

نوع المرجع مدة الحياة الحذف التلقائي الاستخدام
Local Reference حتى نهاية الدالة الـ native نعم — تلقائياً الكائنات المؤقتة داخل دالة واحدة
Global Reference حتى استدعاء DeleteGlobalRef لا — يدوي فقط الكائنات التي تُحتفظ بها بين الاستدعاءات
Weak Global Reference حتى يجمعها GC نعم — بواسطة GC الكائنات التي يمكن التخلص منها عند الحاجة

تخيل ثلاثة أنواع من بطاقات الدخول إلى مبنى:

Local Reference = بطاقة زيارة يومية. تُعطى عند الدخول وتُسحب تلقائياً عند الخروج. لا يمكنك الاحتفاظ بها لليوم التالي.

Global Reference = بطاقة موظف دائمة. يجب أن تطلبها صراحةً (NewGlobalRef) وتُعيدها صراحةً (DeleteGlobalRef). إذا نسيت إعادتها، تبقى البوابة مفتوحة للأبد — وهذا هو "تسريب الذاكرة".

Weak Global Reference = بطاقة ضيف مؤقتة. الحارس (GC) يمكنه سحبها في أي وقت إذا احتاج لإخلاء المكان. يجب أن تتحقق دائماً: هل لا تزال صالحة؟

التنفيذ العملي — إدارة المراجع

jni_reference_management.cpp C++ 
#include <jni.h>
#include <android/log.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "JNI-Refs", __VA_ARGS__)

/**
 * مثال على إدارة المراجع في JNI.
 * 
 * السيناريو: دالة native تستقبل String من Java،
 * وتُحوّله إلى Global Reference للاستخدام لاحقاً.
 */

// متغير عمومي — يحتفظ بـ Global Reference
static jstring g_cachedString = nullptr;
static jobject g_callbackObject = nullptr;

extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_cacheString(
    JNIEnv* env,
    jobject /*thiz*/,
    jstring inputString
) {
    // 1. Local Reference — يُنشأ تلقائياً عند استقبال الوسيط
    // inputString هو Local Reference. سيُحذف تلقائياً عند نهاية هذه الدالة.

    // 2. إنشاء Global Reference — للاحتفاظ بالكائن بعد نهاية الدالة
    if (g_cachedString != nullptr) {
        // حذف المرجع القديم أولاً — وإلا تسريب ذاكرة!
        env->DeleteGlobalRef(g_cachedString);
    }

    g_cachedString = static_cast<jstring>(env->NewGlobalRef(inputString));
    LOGI("String cached as Global Reference");

    // 3. Local Reference يُحذف تلقائياً عند return
    // لا حاجة لـ: env->DeleteLocalRef(inputString);
}

extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_releaseCachedString(JNIEnv* env, jobject) {
    if (g_cachedString != nullptr) {
        env->DeleteGlobalRef(g_cachedString);
        g_cachedString = nullptr;
        LOGI("Global Reference deleted — memory freed");
    }
}

/**
 * Weak Global Reference — مثال عملي.
 * 
 * يُستخدم عندما تريد الاحتفاظ بمرجع لكائن Java
 * لكنك لا تريد منع GC من جمعه.
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_cacheWeakReference(
    JNIEnv* env,
    jobject /*thiz*/,
    jobject targetObject
) {
    static jweak g_weakRef = nullptr;

    if (g_weakRef != nullptr) {
        env->DeleteWeakGlobalRef(g_weakRef);
    }

    g_weakRef = env->NewWeakGlobalRef(targetObject);
    LOGI("Weak Global Reference created");

    // التحقق لاحقاً: هل الكائن لا يزال موجوداً؟

Reference Table Overflow — الكارثة الصامتة

كل Local Reference يُخزّن في جدول يسمى Local Reference Table. هذا الجدول له حد أقصى افتراضي يبلغ 512 مرجعاً (في معظم JVMs). إذا أنشأت 513 Local Reference في دالة native واحدة — أو في حلقة تستدعي دالة JNI تُنشئ مراجع — فإن التطبيق سينهار بخطأ:

java.lang.StackOverflowError: local reference table overflow (max=512)
🚨 السيناريو الكارثي: الحلقة التي تُنشئ Local References

تخيل أنك تستدعي env->NewStringUTF() في حلقة تكرارية 1000 مرة. كل استدعاء يُنشئ Local Reference جديد. بعد 512 تكرار — انهيار. الحل: احذف المراجع يدوياً باستخدام env->DeleteLocalRef() داخل الحلقة، أو استخدم PushLocalFrame / PopLocalFrame لإدارة دفعات من المراجع.

jni_reference_overflow.cpp C++ 
#include <jni.h>
#include <android/log.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "JNI-Overflow", __VA_ARGS__)

/**
 * ❌ الحل الخاطئ — يسبب Reference Table Overflow
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_badLoop(JNIEnv* env, jobject) {
    for (int i = 0; i < 1000; i++) {
        // كل استدعاء يُنشئ Local Reference جديد!
        jstring str = env->NewStringUTF("Hello");
        // str يبقى في Local Reference Table حتى نهاية الدالة
        // بعد 512 تكرار: CRASH!
    }
}

/**
 * ✅ الحل الصحيح 1: حذف المراجع يدوياً
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_goodLoopManual(JNIEnv* env, jobject) {
    for (int i = 0; i < 1000; i++) {
        jstring str = env->NewStringUTF("Hello");
        // ... استخدام str ...

        // حذف فوري — لا يسمح للجدول بالامتلاء
        env->DeleteLocalRef(str);
    }
}

/**
 * ✅ الحل الصحيح 2: PushLocalFrame / PopLocalFrame
 * 
 * PushLocalFrame يُنشئ "إطاراً" (Frame) فرعياً للمراجع.
 * PopLocalFrame يحذف كل المراجع في الإطار دفعة واحدة.
 * 
 * هذا أنظف — خاصة في الدوال التي تُنشئ عدة مراجع.
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_goodLoopFrame(JNIEnv* env, jobject) {
    for (int i = 0; i < 1000; i++) {
        // نُنشئ إطاراً يسع 10 مراجع (احتياط)
        if (env->PushLocalFrame(10) != 0) {
            // فشل في تخصيص الذاكرة
            return;
        }

        jstring str = env->NewStringUTF("Hello");
        jobject obj = env->NewObject(...); // مثال
        // ... استخدام str و obj ...

        // يحذف str و obj وكل Local References في الإطار
        env->PopLocalFrame(nullptr);
    }
}

/**
 * ✅ الحل الصحيح 3: زيادة حجم الجدول (غير مستحسن)
 * 
 * يمكن زيادة الحد الأقصى باستخدام -Xcheck:jni أو تعديل JVM،
 * لكن هذا يُخفي المشكلة بدلاً من حلها.
 * الأفضل: تصميم الكود ليستخدم أقل عدد من المرReferencias.
 */
🔧 نصيحة إنتاجية: استخدم RAII Wrapper في C++

في C++11 والإصدارات الأحدث، يمكنك استخدام std::unique_ptr مع deleter مخصص لإدارة المراجع تلقائياً:

jni_raii_wrapper.hpp C++ 
#include <jni.h>
#include <memory>

/**
 * RAII Wrapper لـ Local References في JNI.
 * يضمن الحذف التلقائي عند الخروج من النطاق (Scope).
 * 
 * Usage:
 *   auto str = JniLocalRef(env, env->NewStringUTF("Hello"));
 *   // str يُحذف تلقائياً عند نهاية النطاق
 */
template<typename T>
class JniLocalRef {
private:
    JNIEnv* m_env;
    T m_ref;

public:
    JniLocalRef(JNIEnv* env, T ref) : m_env(env), m_ref(ref) {}

    ~JniLocalRef() {
        if (m_ref != nullptr && m_env != nullptr) {
            m_env->DeleteLocalRef(m_ref);
        }
    }

    // منع النسخ — المراجع لا يمكن نسخها
    JniLocalRef(const JniLocalRef&) = delete;
    JniLocalRef& operator=(const JniLocalRef&) = delete;

    // السماح بالنقل (Move)
    JniLocalRef(JniLocalRef&& other) noexcept 
        : m_env(other.m_env), m_ref(other.m_ref) {
        other.m_ref = nullptr;
    }

    T get() const { return m_ref; }
    operator T() const { return m_ref; }
};

معالجة البيانات وتمريرها عبر الحدود

تمرير البيانات بين Java و C++ ليس عملية "نسخ ولصق" بسيطة. فكل بيئة لديها تمثيلها الخاص للأنواع (Type Representation)، وحدودها الخاصة للذاكرة (Memory Boundaries)، وآليتها الخاصة لإدارة دورة حياة الكائنات (Lifecycle Management). فهم هذه الاختلافات هو الفارق بين تطبيق "يعمل" وتطبيق "يعمل بكفاءة".

الأنواع البدائية — التعيين (Mapping) والتكلفة

الأنواع البدائية (Primitive Types) هي الأسهل في التعامل. JNI يُعرّف أنواعاً خاصة تتوافق مع أنواع Java:

الأنواع البدائية تُمرّر في سجلات المعالج (CPU Registers) أو على المكدس (Stack). لا حاجة لنسخ الذاكرة، ولا حاجة لإدارة مراجع. لكن احذر: إذا مرّرت 1000 int على حدة في حلقة، فإن تكلفة 1000 استدعاء JNI ستفوق أي توفير. الحل: مرّرها كمصفوفة (int[]) مرة واحدة.

تمرير الكائنات — الـ Signature يُحدد كل شيء

عند استدعاء دالة Java من C++، يجب أن تُحدد التوقيع (Signature) — وهو تمثيل نصي لأنواع الوسائط ونوع الإرجاع. هذا التوقيع يُستخدم في JNI للبحث عن الدالة في جدول الدوال (Method Table).

jni_type_signatures.cpp C++ 
#include <jni.h>

/**
 * جدول تواقيع JNI (JNI Type Signatures).
 * 
 * كل نوع Java له تمثيل توقيعي خاص:
 * - Z = boolean
 * - B = byte
 * - C = char
 * - S = short
 * - I = int
 * - J = long
 * - F = float
 * - D = double
 * - L<package/class>; = Object
 * - [ = Array
 * - (args)return = Method Signature
 */

// مثال: دالة Java:
//   void processData(int count, String name, double[] values)
//
// التوقيع في JNI:
//   (ILjava/lang/String;[D)V
//
// تفسير:
//   (           = بداية الوسائط
//   I           = int
//   Ljava/lang/String; = String Object
//   [D          = double[]
//   )           = نهاية الوسائط
//   V           = void (لا توجد قيمة إرجاع)

// مثال آخر:
//   boolean isValid(long id, byte[] data)
//
// التوقيع:
//   (J[B)Z

/**
 * البحث عن MethodID — يجب تخزينه (Cache) لأن البحث يستغرق O(N).
 */
class MethodCache {
private:
    JNIEnv* m_env;
    jclass m_clazz;
    jmethodID m_processMethod;
    jmethodID m_validateMethod;
    jfieldID m_dataField;

public:
    MethodCache(JNIEnv* env, const char* className) : m_env(env) {
        // FindClass يُرجع Local Reference — يجب تحويله إلى Global إذا أردت الاحتفاظ به
        jclass localClazz = env->FindClass(className);
        m_clazz = static_cast<jclass>(env->NewGlobalRef(localClazz));
        env->DeleteLocalRef(localClazz);

        // البحث عن Method IDs — يستغرق O(N) حيث N = عدد الدوال في الصف
        // لذا يجب تخزينها وعدم البحث في كل استدعاء!
        m_processMethod = env->GetMethodID(
            m_clazz,
            "processData",           // اسم الدالة
            "(ILjava/lang/String;[D)V"  // التوقيع
        );

        m_validateMethod = env->GetMethodID(
            m_clazz,
            "isValid",
            "(J[B)Z"
        );

        // البحث عن Field ID
        m_dataField = env->GetFieldID(
            m_clazz,
            "nativeData",            // اسم الحقل
            "J"                      // النوع: long (يُستخدم لتخزين مؤشر C++)
        );
    }

    ~MethodCache() {
        if (m_clazz != nullptr) {
            m_env->DeleteGlobalRef(m_clazz);
        }
    }

    jmethodID getProcessMethod() const { return m_processMethod; }
    jmethodID getValidateMethod() const { return m_validateMethod; }
    jfieldID getDataField() const { return m_dataField; }
    jclass getClass() const { return m_clazz; }
};

المصفوفات و Direct ByteBuffer — تجنب النسخ

تمرير المصفوفات (Arrays) هو أحد أكثر العمليات تكلفة في JNI. عندما تستدعي GetIntArrayElements، فإن JVM قد تُنشئ نسخة كاملة من المصفوفة في Native Heap — خاصة إذا كانت المصفوفة غير متجاورة في الذاكرة (Non-contiguous) أو إذا كانت GC قد حركتها (Moved by GC).

هناك ثلاث استراتيجيات لتمرير المصفوفات:

  1. Get<Type>ArrayElements: يُعطيك مؤشراً إلى المصفوفة. قد يُنشئ نسخة (Copy) أو قد لا يُنشئ — يعتمد على JVM. يجب استدعاء Release<Type>ArrayElements دائماً.
  2. GetPrimitiveArrayCritical / ReleasePrimitiveArrayCritical: يُوقف GC مؤقتاً (Stop-the-World Pause) لضمان عدم تحريك المصفوفة. يُعطيك مؤشراً مباشراً بدون نسخ. لكن: لا تستدعي أي دالة JNI أخرى أثناء الـ Critical Section — هذا يُسبب Deadlock.
  3. Direct ByteBuffer: يُخصص كتلة ذاكرة في Native Heap مباشرة، ويُمرّر مؤشرها إلى Java. Java ترىها كـ ByteBuffer. C++ يراها كـ void*. لا يوجد نسخ على الإطلاق — Zero-Copy.
jni_array_strategies.cpp C++ 
#include <jni.h>
#include <android/log.h>
#include <cstring>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "JNI-Arrays", __VA_ARGS__)

/**
 * الاستراتيجية 1: GetIntArrayElements — قد يُنشئ نسخة
 * 
 * Time: O(N) إذا نُسخت، O(1) إذا لم تُنسخ.
 * Risk: GC قد يُحرك المصفوفة أثناء المعالجة.
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_processArrayCopy(
    JNIEnv* env,
    jobject /*thiz*/,
    jintArray javaArray
) {
    if (javaArray == nullptr) return;

    jboolean isCopy = JNI_FALSE;
    // isCopy = JNI_TRUE إذا نُسخت المصفوفة
    jint* nativeArray = env->GetIntArrayElements(javaArray, &isCopy);

    if (nativeArray == nullptr) {
        // OutOfMemoryError — المصفوفة كبيرة جداً
        return;
    }

    jsize length = env->GetArrayLength(javaArray);
    LOGI("Array length: %d, IsCopy: %s", length, isCopy ? "YES" : "NO");

    // المعالجة...
    for (int i = 0; i < length; i++) {
        nativeArray[i] *= 2; // مثال: مضاعفة كل عنصر
    }

    // Release — مهم جداً!
    // mode = 0: نسخ التعديلات وتحرير المؤقت
    // mode = JNI_COMMIT: نسخ التعديلات دون تحرير
    // mode = JNI_ABORT: تجاهل التعديلات وتحرير
    env->ReleaseIntArrayElements(javaArray, nativeArray, 0);
}

/**
 * الاستراتيجية 2: GetPrimitiveArrayCritical — بدون نسخ (غالباً)
 * 
 * ⚠️ تحذير: لا تستدعي أي دالة JNI أخرى أثناء Critical Section!
 * ⚠️ لا تُنفذ عمليات طويلة — GC مُوقف!
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_processArrayCritical(
    JNIEnv* env,
    jobject /*thiz*/,
    jintArray javaArray
) {
    if (javaArray == nullptr) return;

    jboolean isCopy = JNI_FALSE;
    jint* nativeArray = static_cast<jint*>(
        env->GetPrimitiveArrayCritical(javaArray, &isCopy)
    );

    if (nativeArray == nullptr) return;

    jsize length = env->GetArrayLength(javaArray);

    // المعالجة السريعة فقط — لا استدعاءات JNI هنا!
    for (int i = 0; i < length; i++) {
        nativeArray[i] *= 2;
    }

    // Release — يُعيد تشغيل GC
    env->ReleasePrimitiveArrayCritical(javaArray, nativeArray, 0);
}

/**
 * الاستراتيجية 3: Direct ByteBuffer — Zero-Copy الأفضل
 * 
 * نُخصص الذاكرة في C++ ونُمرّر مؤشرها إلى Java.
 * Java تراها كـ ByteBuffer مباشرة.
 * لا يوجد نسخ أبداً — المؤشر واحد.
 * 
 * في Android: هذا هو الأسلوب المثالي لـ:
 * - معالجة الصور (Bitmap Lock/Unlock)
 * - معالجة الصوت (Audio Buffers)
 * - تدفقات البيانات الضخمة (Large Data Streams)
 */
extern "C" JNIEXPORT jobject JNICALL
Java_com_example_myapp_NativeBridge_createDirectBuffer(
    JNIEnv* env,
    jobject /*thiz*/,
    jlong size
) {
    // تخصيص في Native Heap — لا يخضع لـ GC
    void* nativeBuffer = malloc(static_cast<size_t>(size));
    if (nativeBuffer == nullptr) {
        return nullptr; // OutOfMemory
    }

    // إنشاء Direct ByteBuffer يشير إلى Native Memory
    jobject buffer = env->NewDirectByteBuffer(nativeBuffer, size);

    // ⚠️ تحذير: Java لا تحرر Native Memory تلقائياً!
    // يجب أن تُنشئ آلية لتحريرها (مثل Cleaner أو finalize).

    return buffer;
}

/**
 * الوصول إلى Direct ByteBuffer من C++
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_processDirectBuffer(
    JNIEnv* env,
    jobject /*thiz*/,
    jobject byteBuffer
) {
    if (byteBuffer == nullptr) return;

    // الحصول على المؤشر الأصلي
    void* nativeBuffer = env->GetDirectBufferAddress(byteBuffer);
    jlong capacity = env->GetDirectBufferCapacity(byteBuffer);

    if (nativeBuffer == nullptr || capacity <= 0) {
        LOGI("Invalid Direct ByteBuffer!");
        return;
    }

    // المعالجة مباشرة — لا نسخ!
    // مثال: ملء البيانات
    std::memset(nativeBuffer, 0, static_cast<size_t>(capacity));
}

 * في Java/Kotlin:
 * 
 * ByteBuffer buffer = nativeBridge.createDirectBuffer(1024 * 1024);
 * // buffer هي ByteBuffer مباشرة تشير إلى Native Memory
 * // يمكن الوصول إليها من Java و C++ في آن واحد
 * 
 * // تحذير: لا تستخدم buffer.array() — لن تعمل مع Direct Buffer!
 * // استخدم buffer.get() و buffer.put() فقط.
 */
⚠️ فخ Direct ByteBuffer — تسريب الذاكرة

عندما تُنشئ Direct ByteBuffer باستخدام malloc في C++، فإن Java لا تعرف بحجم هذه الذاكرة. GC يرى فقط كائن ByteBuffer صغير (بضع عشرات من البايتات) ولا يُدرك أنه يشير إلى ميغابايت من Native Memory. النتيجة: GC لا يُحفز لجمع ByteBuffer، وNative Memory تتسرب. الحل: استخدم java.lang.ref.Cleaner (Java 9+) أو PhantomReference لتحرير الذاكرة الأصلية عندما يجمع GC الـ ByteBuffer.

استدعاء دوال Java من الكود الأصلي — Call Method IDs

في كثير من السيناريوهات — خاصة في معالجة الخلفية (Background Processing) — يحتاج خيط C++ إلى إبلاغ Java بنتائج العملية. هذا يتطلب "الاستدعاء العكسي" (Reverse JNI Call): من C++ إلى Java.

jni_callback_to_java.cpp C++ 
#include <jni.h>
#include <android/log.h>
#include <pthread.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "JNI-Callback", __VA_ARGS__)

static JavaVM* g_javaVm = nullptr;
static jclass g_callbackClass = nullptr;
static jmethodID g_onProgressMethod = nullptr;
static jmethodID g_onCompleteMethod = nullptr;

JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void* /*reserved*/) {
    g_javaVm = vm;
    return JNI_VERSION_1_6;
}

/**
 * تسجيل دوال الاستدعاء العكسي (Callback Methods).
 * يجب استدعاء هذه الدالة من Java مرة واحدة عند التهيئة.
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_registerCallbacks(
    JNIEnv* env,
    jobject /*thiz*/
) {
    jclass localClass = env->FindClass("com/example/myapp/NativeCallback");
    g_callbackClass = static_cast<jclass>(env->NewGlobalRef(localClass));
    env->DeleteLocalRef(localClass);

    // onProgress(int progress, String message)
    g_onProgressMethod = env->GetStaticMethodID(
        g_callbackClass,
        "onProgress",
        "(ILjava/lang/String;)V"
    );

    // onComplete(boolean success, byte[] result)
    g_onCompleteMethod = env->GetStaticMethodID(
        g_callbackClass,
        "onComplete",
        "(Z[B)V"
    );
}

/**
 * خيط أصلي يُبلغ Java بتقدم العملية.
 */
void reportProgress(int progress, const char* message) {
    JNIEnv* env = nullptr;

    // ربط الخيط إذا لم يكن مُرفقاً
    jint attachResult = g_javaVm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6);
    bool needsDetach = false;

    if (attachResult == JNI_EDETACHED) {
        g_javaVm->AttachCurrentThread(&env, nullptr);
        needsDetach = true;
    }

    if (env == nullptr) return;

    // إنشاء String من C++
    jstring jMessage = env->NewStringUTF(message);

    // استدعاء الدالة الثابتة (Static Method) في Java
    env->CallStaticVoidMethod(g_callbackClass, g_onProgressMethod, progress, jMessage);

    // ⚠️ تحقق من وجود Exception بعد كل استدعاء!
    if (env->ExceptionCheck()) {
        env->ExceptionDescribe(); // طباعة الـ Stack Trace
        env->ExceptionClear();    // مسح الـ Exception
    }

    // حذف Local References
    env->DeleteLocalRef(jMessage);

    if (needsDetach) {
        g_javaVm->DetachCurrentThread();
    }
}

/**
 * إرسال النتائج النهائية إلى Java.
 */
void reportComplete(bool success, const uint8_t* data, size_t dataSize) {
    JNIEnv* env = nullptr;
    jint attachResult = g_javaVm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6);
    bool needsDetach = false;

    if (attachResult == JNI_EDETACHED) {
        g_javaVm->AttachCurrentThread(&env, nullptr);
        needsDetach = true;
    }

    if (env == nullptr) return;

    // إنشاء byte[] في Java ونسخ البيانات
    jbyteArray resultArray = env->NewByteArray(static_cast<jsize>(dataSize));
    if (resultArray != nullptr && data != nullptr) {
        env->SetByteArrayRegion(resultArray, 0, static_cast<jsize>(dataSize), 
                                reinterpret_cast<const jbyte*>(data));
    }

    env->CallStaticVoidMethod(g_callbackClass, g_onCompleteMethod, 
                              static_cast<jboolean>(success), resultArray);

    if (env->ExceptionCheck()) {
        env->ExceptionDescribe();
        env->ExceptionClear();
    }

    env->DeleteLocalRef(resultArray);

    if (needsDetach) {
        g_javaVm->DetachCurrentThread();
    }
}
🔧 لماذا نستخدم Static Methods للاستدعاء العكسي؟

في C++، عندما يعمل خيط أصلي في الخلفية، لا يملك مؤشراً إلى كائن Java (jobject) لاستدعاء دالة عضو (Instance Method). الحلول: (1) استخدام Static Methods — لا تحتاج إلى كائن. (2) تخزين Global Reference للكائن Java في البداية واستخدامه لاحقاً. الخيار الأول أبسط وأكثر أماناً — خاصة إذا كان الكائن Java قد جُمع بواسطة GC.

4

إدارة الذاكرة والأداء العالي في الـ Native Heap

الذاكرة في Android ليست كتلة واحدة موحدة. بل هي عالمان متوازيان: Java Heap (الذي تُديره JVM) و Native Heap (الذي تُديره libc). فهم الفرق بينهما — وكيفية التنقل بينهما — هو المفتاح لبناء تطبيقات Android عالية الأداء لا تنهار تحت ضغط البيانات الضخمة.

الفرق الجذري بين Java Heap و Native Heap

الخاصية Java Heap Native Heap
المُدير JVM / ART (Garbage Collector) libc (malloc/free)
الحد الأقصى يحدده الجهاز (192MB-512MB) يقترب من ذاكرة الجهاز الكلية
التجزئة (Fragmentation) منخفضة — GC يُعيد الترتيب عالية — لا يوجد إعادة ترتيب
تتبع التسريبات سهل — Memory Profiler في Android Studio صعب — يتطلب ASan أو Valgrind
الوصول من Java مباشر عبر JNI أو Direct ByteBuffer
السرعة متوسطة — GC pauses عالية — تحكم كامل

تخيل مبنيين سكنيين. Java Heap هو مبنى ذكي يملكه "مدير عقارات" (GC) يُنظف الشقق الفارغة تلقائياً ويُعيد ترتيب الأثاث. Native Heap هو أرض فضاء — لديك حرية كاملة في البناء، لكن إذا بنيت ونسيت أن تهدم، فإن الأرض تبقى مشغولة للأبد (Memory Leak). GC لا يدخل إلى الأرض الفضاء — إنه عالمك أنت.

⚠️ OutOfMemoryError في Native Heap لا يُلقى في Java!

إذا استنفدت Native Heap (باستخدام malloc بكثرة)، فإن malloc يُرجع nullptr. لا يوجد OutOfMemoryError تلقائي. يجب أن تتحقق يدوياً: if (ptr == nullptr) { /* handle error */ }. إذا تجاهلت هذا التحقق واستخدمت المؤشر — SIGSEGV مضمون.

AddressSanitizer (ASan) و HWAddressSanitizer (HWASan)

تتبع تسريبات الذاكرة في Native Code هو من أصعب المهام في تطوير Android. لحسن الحظ، يوفر Android NDK أدوات قوية:

  • AddressSanitizer (ASan): يُضيف "حواجز حمراء" (Red Zones) حول كل كتلة ذاكرة مُخصصة. إذا كتبت خارج الكتلة (Buffer Overflow) أو قرأت من كتلة مُحررة (Use-After-Free)، فإن ASan يكتشف ذلك فوراً ويُلقي تقريراً مفصلاً.
  • HWAddressSanitizer (HWASan): نسخة أحدث تستخدم دعم الأجهزة (ARMv8.5+) بدلاً من الحواجز البرمجية. أسرع بكثير ويستهلك ذاكرة أقل.

التعامل مع Bitmap مباشرة في الذاكرة الأصلية

معالجة الصور في Android تُعدّ من أكثر العمليات استهلاكاً للذاكرة. صورة بدقة 4K (3840×2160) تستهلك حوالي 33 ميغابايت في الذاكرة (ARGB_8888). إذا عالجتها في Java — باستخدام Bitmap.getPixel() و Bitmap.setPixel() — فإنك تُجري 8,294,400 استدعاء JNI (واحد لكل بكسل!) — كارثة أدائية. الحل: قفل (Lock) البكسلات في Native Memory وعالجها كمؤشر C++.

native_bitmap_processing.cpp C++ 
#include <jni.h>
#include <android/bitmap.h>
#include <android/log.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "JNI-Bitmap", __VA_ARGS__)

/**
 * معالجة Bitmap مباشرة في Native Memory.
 * 
 * في Android: يُستخدم لـ:
 * - تطبيق فلاتر الصور (Image Filters) بأداء 60fps
 * - معالجة الكاميرا في الوقت الفعلي (CameraX + OpenCV)
 * - ضغط/فك ضغط الصور باستخدام libjpeg-turbo أو libpng
 * 
 * Time: O(W × H) — خطي على عدد البكسلات.
 * Space: O(1) إضافي — نعالج في المكان (In-place).
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_applyGrayscaleFilter(
    JNIEnv* env,
    jobject /*thiz*/,
    jobject bitmap
) {
    if (bitmap == nullptr) {
        LOGI("Bitmap is null!");
        return;
    }

    AndroidBitmapInfo info;
    void* pixels = nullptr;

    // 1. الحصول على معلومات Bitmap
    int result = AndroidBitmap_getInfo(env, bitmap, &info);
    if (result != ANDROID_BITMAP_RESULT_SUCCESS) {
        LOGI("Failed to get bitmap info: %d", result);
        return;
    }

    // التحقق من التنسيق — يجب أن يكون ARGB_8888
    if (info.format != ANDROID_BITMAP_FORMAT_RGBA_8888) {
        LOGI("Unsupported bitmap format: %d", info.format);
        return;
    }

    // 2. قفل (Lock) البكسلات — يمنع GC من تحريك Bitmap
    result = AndroidBitmap_lockPixels(env, bitmap, &pixels);
    if (result != ANDROID_BITMAP_RESULT_SUCCESS || pixels == nullptr) {
        LOGI("Failed to lock pixels: %d", result);
        return;
    }

    // 3. المعالجة المباشرة — لا يوجد نسخ!
    uint32_t* pixelArray = static_cast<uint32_t*>(pixels);
    const int width = static_cast<int>(info.width);
    const int height = static_cast<int>(info.height);
    const int stride = static_cast<int>(info.stride) / 4; // البايتات لكل صف

    for (int y = 0; y < height; y++) {
        for (int x = 0; x < width; x++) {
            uint32_t pixel = pixelArray[y * stride + x];

            // فك الترميز: ARGB (كل قناة 8 بت)
            uint8_t a = (pixel >> 24) & 0xFF;
            uint8_t r = (pixel >> 16) & 0xFF;
            uint8_t g = (pixel >> 8) & 0xFF;
            uint8_t b = pixel & 0xFF;

            // حساب التدر الرمادي (Luminance)
            uint8_t gray = static_cast<uint8_t>(0.299f * r + 0.587f * g + 0.114f * b);

            // إعادة الترميز
            pixelArray[y * stride + x] = 
                (a << 24) | (gray << 16) | (gray << 8) | gray;
        }
    }

    // 4. فك القفل (Unlock) — مهم جداً!
    AndroidBitmap_unlockPixels(env, bitmap);

    // ⚠️ لا تستخدم pixels بعد Unlock!
    // GC قد يُحرك Bitmap في الذاكرة.
}

/**
 * نسخة محسّنة باستخدام NEON (ARM SIMD) — أسرع 4-8 مرات!
 * 
 * يتطلب: #include <arm_neon.h>
 * يُستخدم في: ARMv7-A و ARMv8-A (جميع أجهزة Android الحديثة).
 */
#ifdef __ARM_NEON
#include <arm_neon.h>

extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeBridge_applyGrayscaleFilterNeon(
    JNIEnv* env,
    jobject /*thiz*/,
    jobject bitmap
) {
    AndroidBitmapInfo info;
    void* pixels = nullptr;

    AndroidBitmap_getInfo(env, bitmap, &info);
    AndroidBitmap_lockPixels(env, bitmap, &pixels);

    uint8_t* pixelBytes = static_cast<uint8_t*>(pixels);
    const int width = static_cast<int>(info.width);
    const int height = static_cast<int>(info.height);
    const int stride = static_cast<int>(info.stride);

    // معاملات التحويل مضروبة في 256 (Fixed-point)
    // 0.299 * 256 = 76, 0.587 * 256 = 150, 0.114 * 256 = 29
    uint8x8_t rCoeff = vdup_n_u8(76);
    uint8x8_t gCoeff = vdup_n_u8(150);
    uint8x8_t bCoeff = vdup_n_u8(29);

    for (int y = 0; y < height; y++) {
        uint8_t* row = pixelBytes + y * stride;
        int x = 0;

        // معالجة 8 بكسلات في آن واحد (SIMD)
        for (; x <= width - 8; x += 8) {
            uint8x8x4_t rgba = vld4_u8(row + x * 4);

            // gray = (r * 76 + g * 150 + b * 29) >> 8
            uint16x8_t gray = vmull_u8(rgba.val[0], rCoeff);
            gray = vmlal_u8(gray, rgba.val[1], gCoeff);
            gray = vmlal_u8(gray, rgba.val[2], bCoeff);

            uint8x8_t gray8 = vshrn_n_u16(gray, 8);

            // كتابة النتيجة
            rgba.val[0] = gray8;
            rgba.val[1] = gray8;
            rgba.val[2] = gray8;
            // rgba.val[3] (Alpha) يبقى كما هو

            vst4_u8(row + x * 4, rgba);
        }

        // معالجة البكسلات المتبقية (Remainder)
        for (; x < width; x++) {
            uint8_t* p = row + x * 4;
            uint8_t gray = (p[0] * 76 + p[1] * 150 + p[2] * 29) >> 8;
            p[0] = p[1] = p[2] = gray;
        }
    }

    AndroidBitmap_unlockPixels(env, bitmap);
}
#endif // __ARM_NEON

🔧 لماذا NEON أسرع بـ 8 مرات؟

NEON هو وحدة SIMD (Single Instruction, Multiple Data) في معالجات ARM. بدلاً من معالجة بكسل واحد في كل دورة معالج، تستطيع NEON معالجة 8 بكسلات (أو 16 في ARMv8) في دورة واحدة. هذا يُعادل "معالجة 8 خطوط موازية في مصنع" بدلاً من "خط واحد". كل أجهزة Android الحديثة (من 2013 فصاعداً) تدعم NEON.

بناء وترجمة المكتبات الأصيلة وإدارة البيئة

بناء مكتبات C++ في Android ليس مجرد كتابة كود — بل هو فن إدارة التبعيات (Dependency Management) وتحسين الترجمة (Compilation Optimization) وفهم معماريات الأجهزة (Device Architectures). في الشركات الألمانية — خاصة Bosch وContinental — يُطلب منك غالباً أن تُبرمج لأجهزة ذات مواصفات متباينة: من معالجات ARM 32-bit قديمة في أجهزة IoT، إلى معالجات ARM 64-bit حديثة في السيارات الفاخرة.

فهم تأثير ABIs على حجم التطبيق (APK Size)

ABI (Application Binary Interface) يُحدد كيف يتفاعل الكود الثنائي مع المعالج. في Android، هناك أربعة ABIs رئيسية:

ABI المعالج السجل (Register) الأجهزة المستهدفة حجم .so نموذجي
armeabi-v7a ARM 32-bit 32-bit أجهزة قديمة (pre-2014) ~2-4 MB
arm64-v8a ARM 64-bit 64-bit كل الأجهزة الحديثة ~3-6 MB
x86 Intel 32-bit 32-bit محاكيات قديمة ~2-4 MB
x86_64 Intel 64-bit 64-bit محاكيات حديثة، Chromebooks ~3-6 MB

تخيل أنك تُرجم كتاباً إلى أربع لغات. كل ترجمة (ABI) تُضاعف حجم المكتبة. إذا أدرجت كل الترجمات في الكتاب (APK)، فإن القارئ (المستخدم) يحمل كل اللغات رغم أنه يحتاج لغة واحدة فقط. الحل: App Bundles (AAB) — يرسل Google Play اللغة (ABI) المناسبة لكل جهاز فقط.

android {
    defaultConfig {
        ndk {
            // تحديد ABIs المدعومة — يقلل حجم APK بشكل كبير
            abiFilters 'arm64-v8a', 'armeabi-v7a'

            // إذا كنت تستهدف Google Play فقط:
            // abiFilters 'arm64-v8a' // يغطي 95%+ من الأجهزة
        }

    buildTypes {
        release {
            // تقليص الحجم — إزالة الرموز والتعليقات
            minifyEnabled true

            splits {

                    enable true
                    reset()
                    include 'arm64-v8a', 'armeabi-v7a', 'x86_64'

            }
        }
    }

    // App Bundle — يُرسل Google Play ABI المناسب فقط
    bundle {
        abi {
            enableSplit = true
        }
    }

تشخيص الأعطال المتقدمة والتعامل مع الإشارات

الانهيارات في الكود الأصلي (Native Crashes) هي من أسوأ أنواع الأخطاء في Android. فبينما يُعطيك Java StackTrace واضحاً يسمح بتتبع الخطأ في ثوانٍ، فإن الانهيار الأصلي يُعطيك فقط رقم إشارة (Signal Number) وعنوان ذاكرة (Memory Address) — وربما لا يُعطيك شيئاً على الإطلاق إذا لم تكن مُجهزاً.

SIGSEGV و SIGABRT — فهم لغة الانهيار

عندما يُخالف الكود الأصلي قواعد الذاكرة أو المنطق، يرسل نظام التشغيل إشارة (Signal) إلى العملية. الإشارات الأكثر شيوعاً في Android:

الإشارة الرمز السبب السيناريو الشائع
SIGSEGV 11 Segmentation Fault — وصول إلى ذاكرة غير مصرح Null Pointer Dereference, Buffer Overflow
SIGABRT 6 Abort — إنهاء اضطراري Assertion Failure, Double Free, Corrupted Heap
SIGFPE 8 Floating Point Exception Division by Zero, Integer Overflow
SIGBUS 7 Bus Error — وصول غير محاذى Misaligned Memory Access
SIGILL 4 Illegal Instruction Corrupted Code, Unsupported CPU Instruction

تخيل نظام إنذار حريق في مبنى. كل إشارة هي نوع مختلف من الإنذار:

SIGSEGV = إنذار "وصول غير مصرح" — شخص حاول فتح باب غرفة ليست له.

SIGABRT = إنذار "إخلاء اضطراري" — اكتشف الحارس فساداً خطيراً (مثل تسرب غاز) وأمر بإخلاء المبنى بالكامل.

SIGFPE = إنذار "خطأ حسابي" — شخص قسم عدداً على صفر في المختبر.

قراءة ملفات التتبع (Crash Dumps) باستخدام ndk-stack

عندما ينهار تطبيقك أصلاً، ينتج Android ملف تتبع (Tombstone) في /data/tombstones/. هذا الملف يحتوي على سجل الذاكرة (Memory Map) وسجل المكدس (Stack Trace) لحظة الانهيار. لكن العناوين (Addresses) غير قابلة للقراءة — يجب تحويلها إلى أسماء دوال باستخدام ndk-stack.

بناء Native Crash Reporter مخصص

في الإنتاج (Production)، لا يمكنك الاعتماد على ndk-stack أو logcat. يجب أن يُبلغ التطبيق نفسه عن الانهيارات. هذا يتطلب تثبيت معالج إشارات مخصص (Custom Signal Handler) يُلتقط الانهيار، ويُسجل الـ Stack Trace، ويرسله إلى خادم (Server) قبل أن يُنهي النظام العملية.

native_crash_reporter.cpp C++ 
#include <jni.h>
#include <android/log.h>
#include <signal.h>
#include <unistd.h>
#include <dlfcn.h>
#include <string.h>
#include <stdlib.h>
#include <ucontext.h>
#include <sys/mman.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "CrashReporter", __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, "CrashReporter", __VA_ARGS__)

// الحد الأقصى لعدد الإطارات في Stack Trace
#define MAX_STACK_FRAMES 64

// سياق الانهيار
struct CrashContext {
    int signal;
    siginfo_t* siginfo;
    void* user_context;
    pid_t crashed_thread;
};

// معالج الإشارات الأصلي (لاستعادته لاحقاً)
static struct sigaction g_oldHandlers[6];

// مؤشر إلى دالة Java للإبلاغ عن الانهيار
static jmethodID g_reportCrashMethod = nullptr;
static jobject g_reporterObject = nullptr;
static JavaVM* g_javaVm = nullptr;

/**
 * الحصول على Stack Trace باستخدام backtrace (libc).
 * 
 * في Android: يتطلب #include <unwind.h> أو استخدام libunwind.
 * هنا نستخدم نسخة مُبسطة باستخدام _Unwind_Backtrace.
 */
#include <unwind.h>

struct BacktraceState {
    void** current;
    void** end;
    int count;
};

static _Unwind_Reason_Code unwindCallback(struct _Unwind_Context* context, void* arg) {
    BacktraceState* state = static_cast<BacktraceState*>(arg);
    uintptr_t pc = _Unwind_GetIP(context);
    if (pc) {
        if (state->current == state->end) {
            return _URC_END_OF_STACK;
        } else {
            *state->current++ = reinterpret_cast<void*>(pc);
            state->count++;
        }
    }
    return _URC_NO_REASON;
}

static int captureBacktrace(void** buffer, int max) {
    BacktraceState state = {buffer, buffer + max, 0};
    _Unwind_Backtrace(unwindCallback, &state);
    return state.count;
}

/**
 * كتابة التقرير إلى ملف — يُستخدم لاحقاً للإرسال.
 */
static void writeCrashReport(const CrashContext* ctx, void** backtrace, int count) {
    const char* signalName = "UNKNOWN";
    switch (ctx->signal) {
        case SIGSEGV: signalName = "SIGSEGV"; break;
        case SIGABRT: signalName = "SIGABRT"; break;
        case SIGFPE:  signalName = "SIGFPE";  break;
        case SIGBUS:  signalName = "SIGBUS";  break;
        case SIGILL:  signalName = "SIGILL";  break;
        case SIGTRAP: signalName = "SIGTRAP"; break;
    }

    LOGE("=== NATIVE CRASH REPORT ===");
    LOGE("Signal: %s (%d)", signalName, ctx->signal);
    LOGE("Fault Address: %p", ctx->siginfo->si_addr);
    LOGE("Fault Code: %d", ctx->siginfo->si_code);
    LOGE("Thread ID: %d", ctx->crashed_thread);
    LOGE("Stack Trace (%d frames):", count);

    for (int i = 0; i < count; i++) {
        // ترجمة العنوان إلى اسم دالة — يتطلب dladdr
        Dl_info info;
        if (dladdr(backtrace[i], &info) && info.dli_sname) {
            LOGE("  #%02d: %p  %s  (%s)", 
                 i, backtrace[i], info.dli_sname, info.dli_fname);
        } else {
            LOGE("  #%02d: %p  (unknown)", i, backtrace[i]);
        }
    }

    LOGE("=== END CRASH REPORT ===");
}

/**
 * إرسال التقرير إلى Java — إذا أمكن.
 * 
 * ⚠️ تحذير: في معالج الإشارات، نحن في سياق غير آمن.
 * استدعاء JNI من هنا قد يفشل أو يُسبب Deadlock.
 * الأفضل: كتابة التقرير إلى ملف وإرساله لاحقاً.
 */
static void notifyJava(const char* report) {
    JNIEnv* env = nullptr;
    jint result = g_javaVm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6);

    if (result == JNI_EDETACHED) {
        // محاولة الربط — قد تفشل في سياق الإشارة
        if (g_javaVm->AttachCurrentThread(&env, nullptr) != JNI_OK) {
            return;
        }
    }

    if (env != nullptr && g_reporterObject != nullptr && g_reportCrashMethod != nullptr) {
        jstring jReport = env->NewStringUTF(report);
        env->CallVoidMethod(g_reporterObject, g_reportCrashMethod, jReport);
        env->DeleteLocalRef(jReport);
    }
}

/**
 * معالج الإشارات الرئيسي.
 * 
 * ⚠️ تحذيرات هامة:
 * 1. لا تستخدم malloc — قد يكون الكومة مُفسداً.
 * 2. لا تستخدم pthread_mutex — قد يُسبب Deadlock.
 * 3. استخدم فقط دوال async-signal-safe.
 * 4. اكتب التقرير واخرج بأسرع ما يمكن.
 */
static void signalHandler(int sig, siginfo_t* info, void* ucontext) {
    // تجنب الانهيار المتكرر — إذا انهار معالج الانهيار، نستسلم
    static volatile int handlerCount = 0;
    if (__sync_fetch_and_add(&handlerCount, 1) > 0) {
        // انهيار ثانٍ — استعادة المعالج الأصلي والانهيار
        sigaction(sig, &g_oldHandlers[sig], nullptr);
        return;
    }

    CrashContext ctx;
    ctx.signal = sig;
    ctx.siginfo = info;
    ctx.user_context = ucontext;
    ctx.crashed_thread = gettid();

    void* backtrace[MAX_STACK_FRAMES];
    int count = captureBacktrace(backtrace, MAX_STACK_FRAMES);

    writeCrashReport(&ctx, backtrace, count);

    // إرسال تقرير إلى Java — محاولة فقط
    // notifyJava("Native crash detected — see logs for details");

    // استعادة المعالج الأصلي وإعادة إرسال الإشارة
    // هذا يُسبب "انهيار نظيف" مع تسجيل Tombstone
    sigaction(sig, &g_oldHandlers[sig], nullptr);
    raise(sig);
}

/**
 * تثبيت معالج الإشارات.
 */
extern "C" JNIEXPORT void JNICALL
Java_com_example_myapp_NativeCrashReporter_installHandler(
    JNIEnv* env,
    jobject thiz
) {
    // تخزين مرجع Java للإبلاغ لاحقاً
    g_reporterObject = env->NewGlobalRef(thiz);
    jclass clazz = env->GetObjectClass(thiz);
    g_reportCrashMethod = env->GetMethodID(clazz, "onNativeCrash", "(Ljava/lang/String;)V");
    env->DeleteLocalRef(clazz);

    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_sigaction = signalHandler;
    sa.sa_flags = SA_SIGINFO; // استخدام siginfo_t

    // حجب الإشارات الأخرى أثناء المعالج
    sigemptyset(&sa.sa_mask);

    // تثبيت المعالج للإشارات الشائعة
    int signals[] = {SIGSEGV, SIGABRT, SIGFPE, SIGBUS, SIGILL, SIGTRAP};
    for (int sig : signals) {
        sigaction(sig, &sa, &g_oldHandlers[sig]);
    }

    LOGI("Native crash handler installed successfully");
}

 * إلغاء تثبيت المعالج.

 * 
 * الاستراتيجية:
 * 1. استخدام Direct ByteBuffer — لا يوجد نسخ ولا تخصيصات متكررة.
 * 2. تخصيص واحد في البداية — إعادة الاستخدام (Reuse).

 */
class AudioProcessor {
private:
    void* m_nativeBuffer = nullptr;
    size_t m_bufferSize = 0;

public:
    ~AudioProcessor() {
        if (m_nativeBuffer != nullptr) {
            free(m_nativeBuffer);
        }
    }

    void ensureBuffer(size_t size) {
        if (m_bufferSize < size) {
            if (m_nativeBuffer != nullptr) {
                free(m_nativeBuffer);
            }
            m_nativeBuffer = malloc(size);
            m_bufferSize = size;
        }
    }

    void* getBuffer() { return m_nativeBuffer; }
};

#include <jni.h>
#include <vector>
#include <mutex>
#include <thread>
#include <condition_variable>

/**
 * ✅ الحل: تجميع النتائج في C++ وإرسالها دفعة واحدة.
 * 
 * بدلاً من 1000 خيط يحاول Attach في آن واحد،
 * نستخدم خيط Java واحد (Looper) يستقبل دفعة كل 100 مللي ثانية.
 */
struct GpsUpdate {
    double latitude;
    double longitude;
    int64_t timestamp;
    int driverId;
};

class GpsBatchProcessor {
private:
    std::vector<GpsUpdate> m_batch;
    std::mutex m_mutex;
    std::condition_variable m_cv;
    std::thread m_senderThread;
    bool m_running = true;

    JNIEnv* m_env = nullptr;
    jclass m_callbackClass = nullptr;
    jmethodID m_batchMethod = nullptr;

    void senderLoop() {
        // ربط هذا الخيط بـ Java مرة واحدة
        JavaVMAttachArgs args = { JNI_VERSION_1_6, "GpsSender", nullptr };
        g_javaVm->AttachCurrentThread(&m_env, &args);

        while (m_running) {
            std::vector<GpsUpdate> batch;

            {
                std::unique_lock<std::mutex> lock(m_mutex);
                m_cv.wait_for(lock, std::chrono::milliseconds(100),
                    [this] { return !m_batch.empty() || !m_running; });

                batch.swap(m_batch); // نقل — لا نسخ!
            }

            if (!batch.empty()) {
                sendBatch(batch);
            }
        }

        g_javaVm->DetachCurrentThread();
    }

    void sendBatch(const std::vector<GpsUpdate>& batch) {
        if (m_env == nullptr || m_batchMethod == nullptr) return;

        // إنشاء مصفوفة Java من الدفعة
        jclass gpsClass = m_env->FindClass("com/example/gps/GpsUpdate");
        jobjectArray array = m_env->NewObjectArray(
            static_cast<jsize>(batch.size()), gpsClass, nullptr);

        jmethodID constructor = m_env->GetMethodID(gpsClass, "<init>", "(DDI)V");

        for (size_t i = 0; i < batch.size(); i++) {
            jobject obj = m_env->NewObject(gpsClass, constructor,
                batch[i].latitude, batch[i].longitude, batch[i].driverId);
            m_env->SetObjectArrayElement(array, static_cast<jsize>(i), obj);
            m_env->DeleteLocalRef(obj); // ❌ لا تنسَ!
        }

        m_env->CallStaticVoidMethod(m_callbackClass, m_batchMethod, array);

        if (m_env->ExceptionCheck()) {
            m_env->ExceptionClear();
        }

        m_env->DeleteLocalRef(array);
        m_env->DeleteLocalRef(gpsClass);
    }

public:
    GpsBatchProcessor() {
        m_senderThread = std::thread(&GpsBatchProcessor::senderLoop, this);
    }

    ~GpsBatchProcessor() {
        m_running = false;
        m_cv.notify_all();
        if (m_senderThread.joinable()) {
            m_senderThread.join();
        }
    }

    void addUpdate(const GpsUpdate& update) {
        std::lock_guard<std::mutex> lock(m_mutex);
        m_batch.push_back(update);
        if (m_batch.size() >= 100) {
            m_cv.notify_one(); // إرسال فوراً إذا امتلت الدفعة
        }
    }

    void initCallback(JNIEnv* env, jclass callbackClass, jmethodID method) {
        m_callbackClass = static_cast<jclass>(env->NewGlobalRef(callbackClass));
        m_batchMethod = method;
    }
};

#include <jni.h>
#include <android/bitmap.h>
#include <android/log.h>
#include <arm_neon.h>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, "ImagePipe", __VA_ARGS__)

/**
* Pipeline كامل لمعالجة الصور بأداء 60fps.
* 
* Time per frame: ~2-3ms (لصورة 2K على ARM64)
* Throughput: 300+ frames/second نظرياً
* Bottleneck: CameraX capture latency (not processing)
*/

// تجمع البكسلات — NEON-accelerated
void applyFilterNEON(uint8_t* pixels, int width, int height, int stride) {
    for (int y = 0; y < height; y++) {
        uint8_t* row = pixels + y * stride;
        int x = 0;

        // معالجة 16 بكسلة في آن واحد (64 بايت)
        for (; x <= width - 16; x += 16) {
            uint8x16x4_t rgba = vld4q_u8(row + x * 4);

            // زيادة التباين (Contrast): pixel = (pixel - 128) * 1.2 + 128
            int16x8_t r_low = vsubq_s16(vmovl_u8(vget_low_u8(rgba.val[0])), vdupq_n_s16(128));
            int16x8_t r_high = vsubq_s16(vmovl_u8(vget_high_u8(rgba.val[0])), vdupq_n_s16(128));

            r_low = vaddq_s16(vshrq_n_s16(vmulq_n_s16(r_low, 12), 3), vdupq_n_s16(128));
            r_high = vaddq_s16(vshrq_n_s16(vmulq_n_s16(r_high, 12), 3), vdupq_n_s16(128));

            rgba.val[0] = vcombine_u8(vmovn_u16(vreinterpretq_u16_s16(r_low)),
                                       vmovn_u16(vreinterpretq_u16_s16(r_high)));

            // تكرار لـ G و B...

            vst4q_u8(row + x * 4, rgba);
        }

        // البكسلات المتبقية
        for (; x < width; x++) {
            uint8_t* p = row + x * 4;
            for (int c = 0; c < 3; c++) {
                int16_t v = static_cast<int16_t>(p[c]) - 128;
                v = (v * 12) >> 3;
                v += 128;
                p[c] = static_cast<uint8_t>(std::max(0, std::min(255, static_cast<int>(v))));
            }
        }
    }
}

extern "C" JNIEXPORT void JNICALL
Java_com_example_image_ImagePipeline_processFrame(
    JNIEnv* env,
    jobject /*thiz*/,
    jobject sourceBitmap,
    jobject destBitmap
) {
    AndroidBitmapInfo srcInfo, dstInfo;
    void* srcPixels = nullptr;
    void* dstPixels = nullptr;

    AndroidBitmap_getInfo(env, sourceBitmap, &srcInfo);
    AndroidBitmap_getInfo(env, destBitmap, &dstInfo);

    // التحقق من التوافق
    if (srcInfo.width != dstInfo.width || srcInfo.height != dstInfo.height) {
        return;
    }

    AndroidBitmap_lockPixels(env, sourceBitmap, &srcPixels);
    AndroidBitmap_lockPixels(env, destBitmap, &dstPixels);

    if (srcPixels && dstPixels) {
        // نسخ المصدر إلى الوجهة
        memcpy(dstPixels, srcPixels, srcInfo.height * srcInfo.stride);

        // تطبيق الفلتر على الوجهة
        applyFilterNEON(static_cast<uint8_t*>(dstPixels),
                        static_cast<int>(srcInfo.width),
                        static_cast<int>(srcInfo.height),
                        static_cast<int>(srcInfo.stride));
    }

    AndroidBitmap_unlockPixels(env, destBitmap);
    AndroidBitmap_unlockPixels(env, sourceBitmap);
}

السؤال: لديك دالة C++ تستقبل jobjectArray من Java تحتوي على 10,000 كائن String. يجب أن تُرجع مصفوفة جديدة من jintArray تحتوي على طول كل String. كيف تُنفذ ذلك دون تسريب ذاكرة أو تجاوز Local Reference Table؟

#include <jni.h>

/**
* ❌ الحل الخاطئ — تسريب ذاكرة وربما Overflow
*/
extern "C" JNIEXPORT jintArray JNICALL
Java_com_example_bad_ProcessStringsBad(
    JNIEnv* env,
    jobject /*thiz*/,
    jobjectArray stringArray
) {
    jsize len = env->GetArrayLength(stringArray);
    jintArray result = env->NewIntArray(len);
    jint* lengths = new jint[len];

    for (int i = 0; i < len; i++) {
        jstring str = static_cast<jstring>(env->GetObjectArrayElement(stringArray, i));
        // ❌ str يُضاف إلى Local Reference Table — 10,000 مرجع!
        // ❌ إذا لم نحذف str في كل تكرار: Overflow بعد 512.
        lengths[i] = env->GetStringUTFLength(str);
        // ❌ نسيان DeleteLocalRef(str);
    }

    env->SetIntArrayRegion(result, 0, len, lengths);
    // ❌ نسيان delete[] lengths;
    return result;
}

/**
* ✅ الحل الصحيح — إدارة مراجع دقيقة
*/
extern "C" JNIEXPORT jintArray JNICALL
Java_com_example_safe_ProcessStringsSafe(
    JNIEnv* env,
    jobject /*thiz*/,
    jobjectArray stringArray
) {
    if (stringArray == nullptr) return nullptr;

    jsize len = env->GetArrayLength(stringArray);
    if (len == 0) return env->NewIntArray(0);

    // تخصيص في الكومة الأصلية — يُحرر تلقائياً
    std::vector<jint> lengths;
    lengths.reserve(static_cast<size_t>(len));

    for (int i = 0; i < len; i++) {
        jstring str = static_cast<jstring>(env->GetObjectArrayElement(stringArray, i));
        if (str != nullptr) {
            lengths.push_back(env->GetStringUTFLength(str));
            env->DeleteLocalRef(str); // ✅ حذف فوري — لا يسمح بالتراكم
        } else {
            lengths.push_back(0);
        }
    }

    jintArray result = env->NewIntArray(len);
    if (result != nullptr && !lengths.empty()) {
        env->SetIntArrayRegion(result, 0, len, lengths.data());
    }

    return result;
}

/**
* ✅ الحل الأفضل — PushLocalFrame / PopLocalFrame
* 
* إذا كان العدد كبيراً جداً (مئات الآلاف)،
* فإن PushLocalFrame يضمن عدم Overflow حتى لو نسيت DeleteLocalRef.
*/
extern "C" JNIEXPORT jintArray JNICALL
Java_com_example_safe_ProcessStringsFrame(
    JNIEnv* env,
    jobject /*thiz*/,
    jobjectArray stringArray
) {
    jsize len = env->GetArrayLength(stringArray);
    jintArray result = nullptr;

    // إطار يسع 10 مراجع — يكفي لكل تكرار
    if (env->PushLocalFrame(10) != 0) {
        return nullptr; // فشل في تخصيص
    }

    std::vector<jint> lengths;
    lengths.reserve(static_cast<size_t>(len));

    for (int i = 0; i < len; i++) {
        jstring str = static_cast<jstring>(env->GetObjectArrayElement(stringArray, i));
        if (str != nullptr) {
            lengths.push_back(env->GetStringUTFLength(str));
            // لا حاجة لـ DeleteLocalRef — PopLocalFrame يحذف كل شيء
        } else {
            lengths.push_back(0);
        }
    }

    result = env->NewIntArray(len);
    if (result != nullptr) {
        env->SetIntArrayRegion(result, 0, len, lengths.data());
    }

    env->PopLocalFrame(nullptr); // ✅ يحذف كل Local References
    return result;
}
