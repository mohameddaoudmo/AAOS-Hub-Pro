أركان تصميم الأنظمة للهواتف (Mobile System Design Pillars)

📐 المتطلبات الوظيفية وغير الوظيفية (Functional vs Non-Functional Requirements)

عند تصميم أي نظام جوال، يجب التفريق بين المتطلبات الوظيفية (Functional Requirements) التي تحدد ما يفعله التطبيق، والمتطلبات غير الوظيفية (Non-Functional Requirements) التي تحدد كيف يؤدي التطبيق عمله.

✅ المتطلبات الوظيفية
  • تسجيل الدخول عبر البريد الإلكتروني أو OAuth
  • عرض قائمة المنتجات مع الفلترة والبحث
  • إرسال واستقبال الرسائل الفورية
  • معالجة المدفوعات داخل التطبيق
⚠️ المتطلبات غير الوظيفية
  • Scalability: دعم مليون مستخدم متزامن
  • Reliability: uptime بنسبة 99.9%
  • Battery Efficiency: استهلاك بطارية منخفض (< 5% في الساعة)
  • Network Optimization: تقليل حجم البيانات المنقولة
  • Security: تشفير البيانات في الراحة والنقل
  • Offline Capabilities: العمل بدون إنترنت لمدة 24 ساعة
🌐 بروتوكولات التواصل بين العميل والخادم (Client-Server Communication Protocols)

اختيار البروتوكول المناسب يؤثر مباشرة على أداء التطبيق واستهلاك البطارية. إليك المقارنة الشاملة:

البروتوكول نمط الاتصال استهلاك البطارية حزمة البيانات أفضل استخدام
REST APIs Request/Response منخفض JSON/XML (ثقيل) العمليات CRUD التقليدية، جلب البيانات الأولية
GraphQL Query/Response منخفض JSON (دقيق — Overfetching مُلغى) شاشات معقدة تحتاج بيانات متعددة المصادر
WebSockets Full-Duplex Persistent متوسط-عالي Binary/Text (خفيف) الدردشة الفورية، التحديثات اللحظية
gRPC HTTP/2 + Protocol Buffers منخفض Protobuf (مضغوط جداً) التواصل بين الخدمات الداخلية (Microservices)
SSE (Server-Sent Events) Server → Client Push منخفض Text/Event-Stream إشعارات خفيفة من الخادم، Live Updates أحادية الاتجاه
💡 توصية معمارية

في التطبيقات الحديثة، استخدم REST/GraphQL للطلبات الأولية وWebSockets للتحديثات اللحظية. يمكن دمج SSE كبديل أخف للـ WebSockets في سيناريوهات الإشعارات البسيطة.

📄 استراتيجيات تصميم الـ API والتصفح (Pagination Strategies)

اختيار استراتيجية التصفح يؤثر على تجربة المستخدم واتساق البيانات في التطبيقات التي تحتوي على feeds ديناميكية.

❌ Offset-based Pagination

// GET /api/feed?offset=20&limit=20
interface FeedApi {
    @GET("feed")
    suspend fun getFeed(
        @Query("offset") offset: Int,
        @Query("limit") limit: Int = 20
    ): FeedResponse
}
  • مشكلة Data Drift: إذا أُضيف عنصر جديد أثناء التصفح، تتكرر العناصر أو تُفقد
  • أداء قاعدة البيانات يتدهور مع زيادة الـ offset
  • غير مناسب للـ feeds الحية (Real-time)

✅ Cursor-based Pagination

// GET /api/feed?cursor=abc123&limit=20
data class FeedResponse(
    val items: List<Post>,
    val nextCursor: String?, // Encoded timestamp + ID
    val hasMore: Boolean
)

interface FeedApi {
    @GET("feed")
    suspend fun getFeed(
        @Query("cursor") cursor: String?,
        @Query("limit") limit: Int = 20
    ): FeedResponse
}
  • ثبات البيانات — لا يتأثر بإضافة/حذف عناصر
  • أداء ثابت O(1) بغض النظر عن عمق التصفح
  • إلزامي للـ feeds الحية (Instagram, TikTok, Twitter)

⚡ تحسين زمن البناء (Build Time Optimization)
KSP over KAPT

استبدل KAPT بـ KSP (Kotlin Symbol Processing) لتقليل زمن البناء بنسبة 25-30% عند استخدام Room, Moshi, أو Dagger.

Configuration Avoidance

استخدم tasks.withType<JavaCompile>().configureEach { } بدلاً من all { } لتجنب تكوين المهام غير الضرورية.

Remote Build Cache

إعداد Gradle Remote Build Cache (عبر Gradle Enterprise أو Bazel) يُقلل زمن البناء الجماعي بشكل كبير.

class FeedRepository @Inject constructor(
    private val api: FeedApi,
    private val dao: PostDao
) {
    // SSOT: Room is the single source of truth
    fun getFeed(): Flow<List<Post>> = 
        dao.getAllPosts()
            .onStart { syncFromNetwork() }
            .flowOn(Dispatchers.IO)

    private suspend fun syncFromNetwork() {
        try {
            val response = api.getFeed(cursor = null)
            dao.insertAll(response.items)
        } catch (e: IOException) {
            // Silently fail — local data is still valid
            Timber.w(e, "Network unavailable, serving cached data")
        }
    }
}

Last-Write-Wins (LWW)

الكتابة الأخيرة تفوز بناءً على الطابع الزمني. بسيط لكنه يفقد البيانات.

Server-Wins / Client-Wins

أحدهما يأخذ الأولوية دائماً. مناسب للأنظمة ذات التسلسل الهرمي الواضح.

🧠 Operational Transformation / CRDTs

للتطبيقات التعاونية (Google Docs, Figma)، استخدم CRDTs (Conflict-free Replicated Data Types) أو Operational Transformation لضمان اتساق البيانات دون Locking مركزي.

// CRDT Example: LWW-Element-Set for collaborative editing
data class LWWElementSet<T>(
    val addSet: Map<T, Long> = emptyMap(),
    val removeSet: Map<T, Long> = emptyMap()
) {
    fun add(element: T, timestamp: Long) = 
        copy(addSet = addSet + (element to timestamp))

    fun lookup(element: T): Boolean {
        val addTime = addSet[element] ?: return false
        val removeTime = removeSet[element] ?: return true
        return addTime > removeTime
    }
}

// OkHttp Cache with Cache-Control strategy
val cache = Cache(context.cacheDir, 50 * 1024 * 1024) // 50 MB

val client = OkHttpClient.Builder()
    .cache(cache)
    .addInterceptor { chain ->
        var request = chain.request()
        val cacheControl = if (hasNetwork()) 
            "public, max-age=" + 60 // 1 min fresh
        else 
            "public, only-if-cached, max-stale=" + 86400 // 1 day stale
        request = request.newBuilder()
            .header("Cache-Control", cacheControl)
            .build()
        chain.proceed(request)
    }
    .build()
🛡️ مرونة الشبكة (Network Resiliency)

Exponential Backoff + Jitter

suspend fun <T> retryWithExponentialBackoff(
    times: Int = 3,
    initialDelay: Long = 1000,
    factor: Double = 2.0,
    block: suspend () -> T
): T {
    var currentDelay = initialDelay
    repeat(times - 1) {
        try { return block() }
        catch (e: IOException) { /* retry */ }
        // Jitter: add randomness to prevent thundering herd
        delay(currentDelay + Random.nextLong(0, currentDelay / 2))
        currentDelay = (currentDelay * factor).toLong().coerceAtMost(60000)
    }
    return block() // Last attempt
}

Circuit Breaker Pattern

class CircuitBreaker(
    private val failureThreshold: Int = 5,
    private val resetTimeout: Long = 30000
) {
    private val state = AtomicReference(State.CLOSED)
    private val failures = AtomicInteger(0)

    enum class State { CLOSED, OPEN, HALF_OPEN }

    fun canExecute(): Boolean = when (state.get()) {
        State.CLOSED -> true
        State.OPEN -> {
            if (System.currentTimeMillis() > lastFailure + resetTimeout) {
                state.set(State.HALF_OPEN); true
            } else false
        }
        State.HALF_OPEN -> true
    }
}

الأداء، الذاكرة وإدارة البطارية (Performance, Battery & Memory Optimization)

🧠 إدارة الذاكرة (Memory Management)

تسرب الذاكرة (Memory Leaks) هو السبب الرئيسي لـ ANRs وعمليات القتل (OOM) في أندرويد. إليك الأنماط الأكثر شيوعاً والحلول.

❌ Common Memory Leak Patterns
  • Static References: الاحتفاظ بـ Context في متغير static
  • Context Leaks: تمرير Activity Context إلى Singleton
  • Handler Leaks: استخدام Handler() بدون WeakReference
  • Listener Leaks: عدم إلغاء تسجيل الـ Listeners في onDestroy()
  • Bitmap Leaks: عدم إعادة تدوير Bitmaps في RecyclerView
✅ Best Practices
  • استخدم LeakCanary في الـ Debug builds
  • استخدم WeakReference<Activity> دائماً
  • استخدم ViewBinding بدلاً من findViewById
  • ألغِ تسجيل الـ Observers في onDestroyView()
  • استخدم Bitmap Pooling مع Glide
// ❌ BAD: Static reference to Activity
object BadSingleton {
    var activity: Activity? = null // LEAK!
}

// ✅ GOOD: Application-scoped context + WeakReference
class SafeRepository @Inject constructor(
    @ApplicationContext private val context: Context
) {
    private val activityRef = WeakReference<Activity>(null)

    fun attachActivity(activity: Activity) {
        activityRef.clear()
        activityRef = WeakReference(activity)
    }
}

🔋 البطارية والتنفيذ في الخلفية (Battery & Background Execution)

الوضع التأثير الاستجابة
Doze Mode تأجيل الـ Network Access و Wake Locks عندما يكون الجهاز ساكناً وغير موصول بالشاحن استخدم WorkManager مع setRequiresBatteryNotLow()

🖼️ خطوط تحميل الوسائط والصور (Media & Image Loading Pipelines)

Bitmap Downsampling (O(1) Scaling)

بدلاً من تحميل الصورة بالحجم الكامل ثم تصغيرها (O(n²))، استخدم inSampleSize لتحميلها بحجم مُخفض مباشرة (O(1)).

fun decodeSampledBitmap(
    options: BitmapFactory.Options,
    reqWidth: Int, reqHeight: Int
): Bitmap {
    options.inJustDecodeBounds = true
    BitmapFactory.decodeResource(resources, resId, options)

    options.inSampleSize = calculateInSampleSize(options, reqWidth, reqHeight)
    options.inJustDecodeBounds = false
    return BitmapFactory.decodeResource(resources, resId, options)
}

// Local queue with Room + WorkManager batching
@Entity(tableName = "analytics_events")
data class AnalyticsEvent(
    @PrimaryKey val id: String = UUID.randomUUID().toString(),
    val eventName: String,
    val payload: String, // JSON
    val timestamp: Long = System.currentTimeMillis(),
    val synced: Boolean = false
)

class AnalyticsBatchWorker(ctx: Context, params: WorkerParameters) : 
    CoroutineWorker(ctx, params) {

    override suspend fun doWork(): Result {
        val events = dao.getUnsyncedEvents(limit = 100)
        if (events.isEmpty()) return Result.success()

        return try {
            api.batchUpload(events)
            dao.markAsSynced(events.map { it.id })
            Result.success()
        } catch (e: Exception) {
            Result.retry()
        }
    }

4. WebSocket + FCM Fallback Strategy
class MessageSyncManager @Inject constructor(
    private val webSocketClient: WebSocketClient,
    private val fcmService: FCMService,
    private val messageDao: MessageDao
) {
    fun sendMessage(message: MessageEntity) {
        // 1. Save locally with PENDING status
        messageDao.insert(message.copy(status = MessageStatus.SENDING))

        // 2. Try WebSocket first
        if (webSocketClient.isConnected()) {
            webSocketClient.send(message)
        } else {
            // 3. Queue for background sync
            WorkManager.getInstance()
                .enqueue(OneTimeWorkRequest.Builder(MessageSyncWorker::class.java)
                    .setConstraints(Constraints.Builder()
                        .setRequiredNetworkType(NetworkType.CONNECTED)
                        .build())
                    .build())
        }
    }

    // FCM fallback for push when app is backgrounded
    fun onFCMMessageReceived(data: Map<String, String>) {
        val message = MessageEntity.fromFCM(data)
        messageDao.insert(message)
        // Acknowledge receipt to server
        sendDeliveryReceipt(message.id)
    }
}

class LocationTrackingService : LifecycleService() {

    private val fusedClient = LocationServices.getFusedLocationProviderClient(this)

    private val locationRequest = LocationRequest.Builder(
        Priority.PRIORITY_BALANCED_POWER_ACCURACY,
        5000 // 5 seconds interval
    ).setWaitForAccurateLocation(false)
     .setMinUpdateIntervalMillis(2000)
     .build()

    override fun onCreate() {
        super.onCreate()
        fusedClient.requestLocationUpdates(
            locationRequest,
            locationCallback,
            Looper.getMainLooper()
        )
    }

    private val locationCallback = object : LocationCallback() {
        override fun onLocationResult(result: LocationResult) {
            val location = result.lastLocation ?: return
            // Batch locations before sending
            batchAndSend(location)
        }
    }

    private fun batchAndSend(location: Location) {
        // Buffer 5 locations then send via WebSocket
        locationBuffer.add(location)
        if (locationBuffer.size >= 5) {
            webSocketClient.sendLocationBatch(locationBuffer)
            locationBuffer.clear()
        }
    }
}
🔋 Battery Optimization Strategy

class FeedPagingSource(
    private val api: FeedApi,
    private val dao: PostDao
) : PagingSource<String, Post>() {

    override suspend fun load(params: LoadParams<String>): LoadResult<String, Post> {
        val cursor = params.key
        return try {
            val response = api.getFeed(cursor = cursor, limit = 20)

            // Cache to Room for offline
            dao.insertAll(response.items)

            LoadResult.Page(
                data = response.items,
                prevKey = null,
                nextKey = response.nextCursor
            )
        } catch (e: Exception) {
            // Return cached data if network fails
            val cached = dao.getPostsAfter(cursor ?: "", limit = params.loadSize)
            if (cached.isNotEmpty()) {
                LoadResult.Page(data = cached, prevKey = null, nextKey = null)
            } else {
                LoadResult.Error(e)
            }
        }
    }
}

class FeedViewHolder(
    private val binding: ItemPostBinding
) : RecyclerView.ViewHolder(binding.root) {

    private var videoPlayer: ExoPlayer? = null

    fun bind(post: Post) {
        // Cancel previous load to prevent cross-contamination
        Glide.with(binding.imageView).clear(binding.imageView)

        when (post.type) {
            PostType.IMAGE -> bindImage(post)
            PostType.VIDEO -> bindVideo(post)
        }
    }

    private fun bindVideo(post: Post) {
        // Release previous player
        videoPlayer?.release()
        videoPlayer = ExoPlayer.Builder(binding.root.context).build().apply {
            setMediaItem(MediaItem.fromUri(post.videoUrl))
            prepare()
            playWhenReady = false // Auto-play only when visible
        }
        binding.playerView.player = videoPlayer
    }

    fun recycle() {
        // CRITICAL: Release resources when view is recycled
        videoPlayer?.release()
        videoPlayer = null
        Glide.with(binding.imageView).clear(binding.imageView)
    }
}

// In Adapter
override fun onViewRecycled(holder: FeedViewHolder) {
    super.onViewRecycled(holder)
    holder.recycle()
}

class PaymentRepository @Inject constructor(
    private val api: PaymentApi,
    private val dao: TransactionDao,
    private val keystoreManager: KeystoreManager
) {
    suspend fun processPayment(
        amount: BigDecimal, 
        paymentMethod: PaymentMethod
    ): Result<Transaction> {
        // 1. Generate idempotency key BEFORE anything else
        val idempotencyKey = UUID.randomUUID().toString()
        val txId = UUID.randomUUID().toString()

        // 2. Save locally as PENDING (zero-data-loss)
        val tx = TransactionEntity(
            id = txId,
            idempotencyKey = idempotencyKey,
            amount = amount,
            status = TransactionStatus.PENDING
        )
        dao.insert(tx)

        // 3. Attempt server processing with idempotency key
        return try {
            val response = api.charge(
                ChargeRequest(
                    amount = amount,
                    paymentMethod = paymentMethod,
                    idempotencyKey = idempotencyKey // Server deduplicates on this
                )
            )

            // 4. Update local state
            dao.updateStatus(txId, TransactionStatus.COMPLETED)
            Result.success(response.transaction)

        } catch (e: Exception) {
            // 5. If network fails, retry later via WorkManager
            WorkManager.getInstance().enqueue(
                OneTimeWorkRequestBuilder<PaymentRetryWorker>()
                    .setInputData(workDataOf("tx_id" to txId))
                    .setBackoffCriteria(
                        BackoffPolicy.EXPONENTIAL,
                        10, TimeUnit.SECONDS
                    )
                    .build()
            )
            Result.failure(e)
        }
    }
}
🔑 Idempotency Key Rules
  • يُولد مرة واحدة عند بدء المعاملة ولا يتغير أبداً
  • يُخزن في الـ Server لمدة 24 ساعة على الأقل
  • إذا تلقى الخادم نفس المفتاح مرتين، يُرجع نفس الاستجابة
  • لا تُعيد توليد المفتاح عند إعادة المحاولة
