المقدمة الاستراتيجية والتحليلية

لماذا تعتبر المقابلات التقنية في قطاع التقنية المالية في ألمانيا وأوروبا شديدة الصعوبة؟

عندما تتقدم لشغل وظيفة في شركة مثل N26 (برلين) أو Klarna (ستوكهولم) أو Adyen (أمستردام)، فأنت لا تتقدم لمجرد وظيفة برمجية عادية. أنت تتقدم للانضمام إلى قلعة رقمية يُدار فيها مليارات اليوروهات يومياً، ويُراقبها منظمون مثل BaFin (الهيئة الاتحادية للرقابة المالية الألمانية) وECB (البنك المركزي الأوروبي).

لنستخدم تشبيهاً واقعياً: تخيّل أنك تتقدم للعمل في خزينة بنك مركزي. لن يسألوك فقط "كيف تُنشئ تطبيقاً؟"، بل سيسألونك: "كيف تضمن أن الخزينة الرقمية لا يمكن اختراقها حتى لو تمكن المهاجم من الوصول الفعلي إلى الجهاز؟" و"كيف تضمن أن التحويل المالي لا يتم تنفيذه مرتين إذا انقطع الإنترنت لثانية واحدة؟"

الفرق الجوهري بين مقابلات Fintech والمقابلات العادية

في المقابلات العادية، قد يسألك المقابل: "كيف تتعامل مع خطأ الشبكة؟" — أما في مقابلات Fintech فيقول: "صمم لي نظاماً يضمن أنه إذا قام المستخدم بتحويل ١٠,٠٠٠ يورو وانقطع الاتصال بعد ثانية واحدة من إرسال الطلب، فلن يتم خصم المبلغ مرتين، ولن يُفقد الطلب، ولن يُعرض للمستخدم رسالة نجاح كاذبة."

هذا الفرق ليس في الصعوبة فحسب، بل في عمق التفكير الهندسي المطلوب. كل سطر برمجي في تطبيق مصرفي رقمي قد يؤثر على أموال حقيقية لملايين الأشخاص.

المعايير التنظيمية والتقنية الصارمة التي تحكم هندسة تطبيقات الموبايل

قبل أن نكتب سطراً واحداً من الكود، يجب أن نفهم القانون الذي نعمل تحت ظله. في أوروبا، هناك ثلاثة أنظمة تنظيمية رئيسية تشكل الإطار القانوني لكل تطبيق مصرفي رقمي:

المعيار التنظيمي الجهة المصدرة التأثير على تطبيق Android العقوبة على عدم الالتزام
PSD2
Payment Services Directive 2		 الاتحاد الأوروبي (٢٠١٩) إلزامية تطبيق Strong Customer Authentication (SCA) على كل عملية مالية تتجاوز ٣٠ يورو. يجب استخدام عاملين منفصلين على الأقل للمصادقة (مثل كلمة المرور + البصمة). غرامات تصل إلى ٤٪ من إجمالي الإيرادات السنوية العالمية
PCI-DSS
Payment Card Industry Data Security Standard		 مجلس معايير صناعة البطاقات منع تخزين أرقام البطاقات الائتمانية (PAN) على الجهاز. إذا اضطررنا لتخزين بيانات مؤقتة، يجب تشفيرها بمعايير AES-256. منع تسجيل أرقام CVV حتى في الذاكرة المؤقتة. غرامات شهرية تتراوح بين ٥,٠٠٠ و١٠٠,٠٠٠ دولار. إلغاء حق المعالجة.
GDPR
General Data Protection Regulation		 الاتحاد الأوروبي يجب الحصول على موافقة صريحة قبل جمع أي بيانات مالية. يجب توفير آلية "النسيان الرقمي" (Right to Erasure) لحذف جميع البيانات المالية عند طلب المستخدم. تسجيل كل عملية وصول إلى البيانات (Audit Trail). غرامات تصل إلى ٢٠ مليون يورو أو ٤٪ من الإيرادات السنوية (أيهما أعلى)
eIDAS
Electronic Identification, Authentication and Trust Services		 الاتحاد الأوروبي التوقيعات الرقمية المستخدمة في المعاملات المالية يجب أن تكون مؤهلة (Qualified Electronic Signature) ومحمية بواسطة مفاتيح Hardware-backed. إلغاء صلاحية التوقيعات الرقمية وعدم الاعتراف القانوني بالمعاملات

تحذير تنظيمي حاسم

في عام ٢٠٢٣، فرضت BaFin غرامة قدرها ٤.٢٥ مليون يورو على بنك رقمي ألماني بسبب "عيوب جسيمة في آليات المصادقة متعددة العوامل داخل تطبيق Android". كان الخلل بسيطاً: التطبيق سمح للمستخدمين بتخطي BiometricPrompt في وضع الطيران (Airplane Mode). هذا الدرس يُعلّمنا أن كل حالة حافة (Edge Case) قد تُكلفك ملايين اليوروهات.

الآن، لنفهم لماذا هذه المعايير تُغيّر طريقة كتابة الكود بالكامل. عندما يفرض عليك PCI-DSS عدم تخزين رقم CVV، فهذا لا يعني فقط "لا تخزنه في قاعدة البيانات" — بل يعني:

  • لا تخزنه في SharedPreferences أو DataStore
  • لا تخزنه في الذاكرة المؤقتة (RAM) لمدة أطول من اللازم
  • لا تُرسله في سجلات الأخطاء (Logcat)
  • لا تُرسله عبر Intent extras إلى Activity أخرى
  • لا تُرسله في تقارير الأعطال (Crashlytics)
  • امسحه من الذاكرة فوراً بعد استخدامه باستخدام Arrays.fill() أو SecureCharArray

 * مثال إنتاجي: تنظيف البيانات الحساسة من الذاكرة فوراً بعد الاستخدام
 * يُحاكي سلوك خزينة بنكية تُعيد مفاتيحها إلى صندوقها الآمن فور الانتهاء
 */
class SecureCardDataHandler {

    // استخدام CharArray بدلاً من String لأن String غير قابل للتعديل (immutable)
    // ويبقى في String Pool حتى يقوم Garbage Collector بتنظيفه
    fun processCvv(cvvInput: CharArray) {
        try {
            // التحقق من صحة CVV
            if (!isValidCvv(cvvInput)) {
                throw IllegalArgumentException("Invalid CVV format")
            }
            // إرسال CVV إلى بوابة الدفع (Tokenization Gateway)
            // لا يتم تخزينه أبداً محلياً
            submitToPaymentGateway(cvvInput)

            java.util.Arrays.fill(cvvInput, '\u0000')
            // إذا كنت تستخدم NDK، يمكنك استخدام memset_secure من OpenSSL
            // memset_secure(cvvBytes, 0, cvvBytes.size)

لاحظ في المثال السابق استخدام CharArray بدلاً من String. لماذا؟ لأن String في JVM غير قابل للتعديل (immutable) ويُخزن في String Pool — مما يعني أنه قد يبقى في الذاكرة لمدة غير محددة حتى يقوم Garbage Collector بتنظيفه. أما CharArray فيمكننا مسحه يدوياً باستخدام Arrays.fill(). هذا الفرق قد يبدو بسيطاً، لكنه الفرق بين تطبيق آمن وآخر عُرضة لهجمات Memory Dump.

هندسة الأمان المتقدمة وحماية البيانات المالية الحساسة

الآلية الداخلية لحماية الذاكرة ومنع تسريب بيانات البطاقات الائتمانية وPIN Codes

تخيّل أنك في خزينة بنك مركزي. عندما يُدخل العميل رمز PIN الخاص به، لا يُسمح لأي شخص بالنظر فوق كتفه. في العالم الرقمي، "النظر فوق الكتف" يتمثل في هجمات Memory Dump — حيث يقوم تطبيق ضار بقراءة ذاكرة تطبيقك أثناء تشغيله.

في نظام Android، كل تطبيق يعمل في Sandbox خاص به، لكن هذا الحماية ليست مطلقة. على الأجهزة المُروتة (Rooted Devices)، يمكن للمهاجم استخدام أدوات مثل GameGuardian أو Frida لقراءة ذاكرة أي تطبيق. حتى على الأجهزة غير المُروتة، يمكن استغلال ثغرات Rowhammer أو CVEs في نواة Linux لقراءة الذاكرة.

استراتيجية "التنظيف الفوري" (Immediate Sanitization)

المبدأ الذهبي: لا تُبقي البيانات الحساسة في الذاكرة أطول من اللازم. بمجرد استخدام رقم البطاقة أو PIN أو CVV، يجب مسحها من الذاكرة فوراً. هذا يُشبه العمل في خزينة بنكية حيث تُعاد الأوراق النقدية إلى الأدراج المحصنة فور الانتهاء من عدها.

Kotlin 
/**
 * SecurePinEntry: مكون إدخال PIN آمن يُحاكي سلوك أجهزة ATM الحقيقية
 *
 * المبدأ: كل رقم يُدخله المستخدم يُخزن في ذاكرة مؤقتة محمية،
 * ويتم مسحها فوراً بعد التحقق أو الإلغاء.
 */
class SecurePinEntry private constructor() {

    // استخدام ByteArray بدلاً من String لأن ByteArray قابل للتعديل
    private val pinBuffer = ByteArray(6) { 0 }
    private var currentIndex = 0

    fun appendDigit(digit: Int): Boolean {
        if (currentIndex >= pinBuffer.size) return false
        if (digit !in 0..9) return false
        pinBuffer[currentIndex] = digit.toByte()
        currentIndex++
        return true
    }

    fun clear() {
        // مسح الذاكرة بشكل آمن — يُعادل إعادة مفاتيح الخزينة إلى صندوقها
        java.util.Arrays.fill(pinBuffer, 0)
        currentIndex = 0
    }

    /**
     * الحصول على نسخة مشفرة من PIN لتوقيع المعاملة
     * يتم استخدام Hardware-backed Keystore للتوقيع
     */
    fun getPinHashForSigning(keyStoreManager: SecureKeyStoreManager): ByteArray? {
        if (currentIndex != pinBuffer.size) return null
        return try {
            // التوقيع باستخدام مفتاح Hardware-backed — PIN لا يُرسل أبداً كـ Plain Text
            keyStoreManager.signWithHardwareKey(pinBuffer)
        } finally {
            // ⚠️ مسح PIN من الذاكرة فوراً بعد التوقيع
            clear()
        }
    }

    protected fun finalize() {
        // حماية إضافية: مسح الذاكرة عند تدمير الكائن
        // ملاحظة: finalize() غير موثوقة 100%، لذا يجب استدعاء clear() صراحةً
        clear()
    }

    companion object {
        fun create(): SecurePinEntry = SecurePinEntry()
    }
}

حماية الذاكرة باستخدام Native Code (NDK)

في بعض الحالات، يكون تنظيف الذاكرة باستخدام Kotlin/Java غير كافٍ. JVM قد تُنشئ نسخاً من البيانات أثناء عملية Garbage Collection أو String Interning. الحل الأمثل هو تخزين البيانات الحساسة في Native Memory باستخدام NDK، حيث يمكننا التحكم الكامل في دورة حياة الذاكرة.

Kotlin + JNI 
/**
 * NativeSecureBuffer: تخزين البيانات الحساسة في Native Heap
 *
 * لماذا Native Heap؟
 * ١. لا يخضع لـ Garbage Collection الخاص بـ JVM
 * ٢. لا يُعرّف String Pool
 * ٣. يمكن استخدام memset_secure من OpenSSL
 * ٤. أصعب في الهندسة العكسية (Reverse Engineering)
 */
class NativeSecureBuffer private constructor(
    private val nativePtr: Long
) : AutoCloseable {

    companion object {
        init {
            System.loadLibrary("securebuffer")
        }
        @JvmStatic external fun nativeAlloc(size: Int): Long
        @JvmStatic external fun nativeWrite(ptr: Long, data: ByteArray, offset: Int)
        @JvmStatic external fun nativeRead(ptr: Long, size: Int): ByteArray
        @JvmStatic external fun nativeSecureClear(ptr: Long, size: Int)
        @JvmStatic external fun nativeFree(ptr: Long)

        fun allocate(size: Int): NativeSecureBuffer {
            val ptr = nativeAlloc(size)
            if (ptr == 0L) throw OutOfMemoryError("Native allocation failed")
            return NativeSecureBuffer(ptr)
        }
    }

    fun write(data: ByteArray, offset: Int = 0) {
        nativeWrite(nativePtr, data, offset)
    }

    fun read(size: Int): ByteArray = nativeRead(nativePtr, size)

    override fun close() {
        // استخدام memset_secure من OpenSSL لمنع التحسين من إزالة المسح
        nativeSecureClear(nativePtr, 4096) // مسح 4KB كحد أقصى
        nativeFree(nativePtr)
    }
}
C++ (JNI) 
// securebuffer.cpp — Native Implementation
#include <jni.h>
#include <openssl/crypto.h>
#include <cstdlib>

extern "C" {

// استخدام OPENSSL_cleanse بدلاً من memset
// لأن المترجم قد يُحسّن memset ويزيلها إذا رأى أن النتيجة غير مستخدمة
JNIEXPORT void JNICALL
Java_com_fintech_security_NativeSecureBuffer_nativeSecureClear(
    JNIEnv* env, jclass clazz, jlong ptr, jint size
) {
    void* nativePtr = reinterpret_cast<void*>(ptr);
    if (nativePtr != nullptr && size > 0) {
        // OPENSSL_cleanse تضمن عدم تحسين المترجم لعملية المسح
        OPENSSL_cleanse(nativePtr, static_cast<size_t>(size));
    }
}

JNIEXPORT jlong JNICALL
Java_com_fintech_security_NativeSecureBuffer_nativeAlloc(
    JNIEnv* env, jclass clazz, jint size
) {
    // استخدام calloc بدلاً من malloc لتصفير الذاكرة عند التخصيص
    return reinterpret_cast<jlong>(calloc(1, static_cast<size_t>(size)));
}

} // extern "C"
💡
لماذا OPENSSL_cleanse وليس memset؟

المترجم الحديث (LLVM/Clang) يستخدم تقنية تُسمى Dead Store Elimination — أي أنه إذا رأى أنك تكتب بيانات في ذاكرة ثم تمسحها دون قراءتها، قد يُحسّن الكود ويزيل عملية الكتابة بالكامل. OPENSSL_cleanse مُصممة خصيصاً لتمنع هذا التحسين، مما يضمن فعلاً مسح البيانات من الذاكرة.

منع أخذ لقطات الشاشة (Screenshots) وتسجيل الشاشة (Screen Recording)

في تطبيقات التقنية المالية، لقطة شاشة واحدة قد تُفضح رقم البطاقة الائتمانية، أو رمز PIN، أو رصيد الحساب. يُشبه هذا ترك نافذة الخزينة مفتوحة أثناء عد النقود. Android يوفر لنا واجهة برمجية بسيطة لمنع هذا:

Kotlin 
/**
 * SecureActivity: Activity أساسي لجميع الشاشات المالية الحساسة
 * يمنع لقطات الشاشة وتسجيل الشاشة تلقائياً
 */
abstract class SecureActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        preventScreenshotAndRecording()
    }

    private fun preventScreenshotAndRecording() {
        // FLAG_SECURE: يمنع كل من لقطات الشاشة وتسجيل الشاشة
        // يعمل أيضاً على منع ظهور المحتوى في Recent Apps Overview
        window.setFlags(
            WindowManager.LayoutParams.FLAG_SECURE,
            WindowManager.LayoutParams.FLAG_SECURE
        )
    }

    /**
     * إضافة حماية إضافية: إخفاء المحتوى عند دخول التطبيق إلى الخلفية
     * يمنع هجمات Recent Apps Screenshot
     */
    override fun onPause() {
        super.onPause()
        // بعض الشركات تفضل إخفاء المحتوى بالكامل في Recent Apps
        // window.addFlags(WindowManager.LayoutParams.FLAG_SECURE) يكفي عادةً
    }
}

تحذير: FLAG_SECURE ليس كافياً بمفرده

على الأجهزة المُروتة، يمكن تخطي FLAG_SECURE باستخدام أدوات مثل Smali Patcher أو Xposed Framework. لذلك، يجب الجمع بين FLAG_SECURE وPlay Integrity API للتحقق من سلامة الجهاز قبل السماح بأي عملية مالية.

التصدي لهجمات تراكب الشاشة (Screen Overlay Attacks)

هجوم التراكب (Overlay Attack) هو من أخطر الهجمات على تطبيقات التقنية المالية. تخيّل أنك تُدخل رمز PIN في تطبيق البنك، لكن في الواقع أنت تُدخله في حقل نصي مزيف يقع فوق التطبيق الحقيقي. هذا ممكن بفضل إذن SYSTEM_ALERT_WINDOW في Android.

في عام ٢٠١٧، اكتشف باحثو أمان أن تطبيقات ضارة تستخدم هذه التقنية لسرقة بيانات تسجيل الدخول لبنوك رئيسية في أوروبا. الحل يتطلب عدة طبقات من الحماية:

Kotlin 
/**
 * OverlayAttackDetector: كشف محاولات التراكب في الوقت الفعلي
 *
 * المبدأ: قبل كل عملية مالية حساسة، نتحقق من عدم وجود تطبيقات
 * تستخدم SYSTEM_ALERT_WINDOW فوق شاشتنا.
 */
class OverlayAttackDetector(
    private val context: Context
) {

    /**
     * التحقق من وجود تطبيقات تراكب نشطة
     * يجب استدعاء هذه الدالة قبل كل عملية مالية (تحويل، دفع، إلخ)
     */
    fun isOverlayAttackDetected(): Boolean {
        // الطريقة ١: التحقق من إذن SYSTEM_ALERT_WINDOW للتطبيقات المثبتة
        if (hasSuspiciousOverlayApps()) {
            return true
        }

        // الطريقة ٢: التحقق من وجود نوافذ تراكب نشطة (Android 6.0+)
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M) {
            if (Settings.canDrawOverlays(context)) {
                // وجود هذا الإذن ليس بالضرورة ضاراً، لكن يجب التحقق
                // من التطبيقات التي تستخدمه
            }
        }

        // الطريقة ٣: استخدام getSystemService(Context.WINDOW_SERVICE) لفحص النوافذ
        return hasActiveOverlayWindows()
    }

    private fun hasSuspiciousOverlayApps(): Boolean {
        val packageManager = context.packageManager
        val installedApps = packageManager.getInstalledApplications(0)

        return installedApps.any { appInfo ->
            // استبعاد تطبيقات النظام الموثوقة
            if ((appInfo.flags & ApplicationInfo.FLAG_SYSTEM) != 0) {
                return@any false
            }

/**

 */
class SecureDatabaseProvider(private val context: Context) {

    private val masterKeyAlias = "_room_master_key_"

    /**
     * توليد أو استرجاع مفتاح SQLCipher بأمان
     * المفتاح مُخزن في Android Keystore — لا يمكن استخراجه حتى من الجذر
     */
    private fun getOrCreateDatabasePassphrase(): ByteArray {
        val masterKey = MasterKey.Builder(context)
            .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
            .setUserAuthenticationRequired(true) // يتطلب Biometric!
            .setUserAuthenticationValidityDurationSeconds(30)
            .build()

        val encryptedPrefs = EncryptedSharedPreferences.create(
            context,
            "secure_db_prefs",
            masterKey,
            EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
            EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
        )

        val existingPassphrase = encryptedPrefs.getString("db_passphrase", null)

        return if (existingPassphrase != null) {
            Base64.decode(existingPassphrase, Base64.DEFAULT)
        } else {
            // توليد passphrase عشوائي ٢٥٦ بت
            val random = SecureRandom()
            val passphrase = ByteArray(32)
            random.nextBytes(passphrase)

            // تخزينه بأمان — مشفر بـ AES-256-GCM
            encryptedPrefs.edit()
                .putString("db_passphrase", Base64.encodeToString(passphrase, Base64.DEFAULT))
                .apply()

            passphrase
        }
    }

    /**
     * إنشاء قاعدة بيانات Room مشفرة
     */
    fun createSecureDatabase(): AppDatabase {
        val passphrase = getOrCreateDatabasePassphrase()

        // إنشاء Factory مشفر لـ Room
        val factory = SupportFactory(passphrase)

        return Room.databaseBuilder(
            context.applicationContext,
            AppDatabase::class.java,
            "fintech_secure_db.db"
        )
            .openHelperFactory(factory) // ← تفعيل SQLCipher
            .addMigrations(*ALL_MIGRATIONS)
            .build()
    }
}

هندسة التشفير من طرف لطرف (End-to-End Encryption - E2EE)

في تطبيقات التقنية المالية، التشفير من طرف لطرف (E2EE) يعني أن البيانات تُشفّر على جهاز المستخدم قبل مغادرته، ولا يمكن فك تشفيرها إلا على السيرفر المستهدف (أو العكس). حتى لو اعترض المهاجم الاتصال، لن يتمكن من قراءة البيانات.

هذا يُشبه إرسال رسالة في صندوق مُغلق بقفل — المفتاح في يد المرسل فقط، والمفتاح المقابل في يد المستلم. لا يمكن لأي طرف وسيط (ISP، VPN، حتى مزود الشبكة) فتح الصندوق.

Kotlin 
/**
 * E2EECryptoManager: إدارة التشفير من طرف لطرف للمعاملات المالية
 *
 * يستخدم مفتاحاً عاماً (Public Key) للتشفير ومفتاحاً خاصاً (Private Key)
 * مخزناً في Android Keystore لفك التشفير.
 */
class E2EECryptoManager(private val context: Context) {

    private val keyStore = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }
    private val keyAlias = "fintech_e2ee_key"

    /**
     * توليد زوج مفاتيح RSA ٤٠٩٦ بت — مُخزن في Hardware-backed Keystore
     * المفتاح الخاص لا يمكن استخراجه أبداً من الجهاز
     */
    fun generateKeyPair(): KeyPair {
        val keyPairGenerator = KeyPairGenerator.getInstance(
            "RSA",
            "AndroidKeyStore"
        )

        val spec = KeyGenParameterSpec.Builder(
            keyAlias,
            KeyProperties.PURPOSE_DECRYPT or KeyProperties.PURPOSE_SIGN
        )
            .setKeySize(4096)
            .setDigests(KeyProperties.DIGEST_SHA256, KeyProperties.DIGEST_SHA512)
            .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_RSA_OAEP)
            .setSignaturePaddings(KeyProperties.SIGNATURE_PADDING_RSA_PSS)
            .setUserAuthenticationRequired(true) // يتطلب Biometric!
            .setUserAuthenticationValidityDurationSeconds(-1) // Biometric كل مرة
            .setRandomizedEncryptionRequired(true) // IV عشوائي — يمنع هجمات التكرار
            .build()

        keyPairGenerator.initialize(spec)
        return keyPairGenerator.generateKeyPair()
    }

    /**
     * تشفير البيانات الحساسة قبل الإرسال
     * يستخدم المفتاح العام للسيرفر (Server Public Key)
     */
    fun encryptForServer(
        plaintext: ByteArray,
        serverPublicKey: PublicKey
    ): EncryptedPayload {
        // توليد مفتاح AES عشوائي للتشفير السريع (Hybrid Encryption)
        val aesKey = ByteArray(32)
        SecureRandom().nextBytes(aesKey)

        // تشفير البيانات بـ AES-256-GCM
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        val iv = ByteArray(12)
        SecureRandom().nextBytes(iv)

        val gcmSpec = GCMParameterSpec(128, iv)
        cipher.init(Cipher.ENCRYPT_MODE, SecretKeySpec(aesKey, "AES"), gcmSpec)
        val ciphertext = cipher.doFinal(plaintext)

        // تشفير مفتاح AES باستخدام RSA Public Key للسيرفر
        val rsaCipher = Cipher.getInstance("RSA/ECB/OAEPWithSHA-256AndMGF1Padding")
        rsaCipher.init(Cipher.ENCRYPT_MODE, serverPublicKey)
        val encryptedAesKey = rsaCipher.doFinal(aesKey)

        // مسح مفتاح AES من الذاكرة فوراً
        java.util.Arrays.fill(aesKey, 0)

        return EncryptedPayload(
            encryptedData = ciphertext,
            encryptedKey = encryptedAesKey,
            iv = iv,
            timestamp = System.currentTimeMillis()
        )
    }

    /**
     * توقيع المعاملة رقمياً باستخدام المفتاح الخاص المخزن في Keystore
     * يضمن عدم إنكار المعاملة (Non-repudiation)
     */
    fun signTransaction(transactionData: ByteArray): ByteArray {
        val privateKey = keyStore.getEntry(keyAlias, null) as KeyStore.PrivateKeyEntry

        val signature = Signature.getInstance("SHA256withRSA/PSS")
        signature.initSign(privateKey.privateKey)
        signature.update(transactionData)
        return signature.sign()
    }
}

data class EncryptedPayload(
    val encryptedData: ByteArray,
    val encryptedKey: ByteArray,
    val iv: ByteArray,
    val timestamp: Long
)

التكامل مع Hardware-backed Keystore لتوليد المفاتيح وتوقيع الحمولات المالية

Android Keystore هو أحد أقوى أدوات الأمان في نظام Android. يوفره النظام كـ Trusted Execution Environment (TEE) أو StrongBox — وهو معالج منفصل مخصص للعمليات التشفيرية الحساسة. المفاتيح المُولدة في Keystore لا يمكن استخراجها أبداً، حتى لو كان الجهاز مُروتاً.

هذا يُشبه خزينة بنكية تقليدية: يمكنك استخدام المفتاح لفتحها، لكن لا يمكنك نسخ المفتاح أو تصويره. حتى لو سرق أحدهم الخزينة، لن يتمكن من فتحها بدون المفتاح الفعلي.

Kotlin 
/**
 * SecureKeyStoreManager: إدارة المفاتيح التشفيرية في Hardware-backed Keystore
 *
 * يدعم StrongBox إذا كان الجهاز يحتوي على معالج أمان منفصل (HSM)
 */
class SecureKeyStoreManager(private val context: Context) {

    private val keyStore = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }

    /**
     * التحقق من دعم الجهاز لـ StrongBox (معالج أمان منفصل)
     * StrongBox يوفر حماية إضافية ضد الهجمات الفيزيائية
     */
    private fun isStrongBoxSupported(): Boolean {
        return Build.VERSION.SDK_INT >= Build.VERSION_CODES.P &&
               context.packageManager.hasSystemFeature(PackageManager.FEATURE_STRONGBOX_KEYSTORE)
    }

    /**
     * توليد مفتاح توقيع مالي — يتطلب Biometric Authentication
     */
    fun generateFinancialSigningKey(alias: String = "financial_signing_key"): KeyPair {
        val keyPairGenerator = KeyPairGenerator.getInstance("RSA", "AndroidKeyStore")

        val builder = KeyGenParameterSpec.Builder(
            alias,
            KeyProperties.PURPOSE_SIGN or KeyProperties.PURPOSE_VERIFY
        )
            .setKeySize(4096)
            .setDigests(KeyProperties.DIGEST_SHA256, KeyProperties.DIGEST_SHA512)
            .setSignaturePaddings(KeyProperties.SIGNATURE_PADDING_RSA_PSS)
            .setUserAuthenticationRequired(true)
            .setInvalidatedByBiometricEnrollment(true) // إبطال المفتاح عند إضافة بصمة جديدة
            .setAttestationChallenge(generateAttestationChallenge()) // للتحقق من صحة المفتاح

        // استخدام StrongBox إذا كان متاحاً — يوفر حماية فيزيائية إضافية
        if (isStrongBoxSupported()) {
            builder.setIsStrongBoxBacked(true)
        }

        keyPairGenerator.initialize(builder.build())
        return keyPairGenerator.generateKeyPair()
    }

    /**
     * توقيع حمولة مالية (Financial Payload) — يتطلب Biometric Prompt
     */
    fun signFinancialPayload(
        alias: String,
        payload: ByteArray
    ): ByteArray {
        val entry = keyStore.getEntry(alias, null) as? KeyStore.PrivateKeyEntry
            ?: throw IllegalStateException("Signing key not found")

        val signature = Signature.getInstance("SHA256withRSA/PSS")
        signature.initSign(entry.privateKey)
        signature.update(payload)
        return signature.sign()
    }

    /**
     * توليد تحدي توثيق (Attestation Challenge) للتحقق من أن المفتاح
     * مُولد فعلاً في Hardware-backed Keystore وليس مُحاكى
     */
    private fun generateAttestationChallenge(): ByteArray {
        val challenge = ByteArray(32)
        SecureRandom().nextBytes(challenge)
        return challenge
    }

    /**
     * التحقق من أن المفتاح لا يزال صالحاً (لم يُبطل عبر إعادة ضبط المصنع أو إضافة بصمة)
     */
    fun isKeyValid(alias: String): Boolean {
        return keyStore.containsAlias(alias) &&
               keyStore.getEntry(alias, null) != null
    }
}

تطبيق Strong Customer Authentication (SCA) وتكامل BiometricPrompt المرتبط بالعمليات المالية

Strong Customer Authentication (SCA) هو قلب نظام PSD2 التنظيمي. يتطلب SCA أن تكون كل عملية مالية إلكترونية مصحوبة بمصادقة تستخدم عاملين منفصلين على الأقل من بين ثلاثة فئات:

  • المعرفة (Knowledge): شيء يعرفه المستخدم — مثل كلمة المرور أو PIN
  • الملكية (Possession): شيء يملكه المستخدم — مثل الجهاز المحمول أو بطاقة الدفع
  • الأصالة (Inherence): شيء يُمثّل المستخدم — مثل البصمة أو بصمة الوجه

في تطبيق Android، الجمع بين PIN (معرفة) + BiometricPrompt (أصالة) يُلبي متطلبات SCA. لكن التنفيذ ليس بهذه البساطة — يجب أن تكون المصادقة مرتبطة بالعملية المالية المحددة وليس مجرد "تسجيل دخول عام".

Kotlin 
/**
 * SCABiometricAuthenticator: مصادقة SCA باستخدام BiometricPrompt
 *
 * يُستخدم فقط للعمليات المالية الحساسة — وليس لتسجيل الدخول العادي.
 * كل عملية مالية تتطلب مصادقة Biometric منفصلة.
 */
class SCABiometricAuthenticator(
    private val activity: FragmentActivity,
    private val cryptoManager: SecureKeyStoreManager
) {

    private val executor = ContextCompat.getMainExecutor(activity)

    /**
     * طلب مصادقة Biometric قبل تنفيذ عملية مالية
     *
     * @param transactionId معرف فريد للمعاملة — يُستخدم في التوقيع
     * @param amount المبلغ — يُعرض للمستخدم للتأكيد
     * @param onSuccess يتم استدعاؤه عند نجاح المصادقة مع توقيع المعاملة
     * @param onError يتم استدعاؤه عند الفشل
     */
    fun authenticateForTransaction(
        transactionId: String,
        amount: String,
        currency: String,
        onSuccess: (ByteArray) -> Unit,
        onError: (SCAError) -> Unit
    ) {
        // ١. التحقق من دعم الجهاز لـ Biometric
        val biometricManager = BiometricManager.from(activity)
        when (biometricManager.canAuthenticate(
            BiometricManager.Authenticators.BIOMETRIC_STRONG
        )) {
            BiometricManager.BIOMETRIC_ERROR_NO_HARDWARE -> {
                onError(SCAError.NoHardware)
                return
            }
            BiometricManager.BIOMETRIC_ERROR_NONE_ENROLLED -> {
                onError(SCAError.NotEnrolled)
                return
            }
            BiometricManager.BIOMETRIC_ERROR_HW_UNAVAILABLE -> {
                onError(SCAError.HardwareUnavailable)
                return
            }
        }

        // ٢. إنشاء CryptoObject مرتبط بالمفتاح الخاص — يتطلب Biometric للوصول
        val cryptoObject = createCryptoObjectForTransaction(transactionId)

        // ٣. إعداد BiometricPrompt
        val promptInfo = BiometricPrompt.PromptInfo.Builder()
            .setTitle("تأكيد المعاملة المالية")
            .setSubtitle("المبلغ: $amount $currency")
            .setDescription("يرجى المصادقة باستخدام بصمة الإصبع لتأكيد هذه المعاملة")
            .setNegativeButtonText("إلغاء")
            .setConfirmationRequired(true) // يتطلب النقر على "تأكيد"
            .setAllowedAuthenticators(
                BiometricManager.Authenticators.BIOMETRIC_STRONG
            )
            .build()

        val biometricPrompt = BiometricPrompt(
            activity,
            executor,
            object : BiometricPrompt.AuthenticationCallback() {
                override fun onAuthenticationSucceeded(
                    result: BiometricPrompt.AuthenticationResult
                ) {
                    // ⚠️ مهم: استخدام CryptoObject للتوقيع — لا يمكن تزويره
                    val signature = result.cryptoObject?.signature
                    if (signature != null) {
                        try {
                            signature.update(transactionId.toByteArray())
                            val signedData = signature.sign()
                            onSuccess(signedData)
                        } catch (e: Exception) {
                            onError(SCAError.SigningFailed)
                        }
                    } else {
                        onError(SCAError.CryptoObjectMissing)
                    }
                }

                override fun onAuthenticationError(errorCode: Int, errString: CharSequence) {
                    onError(SCAError.AuthenticationError(errorCode, errString.toString()))
                }

                override fun onAuthenticationFailed() {
                    onError(SCAError.AuthenticationFailed)
                }
            }
        )

        biometricPrompt.authenticate(promptInfo, cryptoObject)
    }

    /**
     * إنشاء CryptoObject مرتبط بمفتاح Keystore يتطلب Biometric
     */
    private fun createCryptoObjectForTransaction(
        transactionId: String
    ): BiometricPrompt.CryptoObject {
        val keyPair = cryptoManager.generateFinancialSigningKey(
            "sca_tx_" + transactionId
        )

        val signature = Signature.getInstance("SHA256withRSA/PSS")
        signature.initSign(keyPair.private)

        return BiometricPrompt.CryptoObject(signature)
    }
}

sealed class SCAError {
    object NoHardware : SCAError()
    object NotEnrolled : SCAError()
    object HardwareUnavailable : SCAError()
    object SigningFailed : SCAError()
    object CryptoObjectMissing : SCAError()
    object AuthenticationFailed : SCAError()
    data class AuthenticationError(val code: Int, val message: String) : SCAError()
}

إدارة الرموز المميزة (OAuth 2.0 / OpenID Connect / JWT) وتخزينها بأمان تام

في تطبيقات التقنية المالية، Access Tokens وRefresh Tokens هي مفاتيح المملكة الرقمية. إذا سرقها مهاجم، يمكنه الوصول إلى حساب المستخدم وتنفيذ عمليات مالية باسمه. لذلك، يجب تخزينها بأمان قصوى.

Kotlin 
/**
 * SecureTokenManager: إدارة رموز OAuth 2.0 / OIDC بأمان
 *
 * يستخدم EncryptedSharedPreferences لتخزين الرموز
 * ويُدير انتهاء الصلاحية الآلي مع PKCE للمصادقة الآمنة.
 */
class SecureTokenManager(private val context: Context) {

    private val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .build()

    private val encryptedPrefs = EncryptedSharedPreferences.create(
        context,
        "secure_tokens",
        masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )

    /**
     * تخزين رموز المصادقة بأمان — يتم تشفيرها تلقائياً
     */
    fun storeTokens(accessToken: String, refreshToken: String, expiresIn: Long) {
        encryptedPrefs.edit()
            .putString("access_token", accessToken)
            .putString("refresh_token", refreshToken)
            .putLong("expires_at", System.currentTimeMillis() + (expiresIn * 1000))
            .putLong("stored_at", System.currentTimeMillis())
            .apply()
    }

    /**
     * الحصول على Access Token — مع التحقق التلقائي من انتهاء الصلاحية
     */
    suspend fun getValidAccessToken(): String? {
        val expiresAt = encryptedPrefs.getLong("expires_at", 0)

        // إذا انتهت الصلاحية خلال ٥ دقائق القادمة، قم بتحديثها مسبقاً
        if (System.currentTimeMillis() > expiresAt - (5 * 60 * 1000)) {
            return refreshAccessToken()
        }

        return encryptedPrefs.getString("access_token", null)
    }

    /**
     * تحديث Access Token باستخدام Refresh Token
     * يتم في الخلفية دون إزعاج المستخدم
     */
    private suspend fun refreshAccessToken(): String? {
        val refreshToken = encryptedPrefs.getString("refresh_token", null)
            ?: return null

        // استدعاء API لتحديث الرمز
        return try {
            val response = authApi.refreshToken(refreshToken)
            storeTokens(response.accessToken, response.refreshToken, response.expiresIn)
            response.accessToken
        } catch (e: Exception) {
            // إذا فشل التحديث، قم بتسجيل الخروج الآمن
            secureLogout()
            null
        }
    }

    /**
     * تسجيل الخروج الآمن — مسح جميع الرموز من الذاكرة والتخزين
     */
    fun secureLogout() {
        // مسح الرموز من EncryptedSharedPreferences
        encryptedPrefs.edit().clear().apply()

        // إبطال الرموز على السيرفر (Revocation)

    }

استخدام Play Integrity API للتحقق من سلامة الجهاز قبل السماح بإجراء أي معاملة مالية

Play Integrity API هو خليفة SafetyNet Attestation. يتحقق من ثلاثة أشياء أساسية قبل السماح بالعمليات المالية: (١) سلامة التطبيق (لم يُعدّل)، (٢) سلامة الجهاز (غير مُروت)، (٣) صحة الترخيص (تم تنزيله من Google Play).

Kotlin 
/**
 * PlayIntegrityChecker: التحقق من سلامة الجهاز قبل العمليات المالية
 *
 * يجب استدعاء هذه الدالة قبل كل عملية مالية حرجة.
 * إذا فشل التحقق، يتم رفض العملية وإبلاغ السيرفر.
 */
class PlayIntegrityChecker(private val context: Context) {

    private val integrityManager = IntegrityManagerFactory.create(context)

    /**
     * طلب Integrity Token من Google Play Services
     * يتم إرساله إلى السيرفر للتحقق — لا يتم التحقق محلياً!
     */
    suspend fun requestIntegrityToken(
        nonce: String // يجب أن يكون عشوائياً وفريداً لكل طلب
    ): Result<String> = suspendCoroutine { continuation ->
        val request = IntegrityTokenRequest.Builder()
            .setNonce(nonce)
            .build()

        integrityManager.requestIntegrityToken(request)
            .addOnSuccessListener { response ->
                // إرسال token إلى السيرفر للتحقق
                continuation.resume(Result.success(response.token()))
            }
            .addOnFailureListener { exception ->
                // سجل الخطأ وأبلغ السيرفر
                FirebaseCrashlytics.getInstance().recordException(exception)
                continuation.resume(Result.failure(exception))
            }
    }

    /**
     * التحقق السريع قبل العمليات المالية — يستخدم Server-Side Verification
     */
    suspend fun verifyDeviceIntegrity(): IntegrityResult {
        val nonce = generateSecureNonce()

        return when (val tokenResult = requestIntegrityToken(nonce)) {
            is Result.Success -> {
                // إرسال Token إلى السيرفر للتحقق
                val serverResponse = api.verifyIntegrityToken(tokenResult.value, nonce)

                if (serverResponse.deviceIntegrity == "MEETS_DEVICE_INTEGRITY" &&
                    serverResponse.appIntegrity == "MEETS_APP_INTEGRITY") {
                    IntegrityResult.Verified
                } else {
                    IntegrityResult.Compromised(serverResponse)
                }
            }
            is Result.Failure -> {
                IntegrityResult.Error(tokenResult.exception.message ?: "Unknown error")
            }
        }
    }

    private fun generateSecureNonce(): String {
        val nonceBytes = ByteArray(32)
        SecureRandom().nextBytes(nonceBytes)
        return Base64.encodeToString(nonceBytes, Base64.NO_WRAP)
    }
}

sealed class IntegrityResult {
    object Verified : IntegrityResult()
    data class Compromised(val details: ServerIntegrityResponse) : IntegrityResult()
    data class Error(val message: String) : IntegrityResult()
}

ضمان عدم تكرار المعاملات المالية (Idempotency in Mobile APIs)

Idempotency هي من أهم المفاهيم في هندسة التقنية المالية. المعاملة "Idempotent" هي تلك التي يمكن إرسالها مرات عديدة دون تغيير النتيجة النهائية. تخيّل أنك تضغط زر "تحويل" وانقطع الإنترنت — إذا أعدت الضغط، يجب أن يتم التحويل مرة واحدة فقط.

هذا يُشبه إرسال طرد بريدي مسجل: حتى لو أرسلت نسخاً متعددة من نفس الطرد، سيصل المستلم نسخة واحدة فقط. المفتاح هو مفتاح Idempotency فريد يُرفق بكل طلب.

Kotlin 
/**
 * IdempotencyKeyGenerator: توليد مفاتيح Idempotency فريدة وآمنة
 *
 * المفتاح يجب أن يكون:
 * ١. فريداً — لا يتكرر أبداً
 * ٢. غير قابل للتوقع — يمنع هجمات التخمين
 * ٣. مرتبطاً بالمعاملة — نفس المدخلات = نفس المفتاح
 * ٤. مُخزناً محلياً — للإعادة عند فشل الشبكة
 */
class IdempotencyKeyGenerator {

    /**
     * توليد مفتاح Idempotency بناءً على بيانات المعاملة
     * يضمن أن نفس المعاملة دائماً تحصل على نفس المفتاح
     */
    fun generate(
        userId: String,
        amount: BigDecimal,
        recipientIban: String,
        timestamp: Long = System.currentTimeMillis()
    ): String {
        // الجمع بين معرف المستخدم + المبلغ + المستلم + الطابع الزمني
        // الطابع الزمني يُقرب إلى أقرب دقيقة — يسمح بإعادة المحاولة خلال نفس الدقيقة
        val timeBucket = (timestamp / (60 * 1000)) * (60 * 1000)

        val data = "$userId|$amount|$recipientIban|$timeBucket"

        // استخدام HMAC-SHA256 لتوليد مفتاح غير قابل للتوقع
        val mac = Mac.getInstance("HmacSHA256")
        mac.init(getHmacKey())
        val hash = mac.doFinal(data.toByteArray())

        return "idemp_" + Base64.encodeToString(hash, Base64.URL_SAFE | Base64.NO_WRAP)
    }

    private fun getHmacKey(): SecretKey {
        // في الإنتاج، يُخزن هذا المفتاح في Android Keystore
        // هنا نستخدم مفتاح مشتق من معرف الجهاز + Salt ثابت
        return SecretKeySpec("device-specific-key-32-bytes!".toByteArray(), "HmacSHA256")
    }
}

إدارة طوابير العمليات المحلية (Local Transaction Queues)

في بيئة ضعيفة الاتصال (مثل المترو في برلين أو الطائرة)، يجب أن يظل المستخدم قادراً على "إنشاء" معاملات حتى لو لم يكن هناك إنترنت. هذه المعاملات تُخزن محلياً في قاعدة بيانات مشفرة، ثم تُرسل تلقائياً عند استعادة الاتصال.

Kotlin 
/**
 * TransactionQueueManager: إدارة طابور المعاملات المحلي
 *
 * يُخزن المعاملات في Room + SQLCipher، ويُرسلها عبر WorkManager
 * عند استعادة الاتصال مع ضمان عدم التكرار عبر Idempotency Keys.
 */
class TransactionQueueManager(
    private val context: Context,
    private val database: AppDatabase,
    private val apiService: TransactionApiService,
    private val idempotencyGenerator: IdempotencyKeyGenerator
) {

    /**
     * إضافة معاملة جديدة إلى الطابور المحلي
     * تعمل حتى بدون إنترنت
     */
    suspend fun enqueueTransaction(
        request: TransferRequest
    ): Result<String> { // Returns transactionId
        val transactionId = UUID.randomUUID().toString()
        val idempotencyKey = idempotencyGenerator.generate(
            userId = request.userId,
            amount = request.amount,
            recipientIban = request.recipientIban
        )

        val entity = TransactionEntity(
            id = transactionId,
            amount = request.amount,
            currency = request.currency,
            recipientIban = request.recipientIban,
            maskedPan = request.maskedPan,
            status = TransactionStatus.PENDING,
            createdAt = System.currentTimeMillis(),
            syncedWithServer = false,
            localSignature = null // يُوقّع عند الإرسال
        )

        // تخزين محلي مشفر — يعمل حتى بدون إنترنت
        database.transactionDao().insertTransaction(entity)

        // جدولة إرسال المعاملة عبر WorkManager
        scheduleSyncWork(transactionId, idempotencyKey)

        return Result.success(transactionId)
    }

    /**
     * جدولة عملية مزامنة باستخدام WorkManager
     * تتعامل مع القيود: يجب وجود إنترنت، ولا يتم الإرسال إلا عبر WiFi/Cellular آمن
     */
    private fun scheduleSyncWork(
        transactionId: String,
        idempotencyKey: String
    ) {
        val constraints = Constraints.Builder()
            .setRequiredNetworkType(NetworkType.CONNECTED)
            .setRequiresBatteryNotLow(true)
            .build()

        val syncWork = OneTimeWorkRequestBuilder<TransactionSyncWorker>()
            .setInputData(workDataOf(
                "transaction_id" to transactionId,
                "idempotency_key" to idempotencyKey
            ))
            .setConstraints(constraints)
            .setBackoffCriteria(
                BackoffPolicy.EXPONENTIAL,
                10, TimeUnit.SECONDS // إعادة محاولة تصاعدية
            )
            .addTag("transaction_sync")
            .build()

        WorkManager.getInstance(context).enqueueUniqueWork(
            "sync_" + transactionId,
            ExistingWorkPolicy.KEEP, // لا تُكرر إذا كانت موجودة
            syncWork
        )
    }

    /**
     * Worker: إرسال المعاملة إلى السيرفر
     * يُعالج إعادة المحاولة التلقائية والأخطاء
     */
    class TransactionSyncWorker(
        context: Context,
        params: WorkerParameters,
        private val api: TransactionApiService,
        private val db: AppDatabase
    ) : CoroutineWorker(context, params) {

        override suspend fun doWork(): Result {
            val transactionId = inputData.getString("transaction_id") ?: return Result.failure()
            val idempotencyKey = inputData.getString("idempotency_key") ?: return Result.failure()

            val transaction = db.transactionDao().getTransactionById(transactionId)
                ?: return Result.failure()

            // تحديث الحالة إلى SENT قبل الإرسال
            db.transactionDao().updateStatus(transactionId, TransactionStatus.SENT)

            return try {
                // إرسال المعاملة مع Idempotency Key
                val response = api.submitTransaction(
                    idempotencyKey = idempotencyKey,
                    request = TransactionRequest(
                        id = transactionId,
                        amount = transaction.amount,
                        currency = transaction.currency,
                        recipientIban = transaction.recipientIban
                    )
                )

                // ✅ نجاح: تحديث الحالة إلى CONFIRMED
                db.transactionDao().markAsSynced(
                    transactionId,
                    TransactionStatus.CONFIRMED
                )
                Result.success()

            } catch (e: HttpException) {
                when (e.code()) {
                    409 -> { // Conflict — المعاملة موجودة بالفعل (Idempotency)
                        db.transactionDao().markAsSynced(
                            transactionId,
                            TransactionStatus.CONFIRMED
                        )
                        Result.success()
                    }
                    400, 422 -> { // Bad Request — خطأ في البيانات، لا فائدة من الإعادة
                        db.transactionDao().updateStatus(
                            transactionId,
                            TransactionStatus.FAILED
                        )
                        Result.failure()
                    }
                    else -> { // أخطاء أخرى — إعادة محاولة
                        db.transactionDao().updateStatus(
                            transactionId,
                            TransactionStatus.PENDING
                        )
                        Result.retry()
                    }
                }
            } catch (e: IOException) {
                // خطأ شبكة — إعادة محاولة
                db.transactionDao().updateStatus(transactionId, TransactionStatus.PENDING)
                Result.retry()
            }
        }
    }
}

التعامل المعماري المتقدم مع أخطاء الشبكة: Optimistic UI vs Pessimistic UI

في التطبيقات المالية، اختيار نمط تحديث واجهة المستخدم يعتمد على طبيعة العملية. المعاملات المالية الحساسة تتطلب Pessimistic UI (انتظار تأكيد السيرفر)، بينما العمليات غير الحساسة (مثل تفضيلات العرض) يمكن استخدام Optimistic UI.

النمط متى يُستخدم؟ المخاطر مثال Fintech
Optimistic UI عندما يمكن التراجع عن العملية بسهولة قد يُعرض للمستخدم حالة نجاح كاذبة تغيير اسم الحساب، تفعيل/إلغاء الإشعارات
Pessimistic UI عندما لا يمكن التراجع عن العملية تجربة مستخدم أبطأ لكن أكثر أماناً تحويل مالي، دفع فاتورة، شراء أسهم
Hybrid UI عرض حالة وسطى (Pending) مع إمكانية التراجع يتطلب آلية تراجع معقدة تحويل مالي مع "إلغاء" خلال ٥ دقائق

Kotlin 
/**
 * TransferFundsUseCase: Use Case لتنفيذ تحويل مالي
 *
 * يعزل المنطق المالي عن واجهة المستخدم وطبقة البيانات.
 * يمكن اختباره بشكل مستقل بدون Android Framework.
 */
class TransferFundsUseCase(
    private val transactionRepository: TransactionRepository,
    private val securityManager: SecurityManager,
    private val idempotencyGenerator: IdempotencyKeyGenerator,
    private val scaAuthenticator: SCABiometricAuthenticator
) {

    /**
     * تنفيذ التحويل المالي مع جميع طبقات الحماية:
     * ١. التحقق من SCA (Biometric)
     * ٢. توليد Idempotency Key
     * ٣. التوقيع الرقمي للمعاملة
     * ٤. إرسال المعاملة عبر Repository
     * ٥. التعامل مع الأخطاء والتراجع
     */
    suspend operator fun invoke(
        request: TransferRequest
    ): Result<TransactionResult> {
        // ١. التحقق من صحة المدخلات في طبقة Domain
        val validation = validateRequest(request)
        if (validation != null) {
            return Result.failure(validation)
        }

        // ٢. توليد مفتاح Idempotency
        val idempotencyKey = idempotencyGenerator.generate(
            userId = request.userId,
            amount = request.amount,
            recipientIban = request.recipientIban
        )

        // ٣. المصادقة القوية (SCA) — Biometric Prompt
        val authResult = suspendCancellableCoroutine { continuation ->
            scaAuthenticator.authenticateForTransaction(
                transactionId = request.id,
                amount = request.amount.toPlainString(),
                currency = request.currency,
                onSuccess = { signature ->
                    continuation.resume(Result.success(signature))
                },
                onError = { error ->
                    continuation.resume(Result.failure(SCAException(error)))
                }
            )
        }

        if (authResult.isFailure) {
            return Result.failure(authResult.exceptionOrNull()!!)
        }

        // ٤. إنشاء المعاملة الموقعة رقمياً
        val signedTransaction = SignedTransaction(
            request = request,
            idempotencyKey = idempotencyKey,
            userSignature = authResult.getOrThrow(),
            timestamp = System.currentTimeMillis()
        )

        // ٥. إرسال المعاملة عبر Repository (يعزل طبقة البيانات)
        return transactionRepository.submitTransaction(signedTransaction)
    }

    private fun validateRequest(request: TransferRequest): Throwable? {
        return when {
            request.amount <= BigDecimal.ZERO ->
                IllegalArgumentException("Amount must be positive")
            request.recipientIban.isBlank() ->
                IllegalArgumentException("IBAN is required")
            request.amount > BigDecimal("50000") ->
                IllegalArgumentException("Amount exceeds daily limit")
            else -> null
        }
    }
}

Feature Modularization لعزل الوحدات المالية الحساسة

في تطبيق مصرفي رقمي، لا يجب أن يكون كود معالجة التحويلات المالية في نفس الوحدة مع كود عرض الإعلانات أو إعدادات المستخدم. Feature Modularization يتيح لنا:

  • عزل الأمان: الوحدة المالية يمكنها الوصول إلى Keystore فقط

/**
 * OfflineFirstTransferService: خدمة تحويل تعمل أولاً محلياً ثم تتزامن
 *
 * المبدأ: "الحقيقة المصدر" (Source of Truth) هي قاعدة البيانات المحلية المشفرة.
 * السيرفر هو مجرد مرآة للحقيقة المحلية.
 */
class OfflineFirstTransferService(
    private val localDb: AppDatabase,
    private val remoteApi: TransferApi,
    private val networkMonitor: NetworkMonitor
) {
    /**
     * ١. يُنشئ المعاملة محلياً فوراً — حتى بدون إنترنت
     * ٢. يعرض للمستخدم "تم الإنشاء" (لكن ليس "تم التأكيد")
     * ٣. يُرسل تلقائياً عند استعادة الاتصال
     */
    suspend fun initiateTransfer(
        request: TransferRequest
    ): TransferResult {
        val transactionId = UUID.randomUUID().toString()
        val idempotencyKey = generateIdempotencyKey(request)

        // ١. حفظ محلي فوري — "الحقيقة المصدر"
        val localTransaction = TransactionEntity(
            id = transactionId,
            amount = request.amount,
            currency = request.currency,
            recipientIban = request.recipientIban,
            status = TransactionStatus.PENDING,
            createdAt = System.currentTimeMillis(),
            syncedWithServer = false,
            localSignature = null
        )
        localDb.transactionDao().insertTransaction(localTransaction)

        // ٢. محاولة الإرسال الفوري إذا كان هناك إنترنت
        if (networkMonitor.isOnline()) {
            return attemptSync(localTransaction, idempotencyKey)
        }

        // ٣. بدون إنترنت — جدولة المزامنة التلقائية
        scheduleDeferredSync(transactionId, idempotencyKey)

        return TransferResult.Queued(
            transactionId = transactionId,
            message = "تم حفظ التحويل. سيتم الإرسال تلقائياً عند استعادة الاتصال."
        )
    }

    /**
     * محاولة مزامنة المعاملة مع السيرفر
     * يتعامل مع جميع حالات الحافة
     */
    private suspend fun attemptSync(
        transaction: TransactionEntity,
        idempotencyKey: String
    ): TransferResult {
        return try {
            // إرسال مع Idempotency Key
            val response = remoteApi.submitTransfer(
                idempotencyKey = idempotencyKey,
                request = TransferApiRequest(
                    id = transaction.id,
                    amount = transaction.amount,
                    currency = transaction.currency,
                    recipientIban = transaction.recipientIban
                )
            )

            // ✅ نجاح — تحديث الحالة محلياً
            localDb.transactionDao().markAsSynced(
                transaction.id,
                TransactionStatus.CONFIRMED
            )

            TransferResult.Success(
                transactionId = transaction.id,
                serverConfirmationId = response.confirmationId
            )

        } catch (e: HttpException) {
            when (e.code()) {
                409 -> { // Conflict — المعاملة موجودة بالفعل!
                    localDb.transactionDao().markAsSynced(
                        transaction.id, TransactionStatus.CONFIRMED
                    )
                    TransferResult.Success(
                        transactionId = transaction.id,
                        message = "تم التأكيد (معاملة مكررة تم اكتشافها)"
                    )
                }
                400, 422 -> { // خطأ في البيانات — لا فائدة من الإعادة
                    localDb.transactionDao().updateStatus(
                        transaction.id, TransactionStatus.FAILED
                    )
                    TransferResult.Error(
                        message = "فشل التحويل: ${e.message()}",
                        isRetryable = false
                    )
                }
                else -> { // خطأ سيرفر — إعادة محاولة لاحقاً

                    TransferResult.Queued(
                        transactionId = transaction.id,
                        message = "تم حفظ التحويل. سيتم إعادة المحاولة."
                    )
                }
            }
        } catch (e: IOException) {
            // انقطاع الشبكة — إعادة محاولة لاحقاً
            scheduleDeferredSync(transaction.id, idempotencyKey)
            TransferResult.Queued(
                transactionId = transaction.id,

/**
 * AntiTamperingDetector: كشف التلاعب في الوقت الفعلي
 *
 * يجمع بين عدة تقنيات:
 * ١. فحص وجود Frida Server
 * ٢. فحص Debugger Attachment
 * ٣. فحص Root Detection
 * ٤. Native Integrity Checks

class AntiTamperingDetector(private val context: Context) {

    /**
     * فحص شامل — يجب استدعاؤه قبل كل عملية مالية حرجة
     */
    fun isDeviceCompromised(): TamperingResult {
        val checks = listOf(
            ::checkFridaPresence,
            ::checkDebuggerAttached,
            ::checkRootedDevice,
            ::checkEmulator,
            ::checkAppIntegrity
        )

        val failures = checks.mapNotNull { it() }

        return if (failures.isEmpty()) {
            TamperingResult.Clean
        } else {
            TamperingResult.Compromised(failures)
        }
    }

    /**
     * ١. فحص وجود Frida Server
     * Frida تُنشئ منفذ TCP 27042 على الجهاز
     */
    private fun checkFridaPresence(): String? {
        return try {
            Socket("localhost", 27042).use { socket ->
                if (socket.isConnected) {
                    "Frida server detected on port 27042"
                } else null
            }
        } catch (e: Exception) {
            null // Frida غير موجود — هذا جيد
        }
    }

    /**
     * ٢. فحص وجود Debugger مرتبط
     */
    private fun checkDebuggerAttached(): String? {
        return when {
            Debug.isDebuggerConnected() -> "Debugger attached"
            Debug.waitingForDebugger() -> "Waiting for debugger"
            else -> null
        }
    }

    /**
     * ٣. فحص الجهاز المُروت
     */
    private fun checkRootedDevice(): String? {
        val rootIndicators = listOf(
            "/system/bin/su",
            "/system/xbin/su",
            "/sbin/su",
            "/su/bin/su",
            "/data/local/xbin/su",
            "/data/local/bin/su",
            "/system/app/Superuser.apk",
            "/system/app/Kinguser.apk"
        )

        val found = rootIndicators.filter { File(it).exists() }
        return if (found.isNotEmpty()) {
            "Root indicators found: ${found.joinToString()}"
        } else null
    }

    /**
     * ٤. فحص المحاكي
     */
    private fun checkEmulator(): String? {
        val isEmulator = Build.FINGERPRINT.startsWith("generic") ||
            Build.FINGERPRINT.startsWith("unknown") ||
            Build.MODEL.contains("google_sdk") ||
            Build.MODEL.contains("Emulator") ||
            Build.MODEL.contains("Android SDK built for x86") ||

        }
    }

سؤال من مقابلات Adyen — مستوى Principal Engineer

"المستخدم يفتح التطبيق على هاتفه وعلى جهازه اللوحي في نفس الوقت. يبدأ تحويلاً على الهاتف وينتقل إلى الجهاز اللوحي أثناء المعالجة. كيف تتعامل مع هذه الحالة تحت متطلبات PSD2؟"

PSD2 يتطلب أن تكون كل عملية مالية مصحوبة بمصادقة قوية (SCA). لكن ماذا إذا كانت الجلسة على الجهاز اللوحي منتهية الصلاحية بينما الجلسة على الهاتف لا تزال نشطة؟

●●●●● مستوى خبير
Kotlin 
/**
 * SessionManager: إدارة الجلسات المتعددة بأمان
 *
 * متوافق مع PSD2: كل عملية مالية تتطلب SCA منفصلة
 * حتى لو كانت الجلسة نشطة. لا يوجد "تسجيل دخول واحد يكفي للجميع".
 */
class SessionManager(
    private val tokenManager: SecureTokenManager,
    private val api: SessionApi
) {

    /**
     * كل عملية مالية تتطلب "مصادقة ديناميكية" (Dynamic Linking)
     * حسب PSD2: رمز المصادقة يجب أن يكون مرتبطاً بالمبلغ والمستلم
     */
    suspend fun authenticateTransaction(
        transaction: TransferRequest
    ): Result<TransactionAuthToken> {
        // ١. التحقق من صلاحية الجلسة العامة
        val sessionValid = validateSession()
        if (!sessionValid) {
            return Result.failure(SessionExpiredException())
        }

        // ٢. PSD2 Dynamic Linking: رمز المصادقة مرتبط بالمعاملة
        // الرمز يجب أن يتضمن: المبلغ + المستلم + معرف الجهاز
        val dynamicLinkingData = "${transaction.amount}|${transaction.recipientIban}|${getDeviceId()}"

        // ٣. طلب رمز مصادقة مؤقت (Transaction-Specific) من السيرفر
        return try {
            val authToken = api.requestTransactionAuth(
                sessionToken = tokenManager.getValidAccessToken()!!,
                dynamicLinkingData = dynamicLinkingData
            )

            // ٤. عرض Biometric Prompt للمستخدم
            // الرمز يُستخدم مرة واحدة فقط وله مدة صلاحية ٥ دقائق
            Result.success(authToken)

        } catch (e: Exception) {
            Result.failure(e)
        }
    }

    /**
     * التحقق من صلاحية الجلسة — يتحقق من:
     * ١. عدم انتهاء صلاحية Access Token
     * ٢. عدم إبطال الجلسة من السيرفر (Remote Revocation)
     * ٣. عدم تغيير معرف الجهاز (Device Binding)
     */
    private suspend fun validateSession(): Boolean {
        val token = tokenManager.getValidAccessToken() ?: return false

        return try {
            val sessionStatus = api.validateSession(token, getDeviceId())
            sessionStatus.isValid && !sessionStatus.isRevoked
        } catch (e: Exception) {
            false
        }
    }

    /**
     * إبطال جميع الجلسات على الأجهزة الأخرى
     * يُستخدم عند تغيير كلمة المرور أو اكتشاف نشاط مشبوه
     */
    suspend fun revokeAllOtherSessions() {
        val currentDeviceId = getDeviceId()
        api.revokeSessions(
            token = tokenManager.getValidAccessToken()!!,
            exceptDeviceId = currentDeviceId
        )
    }

    private fun getDeviceId(): String {
        // في الإنتاج: استخدام Android ID + Hardware Fingerprint
        // لا تستخدم Advertising ID — يمكن تغييره
        return Settings.Secure.getString(
            context.contentResolver,
            Settings.Secure.ANDROID_ID
        ) ?: "unknown"
    }
}

 *
 * يثبت شهادة السيرفر داخل التطبيق — يمنع هجمات MITM

        "sha256/AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=", // Primary
        "sha256/BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB="  // Backup
    )

    fun create(context: Context): OkHttpClient {
        val certificatePinner = CertificatePinner.Builder()
            .add("api.fintech-bank.com", *PINNED_CERTIFICATES.toTypedArray())
            .build()

        return OkHttpClient.Builder()
            .certificatePinner(certificatePinner)
            .connectionSpecs(listOf(
                ConnectionSpec.Builder(ConnectionSpec.MODERN_TLS)
                    .tlsVersions(TlsVersion.TLS_1_3) // TLS 1.3 فقط!
                    .cipherSuites(
                        CipherSuite.TLS_AES_256_GCM_SHA384,
                        CipherSuite.TLS_CHACHA20_POLY1305_SHA256
                    )
                    .build()
            ))
            .addInterceptor { chain ->
                // إضافة Idempotency Key لكل طلب POST/PUT
                val request = chain.request()
                val newRequest = if (request.method in listOf("POST", "PUT", "PATCH")) {
                    request.newBuilder()
                        .header("X-Idempotency-Key", generateIdempotencyKey())
                        .build()
                } else request
                chain.proceed(newRequest)
            }
            .addInterceptor { chain ->
                // إضافة Device Fingerprint لكل طلب — يساعد في كشف MITM
                val request = chain.request()
                val newRequest = request.newBuilder()
                    .header("X-Device-Fingerprint", getDeviceFingerprint(context))
                    .header("X-App-Version", BuildConfig.VERSION_NAME)
                    .build()
                chain.proceed(newRequest)
            }
            .connectTimeout(15, TimeUnit.SECONDS)
            .readTimeout(30, TimeUnit.SECONDS)
            .writeTimeout(30, TimeUnit.SECONDS)
            .build()
    }

    private fun generateIdempotencyKey(): String {
        val bytes = ByteArray(16)
        SecureRandom().nextBytes(bytes)
        return Base64.encodeToString(bytes, Base64.NO_WRAP)
    }

    private fun getDeviceFingerprint(context: Context): String {
        // مزيج من معرف الجهاز + إصدار التطبيق + طابع زمني
        val raw = "${Build.BOARD}${Build.BRAND}${Build.DEVICE}${Build.HARDWARE}"
        return hashString(raw, "SHA-256")
    }
