01 · الأساسيات

أنواع الـ Collections في Kotlin

كل الـ Collections في Kotlin مبنية على تفرقة واضحة بين النسخ اللي ممكن تتعدّل (Mutable) والنسخ اللي للقراءة بس (Read-only) — الفرق مش في الـ Class نفسه، لكن في الـ Interface اللي بتتعامل بيه.

List

عناصر مرتّبة، وممكن يتكرر نفس العنصر أكتر من مرة. الترتيب مهم والوصول بيكون بالـ Index.

listOf()mutableListOf()ArrayList

Set

عناصر فريدة (بدون تكرار). مفيد لما تحتاج تتأكد إن كل عنصر موجود مرة واحدة بس.

setOf()mutableSetOf()HashSet

Map

مجموعة من أزواج مفتاح-قيمة (Key-Value). كل مفتاح فريد وبيشاور لقيمة واحدة.

mapOf()mutableMapOf()HashMap
Collections.kt
// Read-only — للقراءة فقط، مش هتقدر تضيف أو تحذف
val names: List<String> = listOf("أحمد", "سارة", "محمد")

// Mutable — قابلة للتعديل
val cart: MutableList<String> = mutableListOf("قلم", "دفتر")
cart.add("مسطرة")

// Set — بدون تكرار
val uniqueIds: Set<Int> = setOf(1, 2, 2, 3) // النتيجة: {1, 2, 3}

// Map — مفتاح وقيمة
val userAges: Map<String, Int> = mapOf("أحمد" to 25, "سارة" to 30)
02 · عمليات التحويل

أهم العمليات على الـ Collections

Kotlin بتوفّر مكتبة ضخمة من الـ Extension Functions اللي بتخليك تتعامل مع البيانات بأسلوب وظيفي (Functional) وبكود أقصر بكتير.

map()

بتحوّل كل عنصر لشكل جديد.

val names = users.map { it.name }
filter()

بترجع بس العناصر اللي بتحقق شرط معيّن.

val adults = users.filter { it.age >= 18 }
sortedBy()

بترتب العناصر حسب خاصية معينة.

val sorted = users.sortedBy { it.name }
groupBy()

بتقسّم العناصر لمجموعات على أساس مفتاح.

val byCity = users.groupBy { it.city }
reduce() / fold()

بتجمع كل العناصر لقيمة واحدة نهائية.

val total = cart.fold(0) { acc, item -> acc + item.price }
find() / firstOrNull()

بترجع أول عنصر يحقق الشرط أو null.

val admin = users.find { it.role == "admin" }
any() / all() / none()

بترجع Boolean حسب تحقق الشرط على العناصر.

val hasAdmin = users.any { it.role == "admin" }
flatMap()

بتحوّل كل عنصر لقائمة، وبعدين تدمجهم في قائمة واحدة.

val allTags = posts.flatMap { it.tags }
03 · التنفيذ الكسول

إيه هي الـ Sequence وليه بتفرق؟

الفرق الجوهري بين Collection و Sequence مش في العمليات المتاحة، لكن في إمتى وإزاي بتتنفذ العمليات دي على البيانات.

1

Collection = تنفيذ فوري (Eager)

كل عملية زي map أو filter بتتنفذ على كل الـ List فورًا وبترجع List جديدة كاملة، قبل ما تنتقل للعملية التالية.

Eager.kt
val result = numbers
    .map { it * 2 }       // بتعمل List كامل هنا
    .filter { it > 10 }   // وبعدين List تاني كامل هنا
    .first()             // حتى لو محتاج عنصر واحد بس!
2

Sequence = تنفيذ كسول (Lazy)

كل عنصر بيمر بكل العمليات واحد واحد بدل ما تتعمل List وسيطة في كل خطوة. التنفيذ الفعلي بيحصل بس لما تستدعي عملية "طرفية" زي toList() أو first().

Lazy.kt
val result = numbers
    .asSequence()
    .map { it * 2 }
    .filter { it > 10 }
    .first()   // بتوقف فورًا أول ما تلاقي نتيجة، من غير ما تكمل باقي القائمة
3

الفرق في الأداء عمليًا

لو عندك قائمة فيها مليون عنصر وعايز بس أول عنصر يحقق شرط بعد عمليتين، الـ Collection هتعالج المليون عنصر مرتين كاملين، بينما الـ Sequence ممكن توقف بعد أول عنصر بس.

04 · مقارنة مباشرة

Collection ضد Sequence

مفيش واحد "أفضل" مطلقًا — الاختيار بيعتمد على حجم البيانات وعدد العمليات المتسلسلة.

📦 Collection

  • تنفيذ فوري (Eager) — كل خطوة بتعمل List وسيطة
  • مناسبة للقوائم الصغيرة والمتوسطة
  • أبسط في القراءة والتتبع أثناء الـ Debug
  • أسرع مع عدد عمليات قليل (1-2 عملية)
VS

🌊 Sequence

  • تنفيذ كسول (Lazy) — عنصر بعنصر عند الطلب
  • مثالية للقوائم الكبيرة أو سلسلة عمليات طويلة
  • بتوفّر ذاكرة لأنها مش بتعمل Lists وسيطة
  • أسرع مع أي عدد عمليات + بيانات كبيرة
المعيارCollectionSequence
طريقة التنفيذفوري (Eager)كسول (Lazy)
القوائم الوسيطةبتتعمل في كل خطوةمفيش، معالجة مباشرة
الأنسب لـبيانات صغيرة / عملية أو اتنينبيانات كبيرة / سلسلة عمليات طويلة

05 · تطبيق عملي

استخدامها في تطبيق أندرويد

مثال شائع: عندك قائمة منتجات جاية من API، وعايز تفلترها وتحولها لموديل UI، وتاخد أول 20 منتج بس متاحين في المخزون.

ProductMapper.kt
fun mapToUiProducts(rawProducts: List<ProductDto>): List<ProductUiModel> {
    return rawProducts
        .asSequence()                                  // نبدأ التنفيذ الكسول
        .filter { it.stock > 0 }                     // بس المتاح في المخزون
        .map { it.toUiModel() }                     // تحويل من DTO لموديل UI
        .sortedByDescending { it.rating }             // الأعلى تقييمًا الأول
        .take(20)                                    // أول 20 منتج بس
        .toList()                                     // عملية Terminal — هنا بيتنفذ كل حاجة فعليًا
}

في المثال ده، لو عندك آلاف المنتجات جايين من الـ API، استخدام asSequence() بيمنع إنشاء List وسيطة بعد كل خطوة (filter, map, sortedBy)، وده بيقلل استهلاك الذاكرة بشكل ملحوظ خصوصًا في شاشات فيها Scroll مستمر.

📋

قائمة صغيرة + عملية واحدة

استخدم Collection العادية — الفرق في الأداء مش هيكون محسوس، والكود أبسط.

بيانات كبيرة + عمليات متسلسلة

🎯

محتاج أول نتيجة بس

Sequence مع first() أو find() بتوقف فورًا من غير ما تكمل باقي القائمة.

🧵

مصادر بيانات لا نهائية

استخدم generateSequence() لإنشاء تسلسلات كسولة غير محدودة.

⚠️

لا تستخدم Sequence لكل حاجة

مع القوائم الصغيرة، الـ overhead بتاع إنشاء الـ Sequence نفسه ممكن يخليها أبطأ.
