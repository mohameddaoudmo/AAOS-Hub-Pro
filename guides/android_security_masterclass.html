السياق التنظيمي والقانوني في أوروبا

تُعدّ ألمانيا ودول الاتحاد الأوروبي من أكثر البيئات التنظيمية صرامةً فيما يتعلق بحماية البيانات والأمن السيبراني. فعندما يطور فريق الهندسة في شركة N26 (أكبر بنك رقمي في أوروبا) أو BMW (التي تُدير تطبيقات Connected Drive لملايين السيارات) تطبيقاً لنظام أندرويد، فإنه لا يواجه فقط تحديات تقنية، بل يواجه متطلبات قانونية صارمة:

  • اللائحة العامة لحماية البيانات (GDPR): تفرض غرامات تصل إلى 4% من الإيرادات السنوية العالمية على الشركات التي تفشل في حماية بيانات المستخدمين.
  • قانون أمن الشبكات والمعلومات (NIS2): يُلزم الشركات العاملة في القطاعات الحيوية (المالية، الصحية، النقل) بتطبيق إجراءات أمنية صارمة.
  • معيار PSD2 للمدفوعات الإلكترونية: يُلزم تطبيقات Fintech بتطبيق مصادقة قوية للعملاء (SCA) وتشفير البيانات الحساسة.
  • معيار eIDAS: يُنظّم الهويات الإلكترونية والخدمات الثقة في السوق الأوروبي.
⚠️
تنبيه استراتيجيفي عام 2024، فرضت هيئة حماية البيانات الألمانية (BfDI) غرامة قياسية بقيمة 1.2 مليون يورو على شركة Fintech لتسريب بيانات مصرفية عبر ثغرة في تطبيق أندرويد لم يكن يستخدم EncryptedSharedPreferences بشكل صحيح. هذا يُبرز أن الأمن ليس خياراً تقنياً، بل التزام قانوني.

عزل التطبيقات (Application Sandbox): الحصن الدفاعي الأول

يُعدّ Application Sandbox الحجر الأساسي في بنية أمن أندرويد. لفهم أهميته، تخيّل أن كل تطبيق على جهازك يعيش في "سجن" افتراضي معزول، لا يستطيع التطبيق الأخر الوصول إلى بياناته إلا بموافقة صريحة من نظام التشغيل.

مثال واقعي: تخيّل أنك في مطار دولي كبير. كل مسافر (تطبيق) يحمل جواز سفر فريداً (Linux User ID). عند دخولك منطقة الجوازات (Zygote process)، يتم فحص جواز سفرك ومنحك غرفة فندقية (Sandbox) لا يمكن لأي مسافر آخر الدخول إليها. حتى موظفي الفندق (تطبيقات النظام) لا يستطيعون فتح خزانتك (data directory) إلا إذا منحتهم مفتاحاً صريحاً (Permission).

الآلية التقنية الداخلية للـ Sandbox

عند تثبيت تطبيق، ينشئ نظام أندرويد للتطبيق ما يلي:

  • Linux User ID فريد: يُنشأ معرّف مستخدم Linux فريد (UID) للتطبيق، عادةً يبدأ من 10000. لا يشارك تطبيقان UID نفسه إلا إذا كانا يحملان نفس توقيع الشهادة ويُصرّحان بذلك صراحةً.
  • Process Isolation: يُشغّل كل تطبيق في Process منفصل بذاكرة افتراضية خاصة به، مستخدماً آلية fork() من Zygote.
  • SELinux Policies: يُطبّق نظام SELinux سياسات إلزامية للتحكم في الوصول (MAC) لضمان أن التطبيق لا يتجاوز صلاحياته حتى لو تم اختراقه.
  • Filesystem Isolation: يتم حصر التطبيق في دليل /data/data/<package_name>/ الذي لا يمكن للتطبيقات الأخرى قراءته (Android 4.3+).
مثال: عرض معلومات UID و SELinux ContextShell
# عرض معلومات التطبيق و UID الخاص به
adb shell dumpsys package com.example.bankingapp | grep userId

# عرض SELinux Context للتطبيق
adb shell ps -Z | grep com.example.bankingapp
# الناتج المتوقع: u:r:untrusted_app:s0:c512,c768

# عرض صلاحيات الملفات في دليل التطبيق
adb shell ls -laZ /data/data/com.example.bankingapp/
# الناتج: drwx------ u0_a123 u0_a123 u:object_r:app_data_file:s0:c512,c768
ℹ️
فهم عميقيُعدّ SELinux Context (مثل u:r:untrusted_app:s0:c512,c768) بمثابة "بطاقة هوية" إضافية للتطبيق. الحقل c512,c768 يُمثّل فئة التصنيف (MCS Categories) التي تضمن عزل التطبيقات حتى لو شاركت نفس نوع SELinux. هذا يعني أنه حتى لو وجدث ثغرة في نوع untrusted_app، فإن SELinux يمنع التطبيق A من الوصول إلى ملفات التطبيق B.

لماذا تفشل Sandbox وحدها في حماية التطبيقات المصرفية؟

على الرغم من قوة Sandbox، إلا أنها ليست كافيةً وحدها للتطبيقات الحساسة. السبب:

  • Root Access: إذا حصل المهاجم على صلاحيات الروت (مثلاً عبر Magisk)، فإن Sandbox تصبح عديمة الجدوى لأن الروت يتجاوز جميع قيود Linux.
  • Backup Extraction: التطبيقات التي تسمح بنسخ احتياطي (android:allowBackup="true") يمكن استخراج بياناتها عبر adb backup.
  • Shared User ID: إذا استخدم التطبيق android:sharedUserId مع تطبيق آخر، فإنهما يشاركان نفس Sandbox.
  • Exported Components: المكونات المُصدّرة (Exported Components) تفتح "نوافذ" في جدران Sandbox يمكن استغلالها.

سؤال مقابلة من N26 (Berlin, 2024):
"كيف تضمن أن بيانات المستخدم المصرفية تبقى آمنة حتى على جهاز مُروت؟"

الإجابة المتوقعة: لا يمكن ضمان الأمن بنسبة 100% على جهاز مُروت، لكن يمكن تقليل المخاطر عبر: (1) تشفير البيانات بمفاتيح Hardware-backed Keystore لا يمكن استخراجها، (2) استخدام Play Integrity API للكشف عن بيئات غير موثوقة، (3) عدم تخزين بيانات حساسة محلياً إلا عند الضرورة، (4) ربط العمليات الحساسة بـ BiometricPrompt.

نظام Android Keystore: الخزنة الرقمية للمفاتيح

يُعدّ Android Keystore System الخدمة الأساسية التي تتيح للتطبيقات توليد مفاتيح تشفيرية وتخزينها في مواقع آمنة داخل الجهاز، بحيث لا يمكن للتطبيق نفسه استخراج المفتاح الخاص (Private Key) بعد توليده. يُشبه هذا آلية الخزنة في البنك: أنت تملك المفتاح، لكنك لا تستطيع أخذه معك — يمكنك فقط استخدامه داخل الخزنة.

مثال واقعي: تخيّل أنك تمتلك صندوق إيداع (Safe Deposit Box) في بنك سويسري. لديك مفتاح لفتح الصندوق، لكن البنك يملك آلية ثانية للتحقق من هويتك. لا يمكنك أخذ محتويات الصندوق خارج البنك دون إذن، والبنك يحتفظ بسجل كل عملية فتح. Android Keystore يعمل بنفس الطريقة: المفتاح يبقى داخل "الخزنة" (TEE أو StrongBox) ولا يمكن نسخه أو استخراجه.

البنية الداخلية: TEE مقابل StrongBox

النوعالوصفمستوى الأمانالتوافر
Software Keystoreتخزين المفاتيح في ذاكرة التطبيق المشفرة بمفتاح مُستخرج من بصمة الجهازمتوسطجميع الأجهزة
TEE (Trusted Execution Environment)بيئة تنفيذ موثوقة منفصلة عن نظام التشغيل الرئيسي (ARM TrustZone)عاليمعظم الأجهزة الحديثة
StrongBox Keymasterشريحة أمان منفصلة مادياً (HSM) مع ذاكرة تخزين ومُعالج خاصينعالي جداًAndroid 9+ (مطلوب من Android 12+)
ℹ️
فهم ARM TrustZoneيُقسّم ARM TrustZone المعالج إلى عالمين: Normal World (حيث يعمل أندرويد) و Secure World (حيث يعمل TEE). عندما يُنشئ التطبيق مفتاحاً في Keystore، يتم توليد المفتاح الفعلي داخل Secure World. حتى لو اخترق المهاجم نظام أندرويد بالكامل، فإن Secure World يبقى معزولاً. StrongBox يذهب أبعد من ذلك باستخدام شريحة HSM منفصلة مادياً عن المعالج الرئيسي.

توليد مفتاح AES في Keystore مع ربط المصادقة البيومترية

توليد مفتاح AES-256 مع User AuthenticationKotlin
import android.security.keystore.KeyGenParameterSpec
import android.security.keystore.KeyProperties
import java.security.KeyStore
import javax.crypto.KeyGenerator
import javax.crypto.SecretKey

object SecureKeyManager {

    private const val ANDROID_KEYSTORE = "AndroidKeyStore"
    private const val KEY_ALIAS = "banking_master_key"

    /**
     * توليد مفتاح AES-256 داخل Android Keystore
     * يتطلب المصادقة البيومترية قبل كل استخدام
     */
    fun generateBiometricBoundKey(): SecretKey {
        val keyStore = KeyStore.getInstance(ANDROID_KEYSTORE).apply { load(null) }

        // إذا كان المفتاح موجوداً، أعد استخدامه
        keyStore.getEntry(KEY_ALIAS, null)?.let {
            return (it as KeyStore.SecretKeyEntry).secretKey
        }

        val keyGenerator = KeyGenerator.getInstance(
            KeyProperties.KEY_ALGORITHM_AES,
            ANDROID_KEYSTORE
        )

        val keyGenParameterSpec = KeyGenParameterSpec.Builder(
            KEY_ALIAS,
            KeyProperties.PURPOSE_ENCRYPT or KeyProperties.PURPOSE_DECRYPT
        ).apply {
            // استخدام AES-GCM (أكثر أماناً من CBC)
            setBlockModes(KeyProperties.BLOCK_MODE_GCM)
            setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_NONE)

            // حجم المفتاح 256 بت
            setKeySize(256)

            // ربط المفتاح بالمصادقة البيومترية
            setUserAuthenticationRequired(true)
            setUserAuthenticationValidityDurationSeconds(-1) // -1 = كل مرة
            setInvalidatedByBiometricEnrollment(true)

            // استخدام StrongBox إن توفر
            if (android.os.Build.VERSION.SDK_INT >= android.os.Build.VERSION_CODES.P) {
                setIsStrongBoxBacked(true)
            }

            // التأكد من عدم إمكانية الاستخراج
            setRandomizedEncryptionRequired(true)
        }.build()

        keyGenerator.init(keyGenParameterSpec)
        return keyGenerator.generateKey()
    }

    fun getKey(): SecretKey? {
        val keyStore = KeyStore.getInstance(ANDROID_KEYSTORE).apply { load(null) }
        return (keyStore.getEntry(KEY_ALIAS, null) as? KeyStore.SecretKeyEntry)?.secretKey
    }

    fun deleteKey() {
        val keyStore = KeyStore.getInstance(ANDROID_KEYSTORE).apply { load(null) }
        keyStore.deleteEntry(KEY_ALIAS)
    }
}

نصيحة إنتاجية: دائماً استخدم setInvalidatedByBiometricEnrollment(true) لضمان أن المفاتيح تُبطل عند تسجيل بصمة جديدة. هذا يمنع هجوم "إضافة بصمة أثناء النوم" حيث يضيف المهاجم بصمته إلى الجهاز أثناء نوم المستخدم.

توليد زوج مفاتيح RSA للتوقيع الرقمي

توليد مفاتيح RSA-4096 للتوقيع الرقميKotlin
import android.security.keystore.KeyGenParameterSpec
import android.security.keystore.KeyProperties
import java.security.KeyPairGenerator
import java.security.KeyStore
import java.security.Signature

object RsaKeyManager {

    private const val ANDROID_KEYSTORE = "AndroidKeyStore"
    private const val SIGNATURE_ALIAS = "app_signature_key"

    fun generateRsaKeyPair() {
        val keyStore = KeyStore.getInstance(ANDROID_KEYSTORE).apply { load(null) }
        if (keyStore.containsAlias(SIGNATURE_ALIAS)) return

        val keyPairGenerator = KeyPairGenerator.getInstance(
            KeyProperties.KEY_ALGORITHM_RSA,
            ANDROID_KEYSTORE
        )

        val spec = KeyGenParameterSpec.Builder(
            SIGNATURE_ALIAS,
            KeyProperties.PURPOSE_SIGN or KeyProperties.PURPOSE_VERIFY
        ).apply {
            setKeySize(4096)
            setDigests(KeyProperties.DIGEST_SHA256, KeyProperties.DIGEST_SHA512)
            setSignaturePaddings(KeyProperties.SIGNATURE_PADDING_RSA_PKCS1)
            setUserAuthenticationRequired(true)
            setUserAuthenticationValidityDurationSeconds(300) // 5 دقائق
        }.build()

        keyPairGenerator.initialize(spec)
        keyPairGenerator.generateKeyPair()
    }

    fun signData(data: ByteArray): ByteArray? {
        val keyStore = KeyStore.getInstance(ANDROID_KEYSTORE).apply { load(null) }
        val entry = keyStore.getEntry(SIGNATURE_ALIAS, null) as? KeyStore.PrivateKeyEntry
            ?: return null
        return Signature.getInstance("SHA256withRSA").apply {
            initSign(entry.privateKey)
            update(data)
        }.sign()
    }
}

EncryptedSharedPreferences و EncryptedFile: التخزين الآمن بسهولة

تُعدّ EncryptedSharedPreferences و EncryptedFile من مكتبة AndroidX Security الحل الأمثل لتخزين البيانات الحساسة محلياً. بدلاً من حفظ البيانات كنص عادي (Plaintext) في ملفات XML، تقوم هذه المكتبة تلقائياً بتشفير المفاتيح والقيم باستخدام مفاتيح Keystore.

🚫
خطأ شائع قاتللا تستخدم SharedPreferences العادية (أو DataStore بدون تشفير) لتخزين: رموز JWT، كلمات مرور، أرقام بطاقات ائتمان، مفاتيح API، أو أي بيانات شخصية (PII). هذه البيانات تُحفظ كنص عادي في /data/data/<package>/shared_prefs/ ويمكن استخراجها عبر adb على الأجهزة المُروتة أو عبر نسخ احتياطي.

التكامل الكامل مع EncryptedSharedPreferences

إعداد EncryptedSharedPreferences مع KeystoreKotlin
import android.content.Context
import android.content.SharedPreferences
import androidx.security.crypto.EncryptedSharedPreferences
import androidx.security.crypto.MasterKey
import java.io.IOException
import java.security.GeneralSecurityException

class SecurePreferencesManager(context: Context) {

    companion object {
        private const val PREFS_FILE = "secure_banking_prefs"
        private const val KEY_AUTH_TOKEN = "auth_token"
        private const val KEY_REFRESH_TOKEN = "refresh_token"
        private const val KEY_USER_ID = "user_id"
        private const val KEY_LAST_LOGIN = "last_login_timestamp"
    }

    private val masterKey: MasterKey by lazy {
        MasterKey.Builder(context)
            .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
            .setUserAuthenticationRequired(false)
            .build()
    }

    private val encryptedPrefs: EncryptedSharedPreferences by lazy {
        try {
            EncryptedSharedPreferences.create(
                context,
                PREFS_FILE,
                masterKey,
                EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
                EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
            ) as EncryptedSharedPreferences
        } catch (e: GeneralSecurityException) {
            context.deleteSharedPreferences(PREFS_FILE)
            EncryptedSharedPreferences.create(
                context,
                PREFS_FILE,
                masterKey,
                EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
                EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
            ) as EncryptedSharedPreferences
        }
    }

    fun saveAuthToken(token: String) {
        encryptedPrefs.edit().putString(KEY_AUTH_TOKEN, token).apply()
    }

    fun getAuthToken(): String? = encryptedPrefs.getString(KEY_AUTH_TOKEN, null)

    fun saveRefreshToken(token: String) {
        encryptedPrefs.edit().putString(KEY_REFRESH_TOKEN, token).apply()
    }

    fun getRefreshToken(): String? = encryptedPrefs.getString(KEY_REFRESH_TOKEN, null)

    fun clearAll() {
        encryptedPrefs.edit().clear().apply()
    }

    fun hasStoredCredentials(): Boolean {
        return getAuthToken() != null && getRefreshToken() != null
    }
}
⚡
تحذير هام: Migration Strategyعند الترقية من SharedPreferences العادية إلى EncryptedSharedPreferences، لا تقم بنقل البيانات الحساسة الموجودة. بدلاً من ذلك: (1) اطلب من المستخدم تسجيل الدخول مرة أخرى، (2) احذف البيانات القديمة، (3) خزّن البيانات الجديدة في EncryptedSharedPreferences. نقل البيانات يعني فك تشفيرها ثم إعادة تشفيرها، وهذه الفترة الانتقالية قد تترك البيانات عرضة في الذاكرة.

تشفير الملفات باستخدام EncryptedFile

تخزين ملفات PDF حساسة بشكل مشفرKotlin
import android.content.Context
import androidx.security.crypto.EncryptedFile
import androidx.security.crypto.MasterKey
import java.io.ByteArrayOutputStream
import java.io.File
import java.nio.charset.StandardCharsets

class SecureFileManager(context: Context) {

    private val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .build()

    private val filesDir = context.filesDir

    fun writeEncryptedFile(fileName: String, content: ByteArray): Boolean {
        return try {
            val file = File(filesDir, fileName)
            if (file.exists()) file.delete()

            val encryptedFile = EncryptedFile.Builder(
                context,
                file,
                masterKey,
                EncryptedFile.FileEncryptionScheme.AES256_GCM_HKDF_4KB
            ).build()

            encryptedFile.openFileOutput().use { outputStream ->
                outputStream.write(content)
            }
            true
        } catch (e: Exception) {
            e.printStackTrace()
            false
        }
    }

    fun readEncryptedFile(fileName: String): ByteArray? {
        return try {
            val file = File(filesDir, fileName)
            if (!file.exists()) return null

                context,
                file,
                masterKey,
                EncryptedFile.FileEncryptionScheme.AES256_GCM_HKDF_4KB
            ).build()

            encryptedFile.openFileInput().use { inputStream ->
                ByteArrayOutputStream().use { outputStream ->
                    inputStream.copyTo(outputStream)
                    outputStream.toByteArray()
                }
            }
        } catch (e: Exception) {
            e.printStackTrace()
            null
        }
    }

SSL Pinning: تأمين الاتصال ضد هجمات Man-in-the-Middle

يعتمد نظام أندرويد على مخزن الشهادات (Certificate Store) للتحقق من صحة اتصالات TLS. لكن ماذا لو كان المهاجم قادراً على تثبيت شهادة CA خاصة به على الجهاز؟ في هذه الحالة، يمكنه اعتراض حركة المرور (MitM) دون أن يتنبّه التطبيق. SSL Pinning يحل هذه المشكلة عبر "تثبيت" شهادة الخادم أو مفتاحه العام داخل التطبيق، بحيث يرفض التطبيق أي شهادة أخرى حتى لو كانت موقعة من CA موثوق.

مثال واقعي: تخيّل أنك تعبر نقطة تفتيش حدودية. بدلاً من قبول أي جواز سفر صادر من أي دولة (CA)، يطلب ضابط الجوازات منك إظهار "ختم أمان" محدد مسبقاً على جواز سفرك. حتى لو كان الجواز مزوراً بشكل مثالي، فإن غياب الختم المحدد مسبقاً يُفشل المحاولة فوراً. SSL Pinning يعمل بنفس الطريقة: التطبيق يعرف الشهادة المتوقعة ويرفض أي شيء آخر.

    private const val BACKUP_PIN_1 = "sha256/BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB="

                        okhttp3.CipherSuite.TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384,
                        okhttp3.CipherSuite.TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256,
                        okhttp3.CipherSuite.TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256

                    addInterceptor(HttpLoggingInterceptor().apply {
                        level = HttpLoggingInterceptor.Level.BODY
                    })
                }
                addInterceptor(AuthInterceptor(context))
                retryOnConnectionFailure(true)
            }
            .build()

    class AuthInterceptor(private val context: Context) : okhttp3.Interceptor {
        override fun intercept(chain: okhttp3.Interceptor.Chain): okhttp3.Response {
            val originalRequest = chain.request()
            val token = SecurePreferencesManager(context).getAuthToken()
                ?: return chain.proceed(originalRequest)

            val newRequest = originalRequest.newBuilder()
                .header("Authorization", "Bearer $token")
                .header("X-Request-ID", java.util.UUID.randomUUID().toString())
                .header("X-Client-Version", BuildConfig.VERSION_NAME)
                .build()

            return chain.proceed(newRequest)
        }
    }

object PackageUtils {

    fun isPackageSignedWithOurCertificate(context: Context, packageName: String): Boolean {
        return try {
            val packageManager = context.packageManager
            val packageInfo = if (android.os.Build.VERSION.SDK_INT >= android.os.Build.VERSION_CODES.P) {
                packageManager.getPackageInfo(
                    packageName,
                    android.content.pm.PackageManager.GET_SIGNING_CERTIFICATES
                )
            } else {
                @Suppress("DEPRECATION")
                packageManager.getPackageInfo(packageName, android.content.pm.PackageManager.GET_SIGNATURES)
            }

            val signatures = if (android.os.Build.VERSION.SDK_INT >= android.os.Build.VERSION_CODES.P) {
                packageInfo.signingInfo?.apkContentsSigners
            } else {
                @Suppress("DEPRECATION")
                packageInfo.signatures
            }

            // مقارنة مع التوقيع المتوقع (hash)
            signatures?.any { sig ->
                val currentHash = hashSignature(sig.toByteArray())
                currentHash == EXPECTED_SIGNATURE_HASH
            } ?: false
        } catch (e: Exception) {
            false
        }
    }

    private fun hashSignature(signature: ByteArray): String {
        val digest = java.security.MessageDigest.getInstance("SHA-256")
        return android.util.Base64.encodeToString(digest.digest(signature), android.util.Base64.NO_WRAP)
    }

class RootDetectionEngine(private val context: Context) {

    enum class RootIndicator {
        TEST_KEYS,              // ro.build.tags = test-keys
        SUPERUSER_APK,          // تطبيق Superuser مثبت
        SU_BINARY,              // ملف /system/bin/su موجود
        MAGISK_FILES,           // ملفات Magisk مخفية
        BUSYBOX_INSTALLED,      // BusyBox مثبت
        RW_SYSTEM,              // /system قابل للكتابة
        DANGEROUS_PROPS,        // خصائص نظام مشبوهة
        MAGISK_APP,             // تطبيق Magisk مثبت
        HOOKING_FRAMEWORKS,     // Xposed أو Frida
        EMULATOR_DETECTED       // محاكي
    }

    data class RootCheckResult(
        val isRooted: Boolean,
        val detectedIndicators: List,
        val riskScore: Int // 0-100
    )

    fun performRootCheck(): RootCheckResult {
        val indicators = mutableListOf()

        // الطبقة 1: فحص Test Keys
        if (checkTestKeys()) indicators.add(RootIndicator.TEST_KEYS)

        // الطبقة 2: فحص SU Binary
        if (checkSuBinary()) indicators.add(RootIndicator.SU_BINARY)

        // الطبقة 3: فحص Magisk
        if (checkMagisk()) indicators.add(RootIndicator.MAGISK_FILES)

        // الطبقة 4: فحص BusyBox
        if (checkBusyBox()) indicators.add(RootIndicator.BUSYBOX_INSTALLED)

        // الطبقة 5: فحص خصائص النظام
        if (checkDangerousProps()) indicators.add(RootIndicator.DANGEROUS_PROPS)

        // الطبقة 6: فحص Hooking Frameworks
        if (checkHookingFrameworks()) indicators.add(RootIndicator.HOOKING_FRAMEWORKS)

        // حساب درجة الخطورة
        val riskScore = calculateRiskScore(indicators)
        val isRooted = riskScore >= 30 // عتبة التحذير

        return RootCheckResult(isRooted, indicators, riskScore)
    }

    private fun checkTestKeys(): Boolean {
        val buildTags = android.os.Build.TAGS
        return buildTags != null && buildTags.contains("test-keys")
    }

    private fun checkSuBinary(): Boolean {
        val paths = arrayOf(
            "/system/bin/su",
            "/system/xbin/su",
            "/sbin/su",
            "/su/bin/su",
            "/data/local/xbin/su",
            "/data/local/bin/su",

object SignatureVerifier {

    private const val EXPECTED_SIGNATURE = "YOUR_BASE64_SIGNATURE_HASH"

    fun verifyAppSignature(context: Context): Boolean {
        return try {
            val packageName = context.packageName
            val packageManager = context.packageManager

            val signatures = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P) {
                packageManager.getPackageInfo(
                    packageName,
                    PackageManager.GET_SIGNING_CERTIFICATES
                ).signingInfo?.apkContentsSigners
            } else {
                @Suppress("DEPRECATION")
                packageManager.getPackageInfo(
                    packageName,
                    PackageManager.GET_SIGNATURES
                ).signatures
            }

            signatures?.any { signature ->
                val currentHash = hashSignature(signature.toByteArray())
                currentHash == EXPECTED_SIGNATURE
            } ?: false
        } catch (e: Exception) {
            false
        }
    }

    private fun hashSignature(signature: ByteArray): String {
        val digest = MessageDigest.getInstance("SHA-256")
        return Base64.encodeToString(digest.digest(signature), Base64.NO_WRAP)
    }

    /**
     * التحقق من أن التطبيق غير مُعدّل (Tamper Detection)
     */
    fun verifyAppIntegrity(context: Context): Boolean {
        // التحقق من التوقيع
        if (!verifyAppSignature(context)) return false

        // التحقق من عدم التصحيح (Debug Mode)
        if (context.applicationInfo.flags and android.content.pm.ApplicationInfo.FLAG_DEBUGGABLE != 0) {
            return false
        }

        // التحقق من عدم التثبيت من متاجر غير موثوقة
        val installer = context.packageManager.getInstallerPackageName(context.packageName)
        val trustedInstallers = listOf("com.android.vending", "com.google.android.packageinstaller")
        if (installer != null && installer !in trustedInstallers) {
            // تحذير فقط، لا تمنع
        }

        return true
    }
}

BiometricPrompt: المصادقة البيومترية الاحترافية

يُعدّ BiometricPrompt الواجهة الرسمية والوحيدة الموصى بها للمصادقة البيومترية في أندرويد 9+ (API 28+). يجب ربط العمليات الحساسة (التحويلات المصرفية، تغيير كلمة المرور) بمفاتيح Keystore لا يمكن استخدامها إلا بعد نجاح المصادقة البيومترية.

مثال واقعي: تخيّل أنك في مصرف فاخر. لديك بطاقة دخول (Device Lock) وبصمة إصبع (Biometric). لكن الخزنة الكبرى (Keystore Key) لا تفتح إلا عندما تضع بطاقتك في القارئ وتضع إصبعك في نفس الوقت. BiometricPrompt هو ذلك القارئ: لا يُعيد بصمتك أبداً للتطبيق، بل يُخبر Keystore فقط بأن الهوية مُصدّق عليها.

class BiometricAuthManager(private val activity: FragmentActivity) {
    
    private val executor: Executor = ContextCompat.getMainExecutor(activity)
    
    fun authenticateForCriticalOperation(
        onSuccess: (BiometricPrompt.CryptoObject) -> Unit,
        onError: (String) -> Unit
    ) {
        val biometricManager = BiometricManager.from(activity)
        
        when (biometricManager.canAuthenticate(
            BiometricManager.Authenticators.BIOMETRIC_STRONG
        )) {
            BiometricManager.BIOMETRIC_SUCCESS -> {
                showBiometricPrompt(onSuccess, onError)
            }
            BiometricManager.BIOMETRIC_ERROR_NO_HARDWARE -> {
                onError("لا يوجد مستشعر بيومتري")
            }
            BiometricManager.BIOMETRIC_ERROR_HW_UNAVAILABLE -> {
                onError("المستشعر غير متوفر حالياً")
            }
            BiometricManager.BIOMETRIC_ERROR_NONE_ENROLLED -> {
                onError("لم يتم تسجيل بصمة")
            }
            else -> {
                onError("خطأ غير معروف")
            }
        }
    }
    
    private fun showBiometricPrompt(
        onSuccess: (BiometricPrompt.CryptoObject) -> Unit,
        onError: (String) -> Unit
    ) {
        val cipher = getInitializedCipherForEncryption()
        val cryptoObject = BiometricPrompt.CryptoObject(cipher)
        
        val promptInfo = BiometricPrompt.PromptInfo.Builder()
            .setTitle("تأكيد العملية الحساسة")
            .setSubtitle("يرجى المصادقة لإتمام التحويل المصرفي")
            .setDescription("سيتم خصم مبلغ 5,000 يورو من حسابك")
            .setNegativeButtonText("إلغاء")
            .setAllowedAuthenticators(
                BiometricManager.Authenticators.BIOMETRIC_STRONG
            )
            .build()
        
        val biometricPrompt = BiometricPrompt(
            activity,
            executor,
            object : BiometricPrompt.AuthenticationCallback() {
                override fun onAuthenticationSucceeded(
                    result: BiometricPrompt.AuthenticationResult
                ) {
                    result.cryptoObject?.cipher?.let {
                        onSuccess(result.cryptoObject!!)
                    } ?: onError("فشل في استرجاع Cipher")
                }
                
                override fun onAuthenticationError(errorCode: Int, errString: CharSequence) {
                    onError(errString.toString())
                }
                
                override fun onAuthenticationFailed() {
                    onError("فشلت المصادقة")
                }
            }
        )
        
        biometricPrompt.authenticate(promptInfo, cryptoObject)
    }
    
    private fun getInitializedCipherForEncryption(): Cipher {
        val key = SecureKeyManager.generateBiometricBoundKey()
        return Cipher.getInstance("AES/GCM/NoPadding").apply {
            init(Cipher.ENCRYPT_MODE, key)
        }
    }

import androidx.security.crypto.EncryptedSharedPreferences
import java.nio.ByteBuffer
import java.nio.CharBuffer

class SecureTokenManager(context: Context) {
    
    private val prefs = SecurePreferencesManager(context)
    
    /**
     * تخزين JWT كـ CharArray بدلاً من String لتجنب immutability
     */
    fun storeJwtSecurely(token: String) {
        // تحويل إلى CharArray لإمكانية المسح من الذاكرة
        val tokenChars = token.toCharArray()
        prefs.saveAuthToken(token) // مشفر في EncryptedSharedPreferences
        Arrays.fill(tokenChars, '\u0000') // مسح من الذاكرة
    }
    
    /**
     * استخدام JWT مع Callback لتجنب الاحتفاظ به في الذاكرة
     */
    fun  withToken(operation: (String) -> T): T? {
        val token = prefs.getAuthToken() ?: return null
        return try {
            operation(token)
        } finally {
            // لا يمكن مسح String (immutable)، لكن يمكننا
            // تشجيع GC على إعادة التدوير
            System.gc()
        }
    }
    
    /**
     * التحقق من صلاحية JWT محلياً (بدون فك Secret)
     */
    fun isTokenExpired(token: String): Boolean {
        return try {
            val parts = token.split(".")
            if (parts.size != 3) return true
            
            val payload = String(
                android.util.Base64.decode(parts[1], android.util.Base64.URL_SAFE),
                Charsets.UTF_8
            )
            val json = org.json.JSONObject(payload)
            val exp = json.getLong("exp")
            System.currentTimeMillis() / 1000 >= exp
        } catch (e: Exception) {
            true
        }
    }
}

Play Integrity API: التحقق من سلامة الجهاز والبيئة

Play Integrity API هو الخليفة الرسمي لـ SafetyNet، ويُوفّر تقييماً شاملاً لسلامة التطبيق والجهاز والحزمة. يجب إجراء هذا التحقق على الخادم وليس على العميل.

import com.google.android.gms.common.ConnectionResult
import com.google.android.gms.common.GoogleApiAvailability
import com.google.android.gms.tasks.Tasks
import com.google.android.play.core.integrity.IntegrityManagerFactory
import com.google.android.play.core.integrity.IntegrityTokenRequest
import java.security.MessageDigest
import java.util.UUID

class PlayIntegrityChecker(private val context: Context) {
    
    companion object {
        private const val CLOUD_PROJECT_NUMBER = "1234567890" // رقم مشروع Google Cloud
    }
    
    fun requestIntegrityToken(): String? {
        return try {
            val nonce = generateNonce()
            
            val integrityManager = IntegrityManagerFactory.create(context)
            val request = IntegrityTokenRequest.builder()
                .setNonce(nonce)
                .setCloudProjectNumber(CLOUD_PROJECT_NUMBER)
                .build()
            
            val response = Tasks.await(
                integrityManager.requestIntegrityToken(request),
                10, java.util.concurrent.TimeUnit.SECONDS
            )
            
            response.token() // أرسل هذا إلى الخادم للتحقق
        } catch (e: Exception) {
            null
        }
    }
    
    /**
     * توليد nonce عشوائي فريد لكل طلب
     */
    private fun generateNonce(): String {
        val randomBytes = ByteArray(32)
        java.security.SecureRandom().nextBytes(randomBytes)
        return MessageDigest.getInstance("SHA-256")
            .digest(randomBytes)
            .joinToString("") { "%02x".format(it) }
    }
}

  • Defense in Depth: لا تعتمد على طبقة دفاع واحدة. استخدم: (1) BiometricPrompt + Keystore Key، (2) Server-Side Transaction Signing، (3) Certificate Pinning، (4) Anti-Tampering.
  • Transaction Signing: كل عملية تحويل يجب أن تُوقّع رقمياً على الخادم باستخدام مفتاح خاص لا يترك HSM البنك. التطبيق يُرسل طلب موقّع، والخادم يتحقق من التوقيع.
  • Amount Binding: ربط المبلغ والمستلم بـ Cryptographic Nonce يُولّد على الخادم. أي تعديل على المبلغ يُبطل التوقيع.
  • Out-of-Band Confirmation: إرسال رمز TOTP أو Push Notification منفصل لتأكيد العمليات التي تتجاوز عتبة مالية.
نموذج توقيع المعاملة (Transaction Signing)Kotlin
data class TransactionRequest(
    val amount: BigDecimal,
    val currency: String,
    val recipientIban: String,
    val nonce: String,        // من الخادم
    val timestamp: Long,
    val deviceId: String
) {
    fun toSignableString(): String {
        return "$amount|$currency|$recipientIban|$nonce|$timestamp|$deviceId"
    }
}

class TransactionSigner(context: Context) {
    
    private val keystore = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }
    
    fun signTransaction(request: TransactionRequest): ByteArray? {
        val entry = keystore.getEntry("transaction_key", null) as? KeyStore.PrivateKeyEntry
            ?: return null
            
        return Signature.getInstance("SHA256withRSA").apply {
            initSign(entry.privateKey)
            update(request.toSignableString().toByteArray())
        }.sign()
    }
}
