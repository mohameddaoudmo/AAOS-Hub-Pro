أساسيات الصياغة ونظام الأنواع

Syntax Foundations & Type System

val مقابل var واستنتاج النوع

في Kotlin، يُفرّق بين المتغيرات القابلة للتعديل وغير القابلة للتعديل على مستوى الصياغة نفسها، بينما في Java يعتمد ذلك على الكلمة المفتاحية final التي يُغفلها المطوّرون كثيراً.

Java
// يجب كتابة final يدوياً
final String name = "Kotlin";
String version = "2.3";

// Type Inference غير موجود
Map<String, Integer> scores = 
    new HashMap<>();
Kotlin
// val = final (read-only reference)
val name: String = "Kotlin"
var version = "2.3"  // Type Inference تلقائي

// لا حاجة لتكرار النوع
val scores = mutableMapOf<String, Int>()
💡 نصيحة مهنية

اعتمد val كافتراضي في كل مكان ممكن. استخدم var فقط عندما يكون التغيير ضرورياً فعلياً. هذا النمط يُقلّل من الأخطاء المنطقية ويجعل الكود أكثر قابلية للتنبؤ.

نظام Null Safety — القضاء على NPE

تمثّل Null Safety أبرز نقلة نوعية في Kotlin. يفرّق المترجم بين الأنواع التي يمكن أن تكون null والأنواع التي لا يمكنها ذلك، مما يُلغي NullPointerException (NPE) في وقت الترجمة.

Nullable Types String? Safe Call ?. Elvis Operator ?: Safe Cast as? Non-null Assertion !!
Java
// كل شيء قابل للـ null
String name = null;

// فحص يدوي مطلوب
if (name != null) {
    System.out.println(name.length());
} else {
    System.out.println("Unknown");
}

// Ternary operator
String display = 
    (name != null) ? name : "Guest";
Kotlin
// النوع غير nullable افتراضياً
val name: String = "Kotlin"  // لا يمكن أن يكون null
val nullable: String? = null  // يمكن أن يكون null

// Safe Call + Elvis Operator
val length = nullable?.length ?: 0

// Safe Cast
val number = obj as? Int ?: 0

// Non-null assertion (تجنبه قدر الإمكان)
val risky = nullable!!  // يرمي NPE إن كان null
⚠️ تحذير: Non-null Assertion !!

يُعتبر استخدام !! رائحة كودية (Code Smell) في معظم الحالات. يُفضّل دائماً استخدام ?. أو ?: أو let للتعامل مع القيم القابلة للـ null.

Smart Casts — الاستنتاج الذكي للنوع

بعد فحص النوع باستخدام is، يُدرك المترجم تلقائياً أن المتغير أصبح من النوع المحدد، مما يُلغي الحاجة للـ Casting الصريح الذي يُرهق الكود في Java.

Java
if (obj instanceof String) {
    // Casting صريح مطلوب في كل مرة
    String str = ((String) obj);
    System.out.println(str.length());

    // إذا أردت استخدامه مرة أخرى
    String str2 = ((String) obj);
    process(str2);
}
Kotlin
if (obj is String) {
    // المترجم يعرف أن obj هو String هنا
    println(obj.length)

    // يمكن استخدامه مباشرة
    process(obj)  // String تلقائياً
}

// في العبارة المعاكسة أيضاً
if (obj !is String) return
println(obj.length)  // String مضمون
✅ ميزة Smart Casts

يعمل Smart Casts أيضاً مع العبارات المنطقية (&& و ||)، والحلقات while، والدوال التي تُرجع Nothing. المترجم يُحلّل تدفق البيانات (Control Flow Analysis) ليحدد متى يكون النوع آمناً.

Expressions مقابل Statements

في Kotlin، تعمل عبارات if و when و try-catch كـ Expressions تُرجع قيماً، مما يُلغي الحاجة لعامل Java الثلاثي ? : ويُبسّط المنطق الشرطي.

Java
// if هو statement فقط
String result;
if (score >= 60) {
    result = "Pass";
} else {
    result = "Fail";
}

// Ternary operator محدود
String status = 
    (age >= 18) ? "Adult" : "Minor";

// switch تقليدي
switch (day) {
    case "MON": result = 1; break;
    case "TUE": result = 2; break;
    default: result = 0;
}
Kotlin
// if هو expression يُرجع قيمة
val result = if (score >= 60) "Pass" else "Fail"

// when يُبدل switch بالكامل
val dayNumber = when (day) {
    "MON" -> 1
    "TUE" -> 2
    else -> 0
}

// try-catch كـ expression
val number = try {
    str.toInt()
} catch (e: NumberFormatException) {
    0
}
🔍 مقارنة when مع switch

عبارة when في Kotlin أقوى بكثير من switch في Java: تدعم نطاقات الأرقام (in 1..10)، أنواع متعددة (is String)، شروط منطقية (when { x > 0 -> ... })، ولا تحتاج إلى break لأنها لا تتسرب (No Fall-through).

Kotlin
import kotlin.jvm.Throws

@Throws(IOException::class)
fun readFromNetwork(url: String): String {
    // من Java: يجب معالجة IOException
    return URL(url).readText()
}

// عند استخدام @Throws مع عدة استثناءات
@Throws(IOException::class, IllegalArgumentException::class)
fun processData(input: String): ByteArray {
    if (input.isBlank()) throw IllegalArgumentException("Empty input")
    return input.toByteArray()
}

الدوال والبرمجة الوظيفية

Functions & Functional Paradigm

دوال وخصائص المستوى الأعلى (Top-Level)

في Kotlin، يمكن تعريف الدوال والخصائص مباشرة خارج الأصناف، مما يُلغي الحاجة لـ Utility Classes مثل StringUtils.java أو Collections.java.

Java
// Utility Class مطلوب
public final class StringUtils {
    private StringUtils() {}  // منع الإنشاء

    public static String capitalize(String s) {
        return s.substring(0, 1).toUpperCase() 
            + s.substring(1);
    }
}

// الاستخدام
String result = StringUtils.capitalize("hello");
Kotlin
// دالة مباشرة في الملف
fun capitalize(s: String): String =
    s.replaceFirstChar { it.uppercase() }

// خاصية على المستوى الأعلى
val PI = 3.14159

// الاستخدام — لا حاجة لاسم الصنف
val result = capitalize("hello")
val radius = 2 * PI

الوسائط الافتراضية والمُسماة

تُلغي Default Arguments و Named Arguments في Kotlin الحاجة لكتابة دوال مُحمّلة (Overloads) متعددة في Java، مما يُقلّل Boilerplate بشكل كبير.

Java
// Overloads متعددة مطلوبة
public void connect(String host) {
    connect(host, 8080, 5000);
}

public void connect(String host, int port) {
    connect(host, port, 5000);
}

public void connect(String host, int port, int timeout) {
    // ...
}

// الاستخدام
connect("api.example.com", 443, 10000);
// أي قيمة لـ timeout؟ يجب تذكر الترتيب!
Kotlin
// دالة واحدة فقط
fun connect(
    host: String,
    port: Int = 8080,
    timeout: Int = 5000
) {
    // ...
}

// الاستخدام المرن
connect("api.example.com")                    // port=8080, timeout=5000
connect("api.example.com", 443)              // timeout=5000
connect("api.example.com", timeout = 10000)  // port=8080
connect(port = 443, host = "api.example.com") // أي ترتيب!

دوال الامتداد (Extension Functions)

تُمكّن Extension Functions من إضافة دوال وخصائص لأي صنف (حتى الأصناف النهائية أو من SDK) دون وراثة أو تعديل الكود المصدري. هذا يُحسّن قابلية القراءة ويُبني DSLs قوية.

Java
// لا يمكن إضافة دوال لـ String
// يجب استخدام Utility Class
public class StringExtensions {
    public static String addExclamation(String s) {
        return s + "!";
    }
}

// الاستخدام غير طبيعي
String excited = StringExtensions.addExclamation("Hello");
Kotlin
// إضافة دالة لـ String مباشرة
fun String.addExclamation(): String = this + "!"

// خاصية امتداد
val String.wordCount: Int
    get() = this.split(" ").size

// الاستخدام الطبيعي
val excited = "Hello".addExclamation()
val count = "Hello World".wordCount  // 2
🔍 ملاحظة تقنية

Extension Functions لا تُعدّل الصنف الأصلي فعلياً. يتم تجميعها (Compile) كدوال static تأخذ المستقبل (Receiver) كمعامل أول. هذا يعني أنها لا تُمكنك من الوصول لأعضاء private أو protected في الصنف المُمتد.

دوال الرتبة العليا والـ Lambdas

في Kotlin، الدوال هي First-Class Citizens. يمكن تمريرها كمعاملات، تخزينها في متغيرات، وإرجاعها من دوال أخرى. يدعم Kotlin أيضاً Trailing Lambda Syntax و it الضمني.

Kotlin
// دالة ترتبة عليا
fun operateOnNumbers(
    a: Int,
    b: Int,
    operation: (Int, Int) -> Int
): Int = operation(a, b)

// Trailing Lambda — صياغة أنيقة
val sum = operateOnNumbers(5, 3) { x, y ->
    x + y
}

// it الضمني لمعامل واحد
val doubled = list.map { it * 2 }

// تخزين دالة في متغير
val multiply: (Int, Int) -> Int = { a, b -> a * b }

// إرجاع دالة من دالة
fun multiplierOf(factor: Int): (Int) -> Int =
    { number -> number * factor }

دوال Inline و Reified Types

تُستخدم inline لتجنب تكلفة إنشاء كائنات Lambda في وقت التشغيل. مع reified، يمكن الوصول إلى معلومات Generics في وقت التشغيل — شيء مستحيل في Java بسبب Type Erasure.

Java
// Type Erasure — لا يمكن معرفة T في Runtime
public  T findFirst(List list, 
    Class clazz) {
    for (Object item : list) {
        if (clazz.isInstance(item)) {
            return clazz.cast(item);
        }
    }
    return null;
}

// الاستخدام — يجب تمرير Class
String first = findFirst(list, String.class);
Kotlin
// reified يحفظ معلومات النوع
inline fun  List.findFirst(): T? {
    return this.filterIsInstance().firstOrNull()
}

// الاستخدام — لا حاجة لتمرير Class
val firstString = list.findFirst()

// inline مع crossinline و noinline
inline fun measureTime(
    crossinline block: () -> Unit
) {
    val start = System.currentTimeMillis()
    block()
    println("Time: ${System.currentTimeMillis() - start}ms")
}
⚠️ تحذير: inline

لا تُفرط في استخدام inline. يُناسب الدوال الصغيرة التي تستقبل Lambdas. الدوال الكبيرة المُعلّمة بـ inline تُسبب تضخماً في حجم الكود (Code Bloat). استخدم noinline للمعاملات التي لا تريد inline لها.

دوال Infix وتحميل المعاملات

تُمكّن Infix Functions من كتابة كود يقرأ مثل اللغة الطبيعية. يدعم Kotlin أيضاً Operator Overloading لتخصيص سلوك المعاملات القياسية.

Kotlin
// Infix Function
infix fun Int.times(str: String) = str.repeat(this)
val repeated = 3 times "Hello "  // "Hello Hello Hello "

// Operator Overloading
data class Point(val x: Int, val y: Int) {
    operator fun plus(other: Point) = 
        Point(x + other.x, y + other.y)

    operator fun get(index: Int): Int = when (index) {
        0 -> x
        1 -> y
        else -> throw IndexOutOfBoundsException()
    }
}

// الاستخدام
val p1 = Point(1, 2)
val p2 = Point(3, 4)
val p3 = p1 + p2        // Point(4, 6)
val xCoord = p3[0]     // 4

OOP Redefined

البناء والخصائص (Constructors & Properties)

تُدمج Kotlin البناء الرئيسي (Primary Constructor) مع تعريف الخصائص في سطر واحد. يتم توليد getters و setters ضمنياً، مع إمكانية تخصيصها عبر field.

Java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
}
Kotlin
// Primary Constructor + Properties في سطر واحد
class Person(
    var name: String,
    val age: Int  // val = getter فقط (read-only)
)

// init block للتحقق
class User(val email: String) {
    init {
        require(email.contains("@")) { "Invalid email" }
    }
}

// Custom getter/setter مع backing field
class Employee(var salary: Double) {
    var bonus: Double = 0.0
        set(value) {
            require(value >= 0) { "Bonus must be positive" }
            field = value  // field = backing field
        }
        get() = field * 1.1  // getter مخصص
}

أصناف البيانات (Data Classes)

تُولّد data class تلقائياً equals() و hashCode() و toString() و copy() و componentN() للـ Destructuring Declarations. هذا يُلغي مئات الأسطر من Boilerplate في Java.

Java
public class User {
    private final String id;
    private final String name;
    
    public User(String id, String name) {
        this.id = id; this.name = name;
    }
    
    // equals, hashCode, toString, getters
    // copy method يدوي
    // ... مئات الأسطر
}
Kotlin
// سطر واحد يُولّد كل شيء
data class User(val id: String, val name: String)

// copy() مع named arguments
val updated = user.copy(name = "New Name")

// Destructuring
val (id, name) = user

// toString() تلقائي
println(user)  // User(id=1, name=Ahmed)

// equals() و hashCode() مُولّدان تلقائياً
val same = user == User("1", "Ahmed")  // true

الأصناف المختومة (Sealed Classes & Interfaces)

تُقيّد Sealed Classes و Sealed Interfaces التسلسل الهرمي للأصناف، مما يُمكّن المترجم من التحقق من Exhaustiveness في when — أي أنك مضطر لمعالجة كل الحالات الممكنة.

Kotlin
// Sealed Class — لا يمكن توسيعها إلا في نفس الوحدة
sealed class Result<T> {
    data class Success<T>(val data: T) : Result<T>()
    data class Error(val message: String) : Result<Nothing>()
    object Loading : Result<Nothing>()
}

// Exhaustive when — المترجم يتحقق من كل الحالات
fun <T> handleResult(result: Result<T>) = when (result) {
    is Result.Success -> println("Data: ${result.data}")
    is Result.Error -> println("Error: ${result.message}")
    Result.Loading -> println("Loading...")
}  // لا حاجة لـ else — كل الحالات مُغطاة!

// Sealed Interface (Kotlin 1.5+)
sealed interface UiState {
    object Idle : UiState
    object Loading : UiState
    data class Success<T>(val data: T) : UiState
}
✅ فائدة Sealed Classes

عند إضافة حالة جديدة لـ sealed class، سيُنبّهك المترجم بجميع أماكن when التي لم تُعالج الحالة الجديدة. هذا يُمنع أخطاء وقت التشغيل ويُحسّن صيانة الكود بشكل جذري.

Object Declarations & Companion Objects

يُوفّر object نمط Singleton مُدمج في اللغة. companion object يُبدل الأعضاء static في Java بطريقة أكثر مرونة وموضوعية (OOP-oriented).

Java
// Singleton يدوي
public class Database {
    private static final Database INSTANCE = 
        new Database();
    
    private Database() {}
    
    public static Database getInstance() {
        return INSTANCE;
    }
}

// static members
public class Config {
    public static final String API_URL = "...";
}
Kotlin
// Singleton مُدمج
object Database {
    fun connect() { /* ... */ }
}

// الاستخدام
Database.connect()

// Companion Object
class User(val name: String) {
    companion object {
        const val MAX_NAME_LENGTH = 50
        
        fun createGuest() = User("Guest")
    }
}

// الاستخدام
val guest = User.createGuest()
val maxLen = User.MAX_NAME_LENGTH
🔍 الفرق بين object و companion object

object يُنشئ Singleton واحداً لكل التطبيق. companion object مرتبط بصنف معين (Class-level) ويمكنه الوصول لأعضاء private في الصنف. يمكن تسمية companion object وتطبيق Interfaces عليه.

نمط التفويض (Delegation Pattern)

يدعم Kotlin Class Delegation و Property Delegation بصياغة أنيقة عبر الكلمة by. هذا يُبسّط نمط Decorator ويُلغي Boilerplate كبير.

Kotlin
// Class Delegation
interface Repository {
    fun getData(): String
}

// Decorator بدون Boilerplate
class LoggingRepository(
    private val delegate: Repository
) : Repository by delegate {
    // override فقط ما تريد تخصيصه
    override fun getData(): String {
        println("Fetching data...")
        return delegate.getData()
    }
}

// Property Delegation — by lazy
val heavyObject: ExpensiveService by lazy {
    println("Initializing...")
    ExpensiveService()
}

// Delegates.observable
var name: String by Delegates.observable("") { _, old, new ->
    println("Name changed from $old to $new")
}

// Custom Delegate
class TrimDelegate : ReadWriteProperty<Any?, String> {
    private var value = ""
    override fun getValue(thisRef: Any?, property: KProperty<*>) = value
    override fun setValue(thisRef: Any?, property: KProperty<*>, newValue: String) {
        value = newValue.trim()
    }
}

var username: String by TrimDelegate()

أصناف القيمة (Value / Inline Classes)

تُوفّر Value Classes (سابقاً Inline Classes) نوعاً جديداً يلتف حول قيمة واحدة دون أي تكلفة وقت تشغيل (Zero-cost Abstraction). يتم تجميعها كالنوع الأساسي في JVM.

Kotlin
// Zero-cost wrapper للـ UserId
@JvmInline
value class UserId(val value: Long)

@JvmInline
value class Email(val address: String) {
    init {
        require('@' in address) { "Invalid email" }
    }
    
    val domain: String
        get() = address.substringAfter('@')
}

// الاستخدام — لا Boxting في وقت التشغيل
fun getUser(id: UserId): User { /* ... */ }
val user = getUser(UserId(123))  // يُمرّر كـ Long في JVM

// Type Safety دون تكلفة
fun sendEmail(to: Email, from: Email) { /* ... */ }
// لا يمكن الخلط بين Email و String عادي
✅ فائدة Value Classes

قبل Value Classes، كان المطوّرون يستخدمون typealias (بدون Type Safety) أو Wrapper Classes (مع تكلفة Boxing). Value Classes تجمع الأفضل من العالمين: Type Safety كامل مع أداء النوع الأساسي.

المجموعات ودوال النطاق

Collections & Scope Functions

المجموعات غير القابلة للتعديل (Immutable Collections)

في Kotlin، تكون المجموعات افتراضياً غير قابلة للتعديل (Read-only). يجب استخدام MutableList و MutableMap صريحاً للحصول على مجموعات قابلة للتعديل. هذا يُحسّن Thread Safety ويُقلّل الأخطاء.

Java
// كل المجموعات قابلة للتعديل افتراضياً
List<String> list = new ArrayList<>();
list.add("A");  // مسموح دائماً

// Collections.unmodifiableList يُرجع wrapper فقط
List<String> readonly = 
    Collections.unmodifiableList(list);
// readonly.add("B") // يرمي UnsupportedOperationException
Kotlin
// List غير قابل للتعديل افتراضياً
val list = listOf("A", "B")  // List<String>
// list.add("C") // خطأ في الترجمة!

// MutableList صريح
val mutable = mutableListOf("A", "B")
mutable.add("C")  // مسموح

// Map و Set أيضاً
val map = mapOf(1 to "One", 2 to "Two")
val mutableMap = mutableMapOf<Int, String>()

دوال النطاق (Scope Functions)

تُوفّر Kotlin خمس دوال نطاق (let، run، apply، also، with) لتنظيم الكود وتجنب المتغيرات المؤقتة. يختلفون في: كائن السياق (it مقابل this) والقيمة المُرجعة.

الدالة كائن السياق القيمة المُرجعة الاستخدام الأمثل
let it نتيجة Lambda تنفيذ كود على nullable، تحويل النوع
run this نتيجة Lambda تهيئة كائن + حساب قيمة
apply this الكائن نفسه تهيئة الكائن (Builder-style)
also it الكائن نفسه تسجيل أو side effects بدون تعديل
with this نتيجة Lambda تجميع عمليات على نفس الكائن
Kotlin
// let — مع nullable وتحويل النوع
val length = name?.let { 
    it.length  // it = name (non-null)
} ?: 0

// apply — تهيئة Builder-style
val user = User("").apply {
    name = "Ahmed"   // this = User
    age = 30
}

// also — side effect بدون تعديل
val numbers = mutableListOf(1, 2, 3).also {
    println("Created list with ${it.size} elements")
}

// run — تهيئة + حساب
val result = service.run {
    connect()       // this = service
    fetchData()     // يرجع نتيجة Lambda
}

// with — تجميع العمليات
val description = with(user) {
    "$name is $age years old"  // this = user
}

Sequences مقابل Java Streams

تُوفّر Sequences في Kotlin تقييماً كسولاً (Lazy Evaluation) مشابهاً لـ Java Streams، لكنها أكثر كفاءة لأنها تتجنب إنشاء مجموعات وسيطة (Intermediate Collections).

Java
// Stream API — متاح من Java 8
List<Integer> result = numbers.stream()
    .filter(n -> n % 2 == 0)
    .map(n -> n * 2)
    .limit(10)
    .collect(Collectors.toList());

// لا يمكن إعادة استخدام Stream
// stream.iterator() يُستهلك مرة واحدة
Kotlin
// Sequence — كسول وقابل لإعادة الاستخدام
val result = numbers.asSequence()
    .filter { it % 2 == 0 }
    .map { it * 2 }
    .take(10)
    .toList()

// الفرق: لا يُنشأ List وسيط!
// filter ثم map على كل عنصر قبل الانتقال للتالي

// generateSequence لأعداد لانهائية
val fibonacci = generateSequence(0 to 1) { 
    it.second to it.first + it.second 
}.map { it.first }
💡 متى تستخدم Sequence؟

استخدم Sequence عندما يكون لديك سلسلة طويلة من العمليات (filter, map, flatMap) على مجموعات كبيرة. إذا كانت المجموعة صغيرة (< 1000 عنصر)، فإن List العادية قد تكون أسرع بسبب overhead إنشاء Sequence.

Modern Kotlin Syntax Features

Guard Conditions في when

تُمكّن Kotlin 2.2 من إرفاق شروط if مباشرة بفروع when، مما يُقلّل التداخل ويجعل المنطق الشرطي أكثر وضوحاً.

Kotlin 2.2+
// قبل Kotlin 2.2 — تداخل مُزعج
when (val response = fetchData()) {
    is Result.Success -> {
        if (response.data.isNotEmpty()) {
            process(response.data)
        } else {
            showEmpty()
        }
    }
    is Result.Error -> showError()
}

// Kotlin 2.2 — Guard Conditions مباشرة
when (val response = fetchData()) {
    is Result.Success if response.data.isNotEmpty() 
        -> process(response.data)
    is Result.Success 
        -> showEmpty()
    is Result.Error 
        -> showError()
}

Explicit Backing Fields

تُمكّن Kotlin 2.2 من تعريف Backing Fields صريحة للخصائص بصياغة نظيفة، مما يُسهّل فصل الواجهة العامة عن التخزين الداخلي.

Kotlin 2.2+
// Kotlin 2.2 — Explicit Backing Field
class DataContainer<T> {
    val items: List<T>
        field = mutableListOf()  // field صريح
    
    fun add(item: T) {
        field.add(item)  // الوصول المباشر للـ field
    }
}

// مقارنة مع الطريقة القديمة
class OldContainer<T> {
    private val _items = mutableListOf<T>()  // naming convention
    val items: List<T> get() = _items
}

Multi-dollar String Interpolation

تُعالج Kotlin 2.3 مشكلة استخدام $ في القوالب النصية وDSLs عبر صياغة $$"..." التي تُعامل $ كحرف عادي افتراضياً.

Kotlin 2.3+
// المشكلة: $ يتطلب escaping دائماً
val price = "The price is ${'$'}50"  // مُزعج

// Kotlin 2.3 — Multi-dollar String
val query = $$"
    SELECT * FROM users 
    WHERE name = ${userName}
    AND price > $minPrice
"
// $minPrice يُعامل كحرف عادي!
// ${userName} فقط يُفسّر كـ interpolation

Non-local break و continue

تُمكّن Kotlin 2.3 من استخدام break و continue غير المحلي (Non-local) داخل Lambdas المُعلّمة بـ inline، مما يُحسّن التحكم في التكرار.

Kotlin 2.3+
// Non-local break في inline lambda
fun processList(items: List<Int>) {
    items.forEach { item ->
        if (item < 0) {
            break  // يُخرج من processList بالكامل!
        }
        println(item)
    }
}

// Non-local continue
items.forEach { item ->
    if (item == 0) {
        continue  // يتخطى العنصر ويستمر في forEach
    }
    process(item)
}

// يعمل فقط مع inline functions
// لا يعمل مع lambdas عادية (تتطلب @ label)
