01 · المفهوم

إيه هو الـ Pagination وليه نحتاجه؟

لما يكون عندك بيانات كتير جدًا، تحميلها كلها مرة واحدة بيبطّئ التطبيق ويستهلك الموارد. الحل: نجيب البيانات على دفعات صغيرة، ونكمل تحميل الباقي كل ما المستخدم يعمل Scroll.

🔴 بدون Pagination

  • تحميل كل البيانات دفعة واحدة من السيرفر
  • استهلاك عالي جدًا للـ RAM والشبكة
  • وقت انتظار طويل قبل ظهور أول عنصر
  • تجربة مستخدم بطيئة مع القوائم الكبيرة

🟢 مع Paging 3

  • تحميل تدريجي بحجم صفحة محدد
  • استهلاك أقل، وأداء أسرع وأكثر استقرارًا
  • عرض فوري لأول دفعة من البيانات
  • تجربة Infinite Scroll سلسة واحترافية

2

إنشاء الـ PagingSource

المسؤول عن جلب صفحة واحدة في كل استدعاء.

UserPagingSource.kt
class UserPagingSource(
    private val apiService: ApiService
) : PagingSource<Int, User>() {

    override suspend fun load(params: LoadParams<Int>): LoadResult<Int, User> {
        return try {
            val currentPage = params.key ?: 1

            val response = apiService.getUsers(
                page = currentPage,
                pageSize = params.loadSize
            )

            LoadResult.Page(
                data = response.users,
                prevKey = if (currentPage == 1) null else currentPage - 1,
                nextKey = if (response.users.isEmpty()) null else currentPage + 1
            )
        } catch (e: Exception) {
            LoadResult.Error(e)
        }
    }

    override fun getRefreshKey(state: PagingState<Int, User>): Int? {
        return state.anchorPosition?.let { anchorPosition ->
            val anchorPage = state.closestPageToPosition(anchorPosition)
            anchorPage?.prevKey?.plus(1) ?: anchorPage?.nextKey?.minus(1)
        }
    }
}
3

الـ Repository

إعداد الـ Pager بحجم الصفحة والـ Prefetch.

UserRepository.kt
class UserRepository(private val apiService: ApiService) {

    fun getUsers(): Flow<PagingData<User>> {
        return Pager(
            config = PagingConfig(
                pageSize = 20,
                enablePlaceholders = false,
                prefetchDistance = 5
            ),
            pagingSourceFactory = { UserPagingSource(apiService) }
        ).flow
    }
}
4

الـ ViewModel

تحويل البيانات لـ Flow وحفظها من إعادة التحميل عند تدوير الشاشة.

UserViewModel.kt
class UserViewModel(private val repository: UserRepository) : ViewModel() {

    val usersFlow: Flow<PagingData<User>> = repository.getUsers()
        .cachedIn(viewModelScope)
}
5

الـ Adapter

عرض البيانات في RecyclerView باستخدام PagingDataAdapter.

UserAdapter.kt
class UserAdapter : PagingDataAdapter<User, UserAdapter.UserViewHolder>(USER_COMPARATOR) {

    class UserViewHolder(val binding: ItemUserBinding) : RecyclerView.ViewHolder(binding.root)

    override fun onBindViewHolder(holder: UserViewHolder, position: Int) {
        val user = getItem(position)
        user?.let {
            holder.binding.tvName.text = it.name
            holder.binding.tvEmail.text = it.email
        }
    }

    companion object {
        private val USER_COMPARATOR = object : DiffUtil.ItemCallback<User>() {
            override fun areItemsTheSame(oldItem: User, newItem: User) = oldItem.id == newItem.id
            override fun areContentsTheSame(oldItem: User, newItem: User) = oldItem == newItem
        }
    }
}

04 · Jetpack Compose

نفس المثال بأسلوب Compose

باستخدام collectAsLazyPagingItems() جوه LazyColumn — بشكل تصريحي وأقل كود.

UserListScreen.kt
@Composable
fun UserListScreen(viewModel: UserViewModel) {
    val users = viewModel.usersFlow.collectAsLazyPagingItems()

    LazyColumn {
        items(
            count = users.itemCount,
            key = users.itemKey { it.id }
        ) { index ->
            users[index]?.let { UserItem(user = it) }
        }

        when {
            users.loadState.append is LoadState.Loading -> {
                item { CircularProgressIndicator() }
            }
            users.loadState.append is LoadState.Error -> {
                item { Text("حدث خطأ أثناء تحميل المزيد") }
            }
        }
    }
}
05 · إدارة الحالة

حالات التحميل (Loading States)

مكتبة Paging 3 بتوفّر حالات جاهزة تقدر تربطها بالـ UI مباشرة، وبتنطبق على 3 مواضع: أول تحميل، تحميل تحت، وتحميل فوق.

الحالةالوصفمكانها في القائمة
Loadingالبيانات قيد التحميل حاليًاrefresh / append / prepend
Errorحصل خطأ أثناء الجلب (شبكة، سيرفر...)refresh / append / prepend
NotLoadingالتحميل انتهى بنجاحrefresh / append / prepend
06 · أفضل الممارسات

نصائح لتطبيق احترافي

♻️

استخدم cachedIn دايمًا

حطها في الـ ViewModel علشان البيانات متتحملش من جديد عند تدوير الشاشة.

📏

اختر pageSize بعناية

مش صغير جدًا (طلبات كتيرة) ولا كبير جدًا (استهلاك ذاكرة زايد).

🗄️

استخدم RemoteMediator

لدمج قاعدة بيانات محلية (Room) مع بيانات السيرفر في تجربة Offline-first.

🔁

اختبر حالات الفشل

جرّب قطع النت وأضف زرار "إعادة المحاولة" بشكل واضح للمستخدم.

⚡

استخدم DiffUtil

لتحديث القائمة بكفاءة بدون إعادة رسم كامل للعناصر.
