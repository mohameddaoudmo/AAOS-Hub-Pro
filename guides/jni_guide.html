بنية JNI وقواعد التعامل مع JNIEnv*

١.١ الفصل المعماري بين الكومة المُدارة وغير المُدارة

يُقسّم نظام Android الذاكرة إلى نطاقين منفصلين: الكومة المُدارة (Managed Heap) التي يشرف عليها مُجمّع البيانات المُهملة (Garbage Collector) داخل JVM/ART، والكومة الأصلية غير المُدارة (Unmanaged Native Heap) التي تخضع لإدارة المُبرمج يدوياً في C++.

Kotlin/Java Layer
Managed Heap (GC-Controlled)
↑ ↓
JNI Bridge Layer
JNIEnv* / jmethodID / jfieldID
↑ ↓
C/C++ Native Layer
Unmanaged Heap (malloc/free/new/delete)
💡 مبدأ أساسي

كل كائن Java يمر عبر JNI يحمل مرجعاً (Reference). إذا لم يُحرّر هذا المرجع صراحةً في الكود الأصلي، سيؤدي إلى تسريب ذاكرة (Memory Leak) حتى داخل الكومة المُدارة.

١.٢ طبيعة JNIEnv* كمؤشر جدول محلي للخيط

يمثل JNIEnv* واجهة الدالة للتفاعل مع JVM. يُعدّ هذا المؤشر خاصاً بالخيط (Thread-Local) ولا يجوز مشاركته عبر خيوط متعددة. كل خيط يلتصق (Attach) بـ JVM يحصل على نسخته الخاصة من JNIEnv*. 

// ❌ خطأ جسيم: مشاركة JNIEnv* بين الخيوط
JNIEnv* sharedEnv;  // لا تفعل هذا أبداً!

// ✅ الصحيح: كل خيط يحصل على بيئته الخاصة
JavaVM* g_vm = nullptr;

void* native_thread_worker(void* arg) {
    JNIEnv* env = nullptr;
    jint attachResult = g_vm->AttachCurrentThread(&env, nullptr);

    if (attachResult == JNI_OK && env != nullptr) {
        // تنفيذ العمليات عبر JNIEnv* المحلية
        doWork(env);

        // فصل الخيط عند الانتهاء إلزامي
        g_vm->DetachCurrentThread();
    }
    return nullptr;
}
⚠️ تحذير حاسم

إذا نسيت استدعاء DetachCurrentThread() عند انتهاء الخيط الأصلي، سيظل الخيط مُلتصقاً بـ JVM إلى أجل غير مسمى، مما يُسبب تسريباً في موارد الخيوط (Thread Leak).

١.٣ التسجيل الديناميكي مقابل الثابت (JNI_OnLoad)

يعتمد التسجيل الثابت على تسمية الدوال باتباع قاعدة Java_package_ClassName_methodName، وهو عُرضة لمشاكل تسمية C++ (Name Mangling). أما التسجيل الديناميكي عبر JNI_OnLoad فيُحسّن أداء البدء ويُلغي الاعتماد على الأسماء الطويلة.

٢
إدارة الذاكرة والوقاية من التسريبات

٢.١ أنواع المراجع في JNI

نوع المرجع النطاق (Scope) الدورة الحياتية الاستخدام الأمثل
Local Reference خيط واحد / إطار دالة واحد تُحرّر تلقائياً عند العودة من الدالة الأصلية الكائنات المؤقتة داخل نطاق الدالة
Global Reference عمومي عبر جميع الخيوط تستمر حتى DeleteGlobalRef() صراحةً تخزين كائن Java بين استدعاءات الدوال الأصلية
Weak Global Reference عمومي (غير مُحصّن من GC) قد تُجمعها GC في أي وقت الإشارات الطويلة الأمد مع السماح بجمع البيانات المُهملة

٢.٢ تجاوز جدول المراجع المحلية (الحد ٥١٢)

يحمل كل إطار دالة JNI جدولاً للمراجع المحلية بسعة افتراضية تبلغ ٥١٢ مرجعاً. عند تجاوز هذا الحد داخل حلقة تكرارية (مثلاً معالجة قائمة كبيرة)، سيُطلق JVM استثناء FatalError. 

// ❌ خطير: تسريب ذاكرة + خطر تجاوز الحد ٥١٢
for (int i = 0; i < 1000; ++i) {
    jstring str = (jstring)env->GetObjectArrayElement(stringArray, i);
    // str يُستهلك هنا لكن لا يُحذف!
}  // سيُنهار عند i ≈ 512

// ✅ الصحيح: حذف المرجع المحلي فوراً بعد الاستخدام
for (int i = 0; i < 1000; ++i) {
    jstring str = (jstring)env->GetObjectArrayElement(stringArray, i);
    // ... معالجة النص ...
    env->DeleteLocalRef(str);  // تحرير فوري
}
✅ قاعدة ذهبية

في كل مرة تستدعي دالة JNI تُرجع jobject (مثل NewStringUTF، GetObjectArrayElement، NewObject)، اسأل نفسك: "أين DeleteLocalRef الخاص بها؟"

٢.٣ تحرير السلاسل النصية والمصفوفات الأولية

عند استدعاء GetStringUTFChars أو GetIntArrayElements، يُثبّت JVM البيانات (Pinning) لضمان عدم تحركها أثناء عمل GC. يجب إطلاقها صراحةً باستخدام Release*.

معامل ReleaseStringUTFChars

JNI_COMMIT (0): نسخ البيانات المُعدّلة إلى Java والإبقاء على التثبيت.

JNI_ABORT: تجاهل التعديلات وإطلاق التثبيت فوراً.

معامل ReleaseIntArrayElements

0: نسخ التعديلات وإطلاق الذاكرة المؤقتة.

JNI_ABORT: إلغاء التعديلات وتحرير الذاكرة المؤقتة. 

// مثال: معالجة مصفوفة أعداد صحيحة مع التعامل الآمن
jintArray inputArray = ...;
jboolean isCopy = JNI_FALSE;

jint* elements = env->GetIntArrayElements(inputArray, &isCopy);
if (elements == nullptr) {
    return;  // فشل في التثبيت
}

// ... إجراء العمليات الحسابية ...
jint sum = 0;
for (jsize i = 0; i < len; ++i) {
    sum += elements[i];
}

// ✅ الإطلاق الصحيح مع نسخ التعديلات (0) أو إلغائها (JNI_ABORT)
env->ReleaseIntArrayElements(inputArray, elements, 0);

// مثال: معالجة سلسلة نصية
const char* utfStr = env->GetStringUTFChars(jStringObj, nullptr);
if (utfStr != nullptr) {
    size_t length = strlen(utfStr);
    // ... المعالجة ...
    env->ReleaseStringUTFChars(jStringObj, utfStr);
}

٣.١ إعداد CMakeLists.txt للإنتاج

يجب أن يتضمن ملف CMake إعدادات دقيقة: ربط مكتبة Android Log، تفعيل C++17، تحسين الحجم (-Os) أو السرعة (-O3)، وضبط أعلام التوافق. 

cmake_minimum_required(VERSION 3.22.1)
project("native_bridge")

# تفعيل معيار C++17 إلزامي
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# تحسين الإصدار: التوازن بين الحجم والسرعة
set(CMAKE_CXX_FLAGS_RELEASE "-O3 -DNDEBUG -fvisibility=hidden -ffunction-sections -fdata-sections")
set(CMAKE_SHARED_LINKER_FLAGS_RELEASE "-Wl,--gc-sections")

# إنشاء المكتبة المشتركة
add_library(
    native-bridge
    SHARED
    native_bridge.cpp
    jni_utils.cpp
)

# ربط مكتبة Android Log للتتبع
find_library(log-lib log)

target_link_libraries(
    native-bridge
    ${log-lib}
    android
)

# تضمين المسارات المحلية
target_include_directories(native-bridge PRIVATE ${CMAKE_SOURCE_DIR}/include)

٣.٢ إعداد build.gradle.kts

يُحدّد ملف Gradle إصدار NDK، فلاتر ABI (arm64-v8a، armeabi-v7a، x86_64)، ومسار CMake. يُنصح بتقليل ABI المدعومة لتقليل حجم APK. 

android {
    compileSdk = 34

    defaultConfig {
        minSdk = 24
        targetSdk = 34

        // إعدادات NDK و CMake
        externalNativeBuild {
            cmake {
                cppFlags("-std=c++17 -Wall -Wextra -Werror")
                arguments("-DANDROID_STL=c++_shared")
            }
        }

        // فلاتر ABI: arm64 فقط للحد من الحجم
        ndk {
            abiFilters.add("arm64-v8a")
            // abiFilters.add("armeabi-v7a") // للأجهزة القديمة
            // abiFilters.add("x86_64")    // للمحاكيات
        }
    }

    externalNativeBuild {
        cmake {
            path = file("src/main/cpp/CMakeLists.txt")
            version = "3.22.1"
        }
    }

    packagingOptions {
        pickFirsts.add("lib/arm64-v8a/libc++_shared.so")
    }
}
📋 ملاحظة هامة

استخدام c++_shared بدلاً من c++_static يقلل من حجم المكتبة النهائية عند استخدام مكتبات متعددة، لكنه يتطلب تضمين libc++_shared.so في التعبئة.

تطبيق عملي متكامل للإنتاج

٤.١ جسر Kotlin: NativeBridge.kt

يُمثّل هذا الصف الواجهة العلنية (Public API) التي يتفاعل معها باقي التطبيق. يُحمّل المكتبة الأصلية عبر System.loadLibrary() ضمن كتلة companion object. 

package com.example.nativebridge

class NativeBridge {

    companion object {
        // تحميل المكتبة الأصلية عند أول استخدام للصنف
        init {
            System.loadLibrary("native-bridge")
        }
    }

    // واجهة أصلية: معالجة سلسلة نصية
    external fun processString(input: String): String

    // واجهة أصلية: حساب مجموع مصفوفة
    external fun sumArray(numbers: IntArray): Long

    // واجهة أصلية: تسجيل دالة رد نداء (Callback)
    external fun registerCallback(callback: NativeCallback)

    // واجهة أصلية: إطلاق الموارد
    external fun dispose()

    // واجهة رد النداء
    interface NativeCallback {
        fun onProgress(progress: Int, message: String)
        fun onComplete(result: String)
        fun onError(errorCode: Int, errorMessage: String)
    }
}

٤.٢ التنفيذ الأصلي: native_bridge.cpp

يتضمن هذا الملف التسجيل الديناميكي عبر JNI_OnLoad، معالجة السلاسل، حساب المصفوفات، استدعاء ردود النداء Kotlin، والتعامل الآمن مع الاستثناءات. 

// native_bridge.cpp — التنفيذ الكامل للإنتاج
#include <jni.h>
#include <android/log.h>
#include <cstring>
#include <vector>
#include <string>
#include <mutex>

#define LOG_TAG "NativeBridge"
#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, LOG_TAG, __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, LOG_TAG, __VA_ARGS__)

// ============================================================================
// ١. البيانات العمومية والحماية المتبادلة
// ============================================================================
static JavaVM* g_vm = nullptr;
static jobject g_callbackGlobalRef = nullptr;
static jmethodID g_onProgressMid = nullptr;
static jmethodID g_onCompleteMid = nullptr;
static jmethodID g_onErrorMid = nullptr;
static std::mutex g_callbackMutex;

// ============================================================================
// ٢. التسجيل الديناميكي — JNI_OnLoad
// ============================================================================
JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void* reserved) {
    g_vm = vm;
    JNIEnv* env = nullptr;

    if (vm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6) != JNI_OK) {
        LOGE("Failed to get JNIEnv in JNI_OnLoad");
        return JNI_ERR;
    }

    // تسجيل الدوال الأصلية ديناميكياً
    JNINativeMethod methods[] = {
        {"processString", "(Ljava/lang/String;)Ljava/lang/String;", 
         (void*)&nativeProcessString},
        {"sumArray", "([I)J", 
         (void*)&nativeSumArray},
        {"registerCallback", "(Lcom/example/nativebridge/NativeBridge$NativeCallback;)V", 
         (void*)&nativeRegisterCallback},
        {"dispose", "()V", 
         (void*)&nativeDispose}
    };

    jclass clazz = env->FindClass("com/example/nativebridge/NativeBridge");
    if (clazz == nullptr) {
        LOGE("Failed to find NativeBridge class");
        return JNI_ERR;
    }

    jint ret = env->RegisterNatives(clazz, methods, sizeof(methods) / sizeof(methods[0]));
    env->DeleteLocalRef(clazz);  // ✅ تحرير المرجع المحلي

    if (ret != JNI_OK) {
        LOGE("Failed to register native methods");
        return JNI_ERR;
    }

    LOGI("Native methods registered successfully");
    return JNI_VERSION_1_6;
}

// ============================================================================
// ٣. معالجة السلاسل النصية مع التعامل الآمن
// ============================================================================
extern "C" JNIEXPORT jstring JNICALL
nativeProcessString(JNIEnv* env, jobject thiz, jstring input) {
    if (input == nullptr) {
        return env->NewStringUTF("");
    }

    // الحصول على مؤشر UTF-8 مع التثبيت
    const char* utfChars = env->GetStringUTFChars(input, nullptr);
    if (utfChars == nullptr) {
        return nullptr;  // OutOfMemoryError قد أُطلقت
    }

    // معالجة: عكس السلسلة كمثال
    std::string original(utfChars);
    std::string reversed(original.rbegin(), original.rend());

    // ✅ إطلاق التثبيت إلزامي — حتى لو حدث استثناء لاحقاً
    env->ReleaseStringUTFChars(input, utfChars);

    return env->NewStringUTF(reversed.c_str());
}

// ============================================================================
// ٤. حساب مجموع المصفوفة مع التعامل الآمن
// ============================================================================
extern "C" JNIEXPORT jlong JNICALL
nativeSumArray(JNIEnv* env, jobject thiz, jintArray numbers) {
    if (numbers == nullptr) {
        return 0;
    }

    jsize len = env->GetArrayLength(numbers);
    if (len == 0) {
        return 0;
    }

    jboolean isCopy = JNI_FALSE;
    jint* elements = env->GetIntArrayElements(numbers, &isCopy);
    if (elements == nullptr) {
        return 0;
    }

    jlong sum = 0;
    for (jsize i = 0; i < len; ++i) {
        sum += elements[i];
    }

    // ✅ إطلاق التثبيت مع نسخ التعديلات (0) أو عدم النسخ (JNI_ABORT)
    env->ReleaseIntArrayElements(numbers, elements, 0);

    return sum;
}

// ============================================================================
// ٥. تسجيل دالة رد النداء (Callback) مع GlobalRef
// ============================================================================
extern "C" JNIEXPORT void JNICALL
nativeRegisterCallback(JNIEnv* env, jobject thiz, jobject callback) {
    std::lock_guard<std::mutex> lock(g_callbackMutex);

    // ✅ تحرير المرجع العمومي السابق إن وجد
    if (g_callbackGlobalRef != nullptr) {
        env->DeleteGlobalRef(g_callbackGlobalRef);
        g_callbackGlobalRef = nullptr;
    }

    if (callback == nullptr) {
        g_onProgressMid = g_onCompleteMid = g_onErrorMid = nullptr;
        return;
    }

    // ✅ إنشاء مرجع عمومي (GlobalRef) للاستمرار عبر استدعاءات متعددة
    g_callbackGlobalRef = env->NewGlobalRef(callback);
    if (g_callbackGlobalRef == nullptr) {
        LOGE("Failed to create global ref for callback");
        return;
    }

    jclass callbackClass = env->GetObjectClass(callback);
    if (callbackClass == nullptr) {
        env->DeleteGlobalRef(g_callbackGlobalRef);
        g_callbackGlobalRef = nullptr;
        return;
    }

    // تخزين معرفات الدوال (Method IDs) للاستخدام اللاحق
    g_onProgressMid = env->GetMethodID(callbackClass, "onProgress", "(ILjava/lang/String;)V");
    g_onCompleteMid = env->GetMethodID(callbackClass, "onComplete", "(Ljava/lang/String;)V");
    g_onErrorMid    = env->GetMethodID(callbackClass, "onError",    "(ILjava/lang/String;)V");

    env->DeleteLocalRef(callbackClass);  // ✅ تحرير

    LOGI("Callback registered successfully");
}

// ============================================================================
// ٦. إطلاق الموارد والتنظيف
// ============================================================================
extern "C" JNIEXPORT void JNICALL
nativeDispose(JNIEnv* env, jobject thiz) {
    std::lock_guard<std::mutex> lock(g_callbackMutex);

    if (g_callbackGlobalRef != nullptr) {
        env->DeleteGlobalRef(g_callbackGlobalRef);
        g_callbackGlobalRef = nullptr;
    }
    g_onProgressMid = g_onCompleteMid = g_onErrorMid = nullptr;

    LOGI("Native resources disposed");
}

// ============================================================================
// ٧. استدعاء رد النداء من خيط أصلي (مع Attach/Detach)
// ============================================================================
void invokeCallbackFromNativeThread(int progress, const char* message) {
    JNIEnv* env = nullptr;
    jint attachResult = g_vm->AttachCurrentThread(&env, nullptr);

    if (attachResult != JNI_OK || env == nullptr) {
        LOGE("Failed to attach thread for callback");
        return;
    }

    {
        std::lock_guard<std::mutex> lock(g_callbackMutex);
        if (g_callbackGlobalRef != nullptr && g_onProgressMid != nullptr) {
            jstring jMsg = env->NewStringUTF(message);
            env->CallVoidMethod(g_callbackGlobalRef, g_onProgressMid, progress, jMsg);
            env->DeleteLocalRef(jMsg);  // ✅

            // ✅ فحص الاستثناءات بعد كل استدعاء Java
            if (env->ExceptionCheck()) {
                env->ExceptionDescribe();
                env->ExceptionClear();
                LOGE("Exception occurred during callback");
            }
        }
    }

    // ✅ فصل الخيط إلزامي
    g_vm->DetachCurrentThread();
}
⚠️ فخ الاستثناءات (Exception Handling)

عندما يُطلق استثناء Java داخل دالة أصلية (مثلاً عبر CallVoidMethod)، يبقى JNIEnv* في حالة "استثناء معلق". أي استدعاء JNI لاحق سيفشل صامتاً. يجب فحص ExceptionCheck() بعد كل استدعاء Java ومسحه بـ ExceptionClear().

قائمة الأمان ونمط RAII

٥.١ حارس RAII للسلاسل النصية (StringGuard)

يضمن نمط RAII (Resource Acquisition Is Initialization) تحرير الموارد تلقائياً عند خروج النطاق، حتى لو حدث استثناء C++. 

// ============================================================================
// حارس RAII للسلاسل النصية — يُحرّر التثبيت تلقائياً
// ============================================================================
class JniStringGuard {
public:
    JniStringGuard(JNIEnv* env, jstring jstr) 
        : m_env(env), m_jstr(jstr), m_utfChars(nullptr) {
        if (jstr != nullptr) {
            m_utfChars = env->GetStringUTFChars(jstr, nullptr);
        }
    }

    ~JniStringGuard() {
        if (m_utfChars != nullptr && m_jstr != nullptr) {
            m_env->ReleaseStringUTFChars(m_jstr, m_utfChars);
        }
    }

    // حظر النسخ والإسناد
    JniStringGuard(const JniStringGuard&) = delete;
    JniStringGuard& operator=(const JniStringGuard&) = delete;

    const char* c_str() const { return m_utfChars; }
    bool valid() const { return m_utfChars != nullptr; }

private:
    JNIEnv* m_env;
    jstring m_jstr;
    const char* m_utfChars;
};

// ============================================================================
// حارس RAII للمصفوفات الأولية — IntArrayGuard
// ============================================================================
template<typename T>
class JniArrayGuard {
public:
    using ReleaseFunc = void (*)(JNIEnv*, jarray, T*, jint);

    JniArrayGuard(JNIEnv* env, jarray arr, T* elements, ReleaseFunc release)
        : m_env(env), m_arr(arr), m_elements(elements), m_release(release) {}

    ~JniArrayGuard() {
        if (m_elements != nullptr) {
            m_release(m_env, m_arr, m_elements, 0);  // 0 = نسخ التعديلات
        }
    }

    JniArrayGuard(const JniArrayGuard&) = delete;
    JniArrayGuard& operator=(const JniArrayGuard&) = delete;

    T* data() const { return m_elements; }
    bool valid() const { return m_elements != nullptr; }

private:
    JNIEnv* m_env;
    jarray m_arr;
    T* m_elements;
    ReleaseFunc m_release;
};

// الاستخدام:
void safeProcessArray(JNIEnv* env, jintArray arr) {
    jboolean isCopy;
    jint* elems = env->GetIntArrayElements(arr, &isCopy);

    JniArrayGuard<jint> guard(env, arr, elems, 
        [](JNIEnv* e, jarray a, jint* el, jint mode) {
            e->ReleaseIntArrayElements((jintArray)a, el, mode);
        });

    if (!guard.valid()) return;

    // ... العمليات ...
    // يُحرّر تلقائياً عند خروج النطاق
}

٥.٢ كشف تسريبات الذاكرة باستخدام AddressSanitizer

يُعدّ AddressSanitizer (ASan) أداة فعّالة لكشف تسريبات الذاكرة والوصول غير الصالح في الكود الأصلي. يُفعّل في Gradle عبر علامات البناء. 

// build.gradle.kts — تفعيل AddressSanitizer
android {
    buildTypes {
        debug {
            externalNativeBuild {
                cmake {
                    // تفعيل ASan في البناء التصحيحي فقط
                    cppFlags("-fsanitize=address -fno-omit-frame-pointer")
                    arguments("-DANDROID_STL=c++_shared")
                }
            }
        }
    }
}
🔬 تشخيص ASan

عند تشغيل التطبيق في وضع التصحيح، سيُطبع ASan أي تسريب أو تجاوز للحدود في Logcat تحت الوسم AddressSanitizer. ابحث عن ERROR: AddressSanitizer: لتشخيص المشاكل.

٥.٣ قائمة التحقق الشاملة (Safety Checklist)

  • تأكد من استدعاء DeleteLocalRef() لكل jobject يُنشأ داخل الحلقات
  • لا تشارك JNIEnv* بين الخيوط — استخدم AttachCurrentThread / DetachCurrentThread
  • استخدم NewGlobalRef() للكائنات التي تحتاج للبقاء عبر استدعاءات متعددة
  • استدعِ ReleaseStringUTFChars و Release*ArrayElements دائماً
  • افحص ExceptionCheck() بعد كل استدعاء Java من C++
  • استخدم نمط RAII (Scoped Guards) لضمان التنظيف التلقائي
  • في JNI_OnLoad، سجّل الدوال ديناميكياً لتجنب Name Mangling
  • احفظ JavaVM* عمومياً لاستخدامها في الخيوط الأصلية
  • استخدم std::mutex لحماية البيانات المشتركة بين الخيوط
  • فعّل AddressSanitizer في البناء التصحيحي للكشف المبكر عن التسريبات
  • لا تنسَ DeleteGlobalRef() عند تدمير الكائنات المُخزنة طويلة الأمد
  • تجنب تخصيص أكثر من ٥١٢ مرجعاً محلياً في إطار دالة واحد

جدول دورة حياة الموارد في JNI
المورد طريقة التخصيص طريقة التحرير مدة الحياة خطر التسريب
Local Reference (jobject) NewObject, NewStringUTF, FindClass, GetObjectArrayElement DeleteLocalRef أو تلقائياً عند العودة إطار الدالة الأصلية عالٍ في الحلقات (الحد ٥١٢)
Global Reference NewGlobalRef DeleteGlobalRef صراحةً حتى التطبيق الصريح عالٍ جداً — يمنع GC
Weak Global Reference NewWeakGlobalRef DeleteWeakGlobalRef حتى GC أو التطبيق الصريح منخفض — يسمح بـ GC
UTF String Pointer GetStringUTFChars ReleaseStringUTFChars حتى الإطلاق الصريح عالٍ — يُثبّت الذاكرة
Array Elements GetIntArrayElements, GetByteArrayElements, ... ReleaseIntArrayElements, ... حتى الإطلاق الصريح عالٍ — يُثبّت الذاكرة
Method ID / Field ID GetMethodID, GetFieldID لا يُحذف — صالح طوال عمر الصنف عمر تحميل الصنف لا يوجد
JavaVM* يُمرّر في JNI_OnLoad لا يُحذف — يبقى صالحاً عمر العملية لا يوجد
JNIEnv* AttachCurrentThread أو مُمرّر كمعامل لا يُحذف — ينتمي للخيط عمر الخيط المُلتصق لا يوجد (خيط محلي)

📌 الخلاصة: كل مورد يُخصّص عبر JNI يجب أن يكون له مسار تحرير واضح. إذا لم تكن متأكداً من موعد التحرير، استخدم نمط RAII لضمان التنظيف التلقائي عند خروج النطاق.
